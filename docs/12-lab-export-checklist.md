## 第二部分：约 Ziva 机器

**谁去**：项目负责人和一位能操作原控制器、加载运动、清理 Ziva 缓存的研究员。先预约，再让研究员准备运动。时长以现场短跑估算，**不承诺一小时足够**。

**运行环境**：Maya 2022 或更新版本的 Python 3 模式；已加载并可实际解算的 Ziva；Maya 自带 AbcExport、AbcImport 和 Alembic Python 读取库。现场版本目前未知，预检会检查。脚本不安装软件、不联网、不加载 pickle、不自动打开或保存场景。Python 2/Maya 旧版本不在支持范围；不要在现场临时改语法硬跑。

**验证边界**：普通 Maya 排练使用真实 10,240 顶点的嘴唇 OBJ、合成的 300 关节蒙皮与物理替身、第二组织、带命名空间的整体平移。它验证采集和文件链路；实际 Ziva 节点空间、许可证、缓存和求值行为仍需现场短跑确认（A-28）。

### 去之前：带什么、请研究员准备什么

- □ 带上 `tools/ziva_machine_export.py` 和本清单；脚本是独立文件，不需要复制整个仓库或安装 uv。

- □ 请研究员用原来的界面加载运动、打好关键帧，确认时间轴从 **0** 开始，前 **0–14** 帧沉降，随后运动，30 fps。脚本不替代原控制器，也不会执行 `.pkl`。
- □ 取 AA 对应的原始检查点 `.pkl`：在 Ziva 机器上远程登录取，路径列在实验室仓库的 `a3-stochastic-V1/automation/deformation_path_db.json`，键 `dataV22_AU0_neutral to dataV22_phoneme_AA`（2026-11-11 项目负责人转述）。甩头的运动是实验室仓库的脚本 `automation/passive_dynamics_test.py`（[03](03-asset.md) 第 13.8 节）；若甩头是手工关键帧，没有 `.pkl`，记录制作方式，骨头矩阵仍会导出。

### 在 Ziva 机器上：按这个顺序操作

**A. 启动面板**

把脚本放到 `D:/ASRP/ziva_machine_export.py`（也可用别的 ASCII 路径）。研究员打开场景并加载 AA 运动后，打开 Maya 的 **Script Editor → Python**，执行：

```python
path = "D:/ASRP/ziva_machine_export.py"
with open(path, encoding="utf-8") as f:
    source = f.read()
exec(compile(source, path, "exec"), {"__name__": "__main__", "__file__": path})
```

填面板：`Export root = D:/asrp_export`；`Motion name = neutral_to_AA`；`Motion kind = expression`；`Researcher/operator` 填核对人的名字；`How this motion was loaded` 填场景、运动来源和加载方式；`Original motion file` 填原始 `.pkl` 的完整路径。`Full last frame = -1` 使用时间轴终点；不要为赶时间把正式运动截短。`Pilot last frame` 默认 30，必须覆盖运动开始后的实际变化。带命名空间（如 `character:jaw01`）时，`Namespace` 填 `character`。

若名称不同，可在脚本 SETTINGS 的 `nodes` 中明确给出 `lips`、`skin`、`jaw` 三个完整节点名；不要用模糊通配符。脚本验证 skinCluster 确实在所选嘴唇历史中，并从其实际 influences 取得 300 个关节。

**B. 预检与静态资料**

1. 请研究员按原工作流禁用/清空 Ziva 缓存；确认回到起始帧会重置。只有实际做过才勾选缓存确认。
2. 点 **1 Preflight**。它核对版本、唯一节点、帧率、帧范围、运动、Ziva、缓存确认、应导组织与输出连线、Alembic 读取能力。它不推进整条运动；读取依赖数据仍可能触发 Maya 求值。任何 `INCOMPLETE` 都先看原因。
3. 点 **2 Rescue static data**。单独保存属性、权重默认值、连线、zBuilder、每个 zGeo 的静止网格。即使还没加载好运动，也应先取走这些资料。必须检查四项均为 `complete`；失败项会保留具体原因，其他项继续尝试。

**C. 每条运动：短跑、核对、正式导出**

4. 点 **3 Pilot current motion**。一次顺序求值写出嘴唇物理/最终形状和全部组织/皮肤输出，同时保存所有关节及骨头输入矩阵。面板打印进度。所有 Alembic 随后直接读文件核对，**不再次播放原场景**。
5. 短跑必须满足：`problems` 为空、`readback.ok = true`、`streams_checked` 大于 0。请研究员确认动作是平时的样子。位移检查只证明输出活动，不能替代研究员确认缓存和真实求解。
6. 短跑估算本条完整运动耗时。`Budget for this motion` 填可用分钟数；超过预算会在求解前停下。时间不足时先完成 AA 和甩头，把第三条留到下次；不要把短跑当正式结果。
7. 重置缓存，再点 **4 Export full current motion**。正式导出要求研究员记录和 AA 原始文件。每次都新建独立文件夹，不覆盖短跑或上次失败结果。确认读回通过后，记下 `OUTPUT` 路径。
8. 研究员用原界面切换/重新打开准备好的甩头场景，清空缓存。保持同一个 `Export root`，改 `Motion name = head_shake`、`Motion kind = head_translation`，清空不适用的 AA 原始文件路径并更新加载说明，重新做预检、短跑、正式导出。甩头允许下颌不旋转、landmark 不动，但必须有骨头平移。第三条同理。

**D. 正式结果之后：同帧诊断与总收货**

9. 研究员手工重新打开干净的场景、禁用缓存，再点 **5 Same-frame diagnostic**。脚本从 0 顺序走到 14 帧，两次读取基线，只扰动下颌 `rotateZ` 两度，再读取蒙皮前形状，最后恢复通道值和动画连接。结果只记录变化、耗时与恢复状态，不自动宣称“物理冻结”。**诊断后必须由研究员重新打开场景**，不要继续用已诊断的求解状态采集参考。
10. 点 **6 Check entire collection**。只有至少一条完整表情、一条完整甩头、全部静态资料、所有动态文件读回、原始表情运动文件和同帧诊断齐全，才显示 `COLLECTION COMPLETE`。失败/短跑目录仍保留，但不会冒充成功运动。`collection_report.json` 列出可收货的目录和未完成项。
11. 整个 `D:/asrp_export` 拷到实验室认可的存储设备；再在拷贝上执行下面的检查。另带上研究员对第三部分问题的回答，以及需要补充的研究场景文件（经实验室许可，原始 `.mb` 留在 `assets/`，不进 git）。

```powershell
& "C:/Program Files/Autodesk/Maya2027/bin/mayapy.exe" D:/ASRP/ziva_machine_export.py --collection E:/copied_asrp_export
```

把 `Maya2027` 换成现场实际安装版本，或使用本机相应 mayapy。命令不初始化 Maya，不打开场景，只读文件；非零退出码或 `INCOMPLETE` 都不能认定收齐。单个目录可用 `--check <完整运行目录>`。回来后原始导出归档到 `data/lab_export/` 下独立目录，保持 seal 指纹；先核验再做格式转换。

**E. 2026-11-11 加进来的现场任务（脚本不覆盖，手工做；各几分钟）**

12. **中性到 AA 的 Ziva 参考结果**：就是第 4 项，这趟必须拿到（D3）。
13. **Q20**：Ziva 在同一帧里转 `jaw01` 会不会重新求解——就是上面第 9 步的同帧诊断，我们自己做，不问研究员（11 的 Q20、A-37）。
14. **Q21**：管线顺序（landmark 先进物理，还是物理在前）——我们自己在机器上查，不问研究员（11 的 Q21）。
15. **只留嘴唇的 Ziva 场景**：把其他组织关掉，试它还能不能解算。不能解算，就拿完整场景的结果对比，并写明（11 的 D3）。

| 某个组织没有输出、坐标空间不明、拓扑不符 | 保留报告；先运行静态资料抢救。不能删除该组织来制造“全导出”。需要现场适配或带报告回开发机修复，再补采。 |
| zBuilder、权重或网格失败 | 独立项仍会尝试导出；按下文手动做法保留能取得的数据，修复缺项后重新短跑。部分结果不算齐全。 |
| 中途报错、取消、磁盘不足 | 保留失败目录和 Script Editor 报错，清理/修复原因后由研究员重置场景，从第 0 帧重新采这一条。已有成功运动无需重跑。 |
| Alembic 读取库缺失或读回失败 | 不算验收通过；保留 Alembic、顶点备份和 seal。可在支持的 Maya 安装用 `--check` 核验；若数据不一致则重采。 |
| 同帧诊断失败或恢复不完整 | 保存诊断报告，研究员重新打开场景；正式导出文件独立保留，不受诊断覆盖。 |

**没有“保证现场绝不报错”的承诺。** 本流程保证的是可观察的成功条件、独立文件核验和不把缺项误报为收齐；实际 Ziva 适配仍以现场短跑结果为准。

### 2. Ziva 的完整设置 □

- **需要**：所有 Ziva 设置的**全部属性值**，包括没改过的默认值；以及每个 Ziva 节点的**逐顶点权重表**和它和其他节点的连线。
- **为什么**：`.mb` 只存了改过的值。文件里所有材料都没有存数值，说明很可能都是默认值，但默认值是多少，文件里没有。粘连的权重表决定嘴唇哪些区域被拉着（T-03），而 `ziva_attributes.json` 只收单值属性，读不出权重表：2026-11-03 在普通 Maya 上实测，同样的读法把一个变形器的权重表记成了 `unreadable`。所以权重表单独导出，不再只靠 zBuilder 一个出口。
- **输出**：
  - `ziva_attributes.json`：每个节点的每个单值属性；
  - `ziva_maps.json`：每个节点的权重表（`weightList`）和连线。权重表只列出存了值的顶点，没列出的顶点取这个属性的默认值，默认值也写在文件里（`default` 字段）。**收到后先看粘连的 `default` 是不是 1.0**：我们现在按 1.0 读（11 的 A-33，[03](03-asset.md) 第 6 节），不是就要重做 T-03。连线用来分辨每个粘连的出发方和目标方；
  - `ziva_setup.zBuilder`：Ziva 自己的格式。
- **另外请截图**：`zSolver1` 和 `zMaterial1` 的属性面板（Attribute Editor），方便核对。
- **手动做法**：zBuilder 部分用 `zBuilder.builders.ziva` 的 `Ziva()`、`retrieve_from_scene()`、`write()`，以你们 Ziva 版本的文档为准。

### 4. Ziva 参考结果（许可到期前必须完成） □

- **需要**：一条运动下，嘴唇网格**每一帧**的形状，两份：
  - **4a 最终形状**：`ziva_<运动名>_final.abc`；
  - **4b 只有物理**：landmark 变形之前的形状，`ziva_<运动名>_physics.abc`。脚本从 `skinCluster7` 的输入取这个形状，和 4a 来自同一次解算。
- **为什么**：我们会把它和 FEBio 的结果在 Blender 里并排播放，请研究员评审新结果能不能用于继续研究。我们不要求和 Ziva 逐点一致，所以它不是"标准答案"，而是"以前的样子"。分成两份，可以把物理部分和 landmark 部分分开看；landmark 那一层用的是同一个公式，还能精确核对。
- **手动做法**：选中嘴唇网格，`Cache > Alembic Cache > Export Selection to Alembic`，帧范围从第 0 帧到运动结束（包括第 0 到 14 帧的重力沉降），勾选 **World Space**，导出 4a。再把 `skinCluster7` 的 `envelope` 设为 0，清空缓存，用完全相同的帧范围导出 4b，这会多解算一次。做完把 `envelope` 改回 1。

### 5. 这条运动本身 □

- **需要**：
  - 第 4 项用到的那条运动的**原始文件**（检查点 `.pkl`，格式已由源码确定，[03](03-asset.md) 第 7 节）。**它不在源码仓库里**；2026-11-11 项目负责人转述：它在 Ziva 机器上，去的时候远程登录取，路径列在实验室仓库的 `a3-stochastic-V1/automation/deformation_path_db.json`（键 `dataV22_AU0_neutral to dataV22_phoneme_AA`）；
  - `motion_<运动名>.json`：播放时 `jaw01` 和 300 个 landmark 每一帧的位置矩阵，脚本在 Ziva 会话里随第 4 项自动导出。
- **为什么**：我们要用同一条运动驱动 FEBio（T-10）；两份对得上，也就核对了我们对格式的理解。

### 7. Ziva 里每个物体的静止网格 □

- **需要**：Ziva 给每个软组织、骨头、皮肤各存了一份网格（zGeo）。把每一份都导出来，带面。
- **为什么**：嘴角经口角组织（zTissue4/5 → zTissue2/3，另有 zTissue6/7 拉着）连到颅骨和下颌，周围 6 块肌肉和皮肤还粘在嘴唇上（[03](03-asset.md) 第 6 节）。第一阶段用近似代替这些组织（ADR-32），第二阶段的方案 B 要把它们加进计算，**口角链条上的这几块最要紧**。它们的网格在 v36 里已经删掉，只剩 Ziva 存的副本。`.mb` 里这份副本只能读出顶点数和范围，面读不出来，没有 Ziva 插件也打不开，**许可到期就再也拿不到**。
- **输出**：
  - `ziva_meshes/<zGeo 名>.obj`：场景坐标，保持 Maya 的顶点顺序，和 `data/lab_export/` 里的 OBJ 同一种约定；
  - `ziva_meshes.json`：每份网格属于哪个物体，原来的 Maya 网格是否还在，顶点数、面数、位置矩阵，以及坐标是怎么算出来的。
- **现场自检**：Maya 网格还在场景里的物体（嘴唇、骨头、皮肤等），脚本把导出的网格和它的静止形状逐点比较，结果写进 `ziva_meshes.json`。差别超过 0.001 个场景单位，会在 `notes` 里点名。嘴唇这一份和已删肌肉的副本是同一种存法，所以嘴唇对上了，说明副本的读法是对的。
- **已删网格的位置**：网格删掉以后，Ziva 副本的位置矩阵可能没有保留下来（未验证）。`ziva_meshes.json` 里 `matrix_connected` 为 `false` 的就是这种情况，坐标可能差一个缩放和旋转。用的时候按"带粘连权重的顶点应该贴在目标物体表面"来核对和修正。
- **不需要解算**。没有现成的手动做法：如果 `notes` 提示没导出来，把原文记下来，第 2、4、5 项照常进行。

### 8. 所有被 Ziva 解算的网格的逐帧结果 □（第二阶段要的；脚本已支持，排练过，Ziva 部分未运行，A-28）

- **需要**：第 4 项那一次解算里，**每一块被 Ziva 解算的网格**（每块软组织和皮肤）每一帧的形状，每个网格一个 Alembic：`ziva_<运动名>_<网格名>.abc`。
- **为什么**：现在的第 4 项只有嘴唇一个网格。论文的模型有 36 个物体（4.1.3），第二阶段要做软组织互相牵拉和皮肤；没有它们的逐帧结果，第二阶段就没有"以前的样子"可比（11 的 D11）。Ziva 许可到期以后就再也做不出来了。
- **输出**：每个被解算的网格一个文件，顶点顺序和第 7 项导出的静止网格一致；`session_report.json` 里列出每个网格的帧数和顶点数。
- **手动做法**：和第 4 项一样，选中网格，`Cache > Alembic Cache > Export Selection to Alembic`，World Space，同样的帧范围。网格多的时候，一次选中全部，导成一个文件也行，但要记下每个网格的名字和顶点范围。

### 9. 2 到 3 条运动，其中一条是甩头 □（第二阶段要的；脚本已支持，排练过，Ziva 部分未运行，A-28）

- **需要**：除了第一条运动（建议"中性 → AA"）以外，再拿 1 到 2 条，**其中一条是甩头**（论文 4.4.6，整个头平移）。每条运动都要有第 4、5、8 项的全部文件。
- **为什么**：只有一条下颌张合，验证不了"骨头每帧完整刚体变换"（ADR-21）和惯性。甩头是整个头平移，最能暴露这两样。实验室的甩头是给下颌和颅骨的变换打平移关键帧（[03](03-asset.md) 第 13.8 节），每条运动还要第 5 项的运动文件。
- **输出**：每条运动一套文件，文件名里带运动名。
- **注意**：每条运动都要从第 0 帧起跳回、重新解算。时间不够时，先做甩头，再做第三条。

### 3 个问题

我们在用 FEBio（开源有限元软件）和 Blender 替换 Ziva 和 Maya 里的物理计算。下面 3 个问题会影响我们怎么搭，每条回一两句话就够，不确定就写"不知道"，这也有用。编号是我们内部的，所以不连续。

**1. 粘连是怎么生成的？**
- 背景：论文 3.7 节说粘连由代码自动生成，但你们给我们的源码仓库里找不到这一步。
- 需要您回答：生成脚本在哪里；按距离生成的话阈值或半径是多少；哪些粘连是手工画的（皮肤那批看上去像）；嘴角处的 zTissue2/3（左右成对、同时挂在颅骨和下颌上）和 zTissue6/7 分别是哪块肌肉。

**3. 实验改了哪些场景参数？**
- 背景：论文 4.4.7 的烧伤实验改了材料参数，但源码里没有对应的脚本。
- 需要您回答：改了哪几个 zMaterial / zCloth 的哪个属性、乘了多少、有没有另存场景文件；各实验用的场景文件（比如 `g10-10 rest pose 1200 landmarks v9.mb`、`*_as_rest_pose.mb`）能不能给我们，和代理场景有什么差别。

- 背景：我们已经做出一个原型：真实嘴唇在 Blender 里被下颌带动、由 FEBio 算出、能回放（用的是临时的材料参数和一条代用的张嘴运动），暂不含和 Ziva 结果的对比和验收流程。
- 需要您回答：这样符合你们的期待吗？以后全脸要算多快，要不要交互？
