# 09 路线图与任务

这份文档把第一阶段拆成几个里程碑，每个里程碑再拆成任务卡。**任务卡就是交给开发者（人或 AI 开发会话）的完整说明**：拿到一张卡，加上 [README](README.md) 里开发者要读的文档，就能开工。所有任务卡都按 [templates/task-card.md](templates/task-card.md) 的格式写。

## 1. 里程碑

```
M0 基础 ✅ ──► M1 原料就绪 ──► M2 物理段 ──► M3 landmark 段 ──► M4 对比与评审 ──► M5 界面与验收
                 │ 需要实验室网格     │ 先跑通再细化     │ 需要实验室        │ 需要实验室
```

**原则：先让真实资产从头到尾跑通一次，再逐项细化。** M2 先做一个粗糙但完整的第一版（T-06 第一版），缺的数据用标明来源的临时值，这样真正的问题（四面体质量、尺寸、稳定性）能尽早暴露。

| 里程碑 | 完成后能做到 | 依赖实验室 |
|---|---|---|
| M0 基础 ✅ | 仓库、环境、自动检查；FEBio 本机可用；结果能回放到 Blender | 否 |
| M1 原料就绪 | 实验室资产能完整导入成我们的场景描述 | **是**：导出的网格（T-01，清单第 1 项） |
| M2 物理段 | 下颌带动嘴唇的物理过程能用 FEBio 算出来、通过合理性检查并回放 | 第一版只依赖导出的网格（清单第 1 项，经 T-02、T-04）；第二版需要单位、Ziva 设置、P-01 的认可 |
| M3 landmark 段 | 叠加 landmark 变形，得到最终的嘴唇形状 | **是**：运动轨迹（D2） |
| M4 对比与评审 | 和 Ziva 并排比较，研究员评审通过（[07](07-validation.md) 第 4 节） | **是**：参考结果（D3）、研究员评审 |
| M5 界面与验收 | 研究员能在 Blender 里独立完成全流程，实验室签字验收 | **是**：试用和验收 |

- **验收**：清单每一项都打了勾，或者写明了为什么不需要；导出网格的顶点数和 [03](03-asset.md) 第 3 节一致。

### T-02 资产导入 🔴（等 T-01、T-05）
- **目标**：`asrp import-asset <导出文件夹>`，把实验室导出的文件变成我们的场景描述（`scene.json`）和一份检查报告。
- **为什么**：需求 R-01、R-02。
- **按照**：[04](04-architecture.md) 第 5.1 节；[03](03-asset.md) 第 10 节（单位、坐标轴）；ADR-04、ADR-07。
- **输入**：实验室导出的网格、属性清单、蒙皮权重（[12](12-lab-export-checklist.md) 第 1–3 项）；T-05 定好的格式。
- **只有第 1 项时也要能导入**：属性清单或权重还没到时，对应参数的来源标成"我们定的"，检查报告里列出缺了什么；收到以后重新导入补上。这样 T-06 第一版不用等齐三项。
- **输出**：`src/asrp_core/asset/` 下的导入模块；`scene.json`、`meshes/`（毫米、Z 轴朝上）、检查报告；测试。
- **验收**：
  - 五个网格的顶点数和 [03](03-asset.md) 第 3 节一致（10,240 / 7,426 / 28,414 / 24,608 / 24,608）；
  - 严格按 [03](03-asset.md) 第 10 节的顺序处理：先套用每个网格自己的变换（来自 `mesh_report.json` 的 `world_matrix`），再换单位，再转坐标轴；
  - 导出网格的顶点坐标，和 `tools/mb_inventory.py` 从 `.mb` 读出的静止坐标逐点一致。比较之前，两边都换算到场景坐标，也就是 `.mb` 的物体坐标要先套上同一个变换。误差小于 0.001 个场景单位。这条检查同时验证变换和顶点顺序；
  - 下颌在场景坐标下 z 方向的尺寸为 155.92 个单位（论文附录 V 用的就是这个数），能发现漏套变换、套错变换的问题；
  - 检查报告列出每个网格的变换、单位换算系数、坐标轴转换方式，以及每个参数的来源。
- **不做**：四面体化（T-04）、生成 FEBio 输入（T-06）。
- **依赖**：T-01、T-05；T-03 作为交叉核对。
- **改动范围**：`src/asrp_core/asset/`、`cli.py`（加一条命令）、`tests/`。

### T-03 从 .mb 读取权重和静止数据，用于交叉核对 🟢
- **目标**：从 `.mb` 文件里读出原型需要的权重和静止位置，作为**核对实验室导出的工具**。
- **为什么**：这些数据在 `.mb` 里读得出来（[03](03-asset.md) 第 8 节）。自己读一份，就能检查实验室的导出有没有出错。但是 `.mb` 的格式没有公开文档（还有 41 个数据块没认出来），所以**它只做核对工具，不做产品的数据来源**（ADR-07）。
- **按照**：`tools/mb_inventory.py` 文件开头记录的格式说明。
- **要读出**：
  1. 和嘴唇相连的每个粘连的逐顶点权重（[03](03-asset.md) 第 6 节的表）。注意权重记在"出发方"的顶点上；
  2. **嘴唇表面被周围组织拉着的区域**：肌肉和皮肤是"出发方"的那些粘连，算出它们带权重的顶点离嘴唇表面最近的位置，落在哪些嘴唇顶点附近。皮肤网格还在文件里；6 块肌肉的网格被删了，要先确认能不能从 Ziva 保留的副本（zGeo）里读出坐标。P-01 方案 A 要靠它决定嘴唇的哪些区域挂到骨头上；
  3. 300 个 landmark 对嘴唇顶点的蒙皮权重（skinCluster7）；
  4. 300 个 landmark 和 `jaw01` 关节的静止位置和朝向。
- **输出**：`tools/` 下的一个核对脚本（比如 `tools/mb_weights.py`），把以上数据写成 JSON；测试（用一个小的合成数据样本）；嘴唇上被拉着的顶点总数（不重复计数）和占比，写进 03 第 6 节。
- **验收**（不需要等实验室）：
  - 每个粘连的权重都在 0 到 1 之间，权重表长度等于出发方网格的顶点数；
  - 嘴唇上带粘连权重的顶点（嘴唇作为出发方）不重复计数为 733 个，和 `tools/asset_report.py` 一致。注意：这一条和 `asset_report.py` 用的是同一个解析器，**只能发现脚本写错，发现不了解析器本身的错**；
  - 每个嘴唇顶点的 landmark 权重之和等于 1（误差 1e-6 以内），或者说明为什么不等于 1；
  - 第一步先确认蒙皮权重存在哪个属性里、能不能完整读出，把结论写进 03 第 8 节。
- **之后**：真正独立的检查，是收到实验室导出以后，在 T-02 里和导出的权重逐项比对。
- **不做**：解析网格的面；把它变成产品模块。
- **依赖**：无。
- **改动范围**：`tools/`、`tests/`。
- **规模**：中。

### T-04 嘴唇四面体化试验（S2） 🟡（可以先用测试网格）
- **目标**：确认能把嘴唇表面网格变成质量合格的四面体网格，并选定工具。
- **为什么**：Ziva 自己做四面体化，我们得自己做。实验室的网格在静止状态下可能有互相穿插，有些工具遇到这种网格会直接失败（A-10）。
- **按照**：[05](05-ziva-to-febio.md) 第 1 节 zTet 一行。
- **做法**：比较至少两种四面体化工具在 Windows 上的安装难度、对"不完美网格"的容忍度、网格质量和速度。尺寸按 `tetSz` 26.37 换算成毫米，另外试粗一倍、细一倍两档。
- **输入**：先用公开的测试网格；T-01 到了以后换成嘴唇网格。
- **输出**：试验报告（写进 05 和 11）、一个最小的四面体化模块 `src/asrp_core/tetmesh.py`。
- **验收**：嘴唇网格能稳定生成四面体，没有被压扁、体积接近 0 的坏四面体；报告写明计算点数、四面体数、耗时；三档尺寸都有数据。
- **注意**：`tetSz` 26.37 是场景坐标下的尺寸，而嘴唇最薄的方向只有约 45.8，厚度方向大约只有两层四面体，可能太粗。试验时要看这对结果的影响。
- **不做**：生成 FEBio 输入。
- **依赖**：最终验收要等 T-01 的嘴唇网格。
- **改动范围**：`src/asrp_core/tetmesh.py`、`spikes/`、`pyproject.toml`（新增依赖）。
- **规模**：中。

### T-07 粘连做法试验（S3） 🟢
- **目标**：在 [05](05-ziva-to-febio.md) 第 3 节的"硬绑定"和"弹簧"两种做法之间做出选择。
- **为什么**：粘连决定嘴唇怎么被拉住，做错了结果会差很多。
- **按照**：05 第 3 节；FEBio 手册（安装目录 `doc/FEBio_User_Manual.pdf`）：
  - 硬绑定：第 3.11.16 节的 `rigid` 边界条件，把一组计算点并入刚体；或者像 S1 那样让组织和刚体共用计算点；
  - 弹簧：第 3.6.7 节的 `DiscreteSet` 加第 3.16 节的 `linear spring`（刚度参数是 `E`）。弹簧的另一端需要一个计算点，再用 `rigid` 条件把这个点并入骨头。**一个弹簧材料只能有一个刚度**，所以"刚度 × 权重"要把权重分成几档，每档一种材料。
- **做法**：
  1. 一个几乎不变形的方块挂在 4 根弹簧上，加重力。理论答案是每根弹簧伸长 = 方块重量 ÷（4 × 刚度），用它检查弹簧和重力的写法对不对；
  2. 一个软方块分别用两种做法粘在刚体上，加重力和刚体转动，比较变形、稳定性、计算时间；弹簧刚度逐步加大时，结果应该趋近硬绑定；
  3. 试验权重小于 1 的情况；
  4. 把刚体整个固定（代替 S1 里"把一组计算点固定"的做法），确认颅骨可以这样处理。
- **输出**：试验代码（放 `spikes/`），结论写进 05 和 10。
- **验收**：第 1 步和理论值误差在 1% 以内；给出明确的选择和理由；如果选弹簧，给出刚度怎么取的规则（假设 A-23 要一起验证，或者标明待定）。
- **不做**：用实验室资产做试验。
- **依赖**：无。
- **改动范围**：`spikes/`、`docs/05`、`docs/10`。
- **规模**：小到中。
