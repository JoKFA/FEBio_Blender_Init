# 09 路线图与任务

给谁看：项目的开发者和项目负责人。读完能知道：项目现在到哪了、接下来按什么顺序做、每项任务的目标、输入、输出和验收。为什么这样定在 [10](10-decisions.md)，还开着的问题在 [11](11-risks-and-questions.md)。**任务的状态只写在这里**，别的文档链到这里。

**原则：先让真实资产从头到尾跑通一次，再逐项细化。** M2 先做一个粗糙但完整的第一版（T-06a），缺的数据用标明来源的临时值，这样真正的问题（四面体质量、尺寸、稳定性）能尽早暴露。

**原型机**（也叫原型机一；11 的 P-05；**定义只写在这里**，其他文档链到这一节）：**真实嘴唇在 Blender 里被下颌带动、由 FEBio 算出、能回放**，**不含** Ziva 对比（M4）和验收流程（M5）。2026-11-11 完成（T-06a，PR #7、#8）。怎么重新跑、结果是什么样：[15](15-prototype.md)。

**原型机二**（ADR-39、ADR-42；**定义只写在这里**）：在原型机上加 landmark 层，做实验室的两个动作，外加一个附带项。范围是骨头加嘴唇一块组织。

**怎么算做成了**（三层，各自的标准不同）：

| 层 | 标准 | 有没有硬的合格线 |

| 训练接口（给实验室的函数，T-31） | 给出存档里 landmark 的绝对位置，复现实验室的训练程序存下的嘴唇 | 有：最大差小于 0.0001 mm，145 份都过（已经是测试） |

## 2. 现在到哪，接下来做什么（2026-11-24）

**现在到哪**：

- **原型机一、二已跑通单嘴唇三段运动**：在同一套资产上，Blender 面板三步（打开资产、选运动、Run，T-35）可跑原型机一（下颌张开 12°）和原型机二（实验室中性到 AA、甩头）；嘴唇已有粗格子（126 个四面体，默认）和细网格（26,721 个四面体，可选）两套网格（ADR-44；中性到 AA、物理层、第 36 帧对 Ziva 整张脸：粗格子平均 1.88、最大 5.12 mm，细网格平均 2.21、最大 7.64 mm，[13](13-explanations.md) E-20）；`asrp compare`（T-11 ✅）和 Ziva 默认材料 12 kPa、0.4（T-37）均已落地；甩头到每帧 16 步仍未收敛（T-33），重力下垂小于 Ziva 且物理尺度未对齐（[11](11-risks-and-questions.md) D18，归 T-41）。详见 [15](15-prototype.md)。
- **四轮地基设计拷问已收敛（2026-11-24）**：定下"场景、建造、段、结果"四处边界、模块划分（`importers`、`scene`、`build`、`motion`、`backends/febio`、`sessions`、`results`、`checks`、独立打包的 `asrp_query` 及 CLI/插件；插件 `RunSession` 改称 `RunJob`；只实现 FEBio 后端）、场景版本按摘要落盘与 `.blend` 引用、独立建造配置与预分配骨头通道、状态与缓存分离、检查与提交分工、粘连三层表达、`physics`/`final` 两层公开结果以及新段默认分段线性。目标结构见 [04](04-architecture.md) 第 13 节，九条决策见 `ADR-46` 到 `ADR-54`，设计解释见 [13](13-explanations.md) E-24，核实与试验记录见 [archive/13-audit-history.md](archive/13-audit-history.md) E-23；原 `T-26` 拆成 `T-43` 到 `T-52` 十张卡实施。
- **2026-11-24 本机试验结论（数字与出处均汇总在 [archive/13-audit-history.md](archive/13-audit-history.md) E-23）**：
  - **FEBio 会话实测**：原地改写过的存档重试，12 次里 11 次"正常结束"却多走 24 帧停在第 70 帧（预期第 46 帧）；在独立副本上重试、同档分支、删档重放均与基线一致。
  - **长间距粘连与 `tied-elastic` 探针**：可变形目标上"目标四面体外推参考点 + 纯罚线性约束"事先登记的 9 项全过；`tied-elastic` 保持世界方向偏移，15 mm、15° 时与"跟着转"差 `3.9158 mm`，且 `search_radius` 留 0 找不到接触对仍正常结束，反向双边平衡 `−0.6667 mm`，面积加权手算裁判 `2.8 N` 对组平均 `6.0 N`；不写 `<laugon>` 默认增广拉格朗日、0.1 N 位移变成 `7.5×10⁻⁸ mm`（显式写 0 是 `0.2 mm`）且无警告；2,025 个受粘连节点、6,075 条约束、全模型 5,637 节点算例中，线性约束 `9.655 秒`、`tied-elastic` `12.662 秒`，均 30 次迭代（两者算出的运动不同，不称同精度更快，`test10_cost`）。
  - **骨头通道、运动统计与查询计时**：原型中性到 AA（粗格子，224 节点，46 帧）将颅骨从固定改为给定零位移，几何坐标最大差 `1.5×10⁻¹⁰ mm`；84 份实验室运动中 46 份动下颌（最大转角最小 0.37°、中位 2.3°、九成以内 5.2°、最大 6.65°；最大转角下 3/8/15/30 mm 对应间距偏移上界 0.35/0.93/1.74/3.48 mm）、12 份只动眼或额头；多条粘连的 12 对网格中参与顶点有重叠的是 8 对；本机 Python 3.13 训练查询内存耗时 `3.1–3.6 ms`、载入 `219–272 ms`、起一个空 CLI 子进程约 `275 ms`。

### T-43 封存旧嘴唇基线 🟢（地基第 1 步，与 T-42 互不依赖）
- **状态**：🟢 可以开始
- **目标**：通过正式命令 `asrp run <scene> <motion> --threads 1` 把现有两种旧嘴唇场景和"只改材料、未改旧弹簧刚度"的样本封存成独立的本地基线与比较器，使后续迁移（T-44、T-46）能自动抓住数值漂移、旧弹簧被重算或坐标行错位。

- **按照**：`[04](04-architecture.md) 第 13.1 节（四处核心边界）、第 13.3 节（数据的六种形态与契约规则）`、`ADR-48`（旧嘴唇沿用存量 N/mm，新旧均保留迁移门限 `1e-9 mm`）、`[08](08-engineering-standards.md)` 第 6、7、10 节（测试必须能失败、敏感数据不进仓库）。
- **输入**：
  - 现行可运行的 `asrp run` 命令行入口；

- **输出**：

  2. 编写独立比较器：在同环境、同驱动、同帧、同点口径下，对核心几何毫米坐标执行 `1e-9 mm` 迁移门限检查并报最坏帧、点、分量；对 PC2 点缓存按 float32 读回精度单独检查，不把 PC2 混入 `1e-9 mm` 门限；
  3. 明确把实验室敏感样本留在仓库外原处；无仓库外数据时，真实样本部分自动跳过并打印 `NOT VERIFIED`，合成输入和坏例检查照常执行。

- **做法**：
  1. **场景版本落盘（ADR-46）**：项目数据目录保存持久 `store_id`；`scenes/<revision>/scene.json` 存规范化清单，版本号为规范化清单的 SHA-256；`blobs/<sha256>` 按内容摘要共享有序网格、权重、绑定等大文件，清单写明用途、格式、摘要和长度。规范化 JSON 固定 UTF-8、键序和有限数规则，保留有意义的数组顺序，拒绝重复键和非有限数，并用固定样本锁住规范化字节；时间、绝对路径、提交者、编辑说明及父版本记在版本外的历史记录。编辑发布时先写并校验缺少的大文件，再同卷暂存并发布清单，最后更新发起编辑的引用；单字节损坏必须报摘要错误，不得静默替换；已发布版本首版不自动删除（关闭 Blender、删分支、另存为均不触发回收，只可另行清理暂存失败文件）；

- **验收**（只看到 `passed` 或退出码 0 不算交付，必须贴出真实命令与完整打印输出作为证据）：

### T-46 从建造冷启动旧嘴唇 🔴（依赖 T-43、T-44、T-45）
- **状态**：🔴 在等 T-43、T-44、T-45
- **目标**：用户继续使用同一命令 `asrp run`，但内部已切开 `generate.build()`，先生成并落盘不可变的**建造记录**（含有效建造配置、计算网格、显示绑定、粘连实现、预分配的骨头驱动通道和 FEBio 编号表），再由 `backends/febio` 写出首份 `.feb` 并经 `checks` 核验输出，使两种旧嘴唇场景的回归误差都在 `1e-9 mm` 以内。

- **按照**：`[04](04-architecture.md) 第 13.1 节（四处核心边界）、第 13.2 节（模块划分与职责）、第 13.5 节（建造配置与设置归属）、第 13.7 节（检查与提交的分工）、第 13.8 节（计算网格的生成与加载）、第 13.13 节（骨头的驱动通道预分配）`、`ADR-47`、`ADR-48`、`ADR-50`、`ADR-44`、`[08](08-engineering-standards.md)` 第 5、6、7 节。
- **输入**：
  - T-43 封存的三份旧嘴唇基线与独立比较器；

  - T-45 的导入与场景声明结构；
  - 离线生成的细网格（如 `data/tetmesh/lips.json`）及规则格子参数（ADR-44）。
- **输出**：
  - `build` 模块（`prepare(revision, profile)` 返回不可变并落盘的建造记录）与随代码发布的版本化 `legacy-v1` 建造配置 JSON；
  - `backends/febio` 首段写出与编号表（`prepare_model()`、`write_initial()` 等，首次与重启共享一份编号表）；
  - `checks` 模块（从 `simulate.py` 迁入 `_physics_checks` 等校验逻辑，按执行门槛 / 物理合理性 / 显示面质量 / Ziva 对照分工）；
  - 旧 `asrp run` 适配（`asrp run --feb` 继续直调底层执行器，不虚构建造）；
  - 验收测试 `C04`。
- **做法**：
  1. **切开 `generate.build()` 与不可变建造记录（ADR-47）**：把静态模型构建移入 `build`，落盘完全展开后的有效配置、来源和摘要、实际计算网格及内容摘要、显示绑定、粘连对应和实现记录、有效材料/刚度/物理尺度、驱动通道和 FEBio 编号表，以及足以重放的数组；
  2. **`legacy-v1` 建造配置（ADR-47、ADR-48）**：两种旧嘴唇资产共用一份 `legacy-v1` 建造配置——对 `ours` 执行原文件的上唇硬、其余三组弹簧，对 `ziva-soft` 执行原文件的四组全软；两者均严格沿用已落盘的 N/mm 刚度、硬优先、节点冲突处理和分档；用户只改材料时绝不用新材料重算旧弹簧；
  3. **计算网格规矩（ADR-47）**：细四面体网格只按引用加载并核对摘要，禁止在缺失时调用 fTetWild 或静默回退粗格子；规则格子允许在建造时生成，但节点、单元、顺序、参数（含格子原点，ADR-44）和生成器版本一并封存进建造记录；缺细网格、摘要不符或格子无有效单元报到具体对象 ID；
  4. **骨头通道预分配与 Q8 第一类补测（ADR-48）**：声明为可驱动且纳入本次建造的骨头，从第一段起分配完整通道，首段无运动时给定零位移，不设"本段缺驱动则固定"的兼容开关（真正声明为永久固定的骨头仍按场景语义处理）。切换旧入口前补跑 Q8 第一类用例：覆盖两种旧嘴唇（含承受上唇硬连接反力的静止骨和只承受软弹簧的静止骨），至少补一例已有细网格，加重力沉降与一段非零载荷；固定版、给定零版、同输入自重复三者同环境对比，分别记录 1 线程与默认线程，全帧全原序点几何毫米差须 `≤ 1e-9 mm`（PC2 另按 float32 验）；
  5. **检查分工（ADR-50）**：后端保留原始顺序与全部记录，`checks` 先核对全部实际物理时间、完整行、节点身份、有限值与倒置四面体等硬门槛（不得在挑选预期帧之后才查），再输出物理合理性与逐层表面质量报告（保留 `_surface_health` 只报告语义与独立 `asrp compare`）。
- **验收**（只看到 `passed` 或退出码 0 不算交付，必须贴出真实命令与完整打印输出作为证据）：

  - **必须失败的坏例**：
    1. 移走或篡改细网格文件，必须报到对象 ID 并失败（不得启动 fTetWild 或回退粗格子）；
    2. 改动旧场景材料后触发旧弹簧刚度被重算，必须失败；
    3. 建造记录漏分配静止但可驱动骨头的通道，必须失败；
  - 交付最终状态跑 `uv run python tools/verify.py` 并记录实际输出。

### T-47 同一块嘴唇接着算 🔴（依赖 T-46）
- **状态**：🔴 在等 T-46
- **目标**：用户可通过正式会话入口新建会话、提交初始化段（纯重力沉降或非中性起步），再显式指定父状态追加第二段运动并读出接头前后两帧，且在同一起点、同一实际驱动样本和相同步序下，分段续算与从头整算在登记容差内一致。
- **为什么**：实验室的钢琴界面每按一次键从上一段末状态续算，非中性初始化也是在同一场景前 14 帧把控制量移到起点姿态；而旧运动转换器会自动补 0–14 帧沉降和末尾保持、且旧插值在追加新关键帧后会改写历史区间中点（复算输入 `[0, 1]` 与 `[0, 1, 0]` 时首个区间中点由 `0.5` 变为 `0.625`）。没有独立的 `motion` 和 `sessions` 层，就无法在不改写过去、不重复沉降、不误把下颌拉回零位的前提下实现连续多段仿真。
- **按照**：`[04](04-architecture.md) 第 13.2 节（模块划分与职责）、第 13.3 节（数据的六种形态与契约规则）、第 13.6 节（会话：磁盘结构与七条规矩）的第 1–5 条、第 13.12 节（段界插值与样本封存）、第 13.13 节（骨头的驱动通道预分配）`、`ADR-48`、`ADR-49`、`ADR-50`、`ADR-54`、`[glossary.md](glossary.md)`、`[08](08-engineering-standards.md)` 第 6、7 节。
- **输入**：
  - T-46 的不可变建造记录、编号表与 `checks`；
  - 实验室或合成两段连续运动（覆盖"首段静止、次段动下颌"及"非零通道下段省略"）。
- **输出**：
  - `motion` 模块（`resolve(parent_controls, segment)`：识别起步/追加/保持/复位，单位转换与插值，分离物理通道与显示通道）；
  - `sessions` 模块基础目录与操作（`session.json`、`build/`、`states/<state-id>/`、`cache/<state-id>/`、`attempts/<attempt-id>/`、`refs/`；`create()`、`advance(parent, segment)` 等）；
  - `backends/febio` 首段 `.feb` 与续算 `.rst`（加 `-noappend`）写出及按绝对物理时间读回结果；
  - 验收测试 `C05`。
- **做法**：
  1. **会话新建与起步（ADR-49）**：根状态为参考姿态、零时刻和明确初始控制量；新建时锁住场景版本、建造记录、FEBio 可执行文件身份、相关库与线程设置。从根提交初始化段，支持纯重力沉降与第 0–14 帧非中性起步；仅在满足原有静止检查时标"已沉稳"，非中性起步无纯重力沉降区间时记录"不适用"和原因且不标"已沉稳"；随后接段绝不自动补沉降或末尾保持；
  2. **追加与缺省通道语义**：显式指定父状态（`motion` 读取父段末控制量，不读 `.dmp`）；父末帧 `f` 归父，子段发布 `(f, f+n]`，输入包含 `f` 作接头。省略已声明通道表示**保持父末值**，回零必须显式给出；接头控制值与父末不符时报错并指明通道，突变须写成有时间含义的动作；未知非零通道报错；物理通道样本与显示通道输入（如 landmark）一并封存；
  3. **插值规则（ADR-54）**：新会话默认分段线性；旧整段平滑（单调三次 Hermite）显式保留；显式要求平滑的新段只使用该段已知关键帧及父末值，端点用单侧规则，一次生成即封存，不承诺接头速度连续；**首版段格式不要求端点速度**；
  4. **续算写入、时间读取与段级设置**：首段写 `.feb`、追加写 `.rst`（共享建造编号表，采用 `-noappend` 并在正式入口核验）；两阶段整算对照须把两阶段均写成 `Step`（已知坑：顶层 `Control` 后写普通 `Step` 会替换顶层 `Control`，[13 归档](archive/13-audit-history.md) E-23）。读取器必须按**绝对物理时间**匹配帧（已知坑：FEBio 续算后步数从 1 重新数，按步号会叠帧）；段级覆盖先只开放已验证的段界换步长，迭代上限、数值阻尼等首版沿用会话值；
  5. **补齐 Q8 第二类用例（ADR-48）**：首段颅骨和下颌均静止，次段驱动其中一块、另一块保持，再在后续段省略非零通道，对照相同实际样本和步序的整算（按续算门限单列：位置 `1e-5 mm`、速度 `1e-4 mm/s`、应力 `1e-6 MPa`，[13 归档](archive/13-audit-history.md) E-23）。
- **验收**（只看到 `passed` 或退出码 0 不算交付，必须贴出真实命令与完整打印输出作为证据）：
  - 运行 `uv run pytest -s -k C05`，经正式 CLI/会话入口完成新建会话、初始化和追加第二段，打印：父末帧、子首末帧、绝对物理时间表、接头处控制值，以及与同实际样本整算的逐帧最大差（位置、速度、应力对照 `1e-5 mm` / `1e-4 mm/s` / `1e-6 MPa`）；
  - "先静后动"（首段不动、次段动下颌，验证通道预分配）和"非零后省略"（省略已转下颌通道时保持父末位姿）均通过；
  - **必须失败的坏例**：
    1. 子段接头控制值与父末不符（接头跳值），必须报错并指出具体通道；
    2. 首段静止的可动下颌被写成永久固定导致次段无法驱动，必须失败；
    3. 追加子段时重复计算沉降或把省略通道拉回零位，必须失败；
  - 交付最终状态跑 `uv run python tools/verify.py` 并记录实际输出。
- **不做**：不许动已锁定的建造、已经发布的样本、旧整段插值语义。
- **依赖**：T-46。
- **改动范围**：`motion`、`sessions`、`backends/febio`（首段与重启写入、时间读取）、`results` 读取。
- **规模**：没有估。
- **注意**：
  - 接头处是否提供端点速度**现在不定**（等实验室真实两次连续按键记录证明速度突变对研究任务造成可重复、显著影响后再增可选端点速度）；本卡首版不加端点速度，新段默认分段线性；
  - 续算一致容差（`1e-5 mm` 等）与旧场景迁移容差（`1e-9 mm`）分开登记，绝不用较宽的续算容差代替旧场景迁移验收；
  - 生产检查必须先查看**全部实际时间**再筛期望帧，不可照抄旧试验脚本先筛帧再查的做法（[13 归档](archive/13-audit-history.md) E-23）。

### T-48 失败、分支、删档重放 🔴（依赖 T-47）
- **状态**：🔴 在等 T-47
- **目标**：用户可从运动中的已提交状态开出两条不同未来、在运行中途杀掉一路后安全重试、并发提交同一分支而不丢状态，并可清光 FEBio `.dmp` 缓存后只凭已提交记录重放恢复且核对结果。
- **为什么**：本机 FEBio 会话实测（[13 归档](archive/13-audit-history.md) E-23）已经抓到致命故障：如果续算直接改写起点存档路径，进程被杀后再重试，**12 次里有 11 次"正常结束"且健康检查通过，实际却从第 33–35 帧接着多走 24 帧停在第 70 帧（预期第 46 帧）**；而在独立副本上重试、同档分两路、删档重放则全部与基线一致（误差 0 或 `1e-10 mm`）。不先落实独立工作副本、提交前全时间检查和原子整目录发布，就不能签会话三条承诺。
- **按照**：`[04](04-architecture.md) 第 13.6 节（会话：磁盘结构与七条规矩）的第 5–7 条、第 13.7 节（检查与提交的分工）`、`ADR-49`、`ADR-50`、`[archive/13-audit-history.md](archive/13-audit-history.md) E-23`、`[08](08-engineering-standards.md)` 第 6、7 节。
- **输入**：
  - T-47 的可续算单嘴唇会话与运动中状态；
  - 两组分叉运动输入及用于故障注入的坏例数据（多走 24 帧、重复时间、错父档、截断行、篡改结果）。
- **输出**：
  - `sessions` 完整能力（独立尝试目录与父档副本复制/校验、同卷暂存整目录原子发布、带预期旧值的分支引用更新、`checkout()`、`replay()`、`drop_cache()`、失败恢复与已校验提交复用）；
  - `checks` 的提交前硬门槛校验（全实际时间表、精确结束时间、重复时间、截断行、父档/建造身份、摘要与重放数值参照核对）；
  - 验收测试 `C06`。
- **做法**：
  1. **独立工作副本与提交前检查（ADR-49、ADR-50）**：每次尝试新建独立 `attempts/<attempt-id>/`，校验父档摘要后复制到工作副本，禁止 FEBio 写父档原路径。后端交出原始顺序与全部记录，`checks` 必须在取整、去重和挑预期帧**之前**核对正常结束、全部实际物理时间、精确结束时间、完整行、节点身份、有限值、网格健康（倒置四面体等）、未列出警告、父状态与建造身份。硬门槛失败或必做检查缺失时，绝不发布子状态，尝试目录仅留诊断，父状态与父档保持可用；
  2. **原子发布与并发分支**：先在同卷临时目录写齐结果、清单和摘要并关闭文件，再一次重命名发布整个子状态目录 `states/<state-id>/`，最后带预期旧值更新 `refs/` 分支引用。同一父状态允许多个成功子状态；两个任务争更新同一分支引用时，引用只移动一次，后到者收到分支已移动的提示，两个有效子状态都能按 ID 找回。崩溃后未发布目录不算状态，已发布但分支未移动的子状态可按 ID 找回；相同父状态与相同有效输入重试时复用已校验提交；
  3. **删档重放与缓存清理**：状态身份覆盖父 ID、建造与环境身份、有效设置、物理样本及显示输入。字节摘要抓文件损坏，数值参照按登记容差（位置 `1e-5 mm`、速度 `1e-4 mm/s`、应力 `1e-6 MPa`）抓重算漂移。`drop_cache()` 清光 `cache/` 时不删任何已提交输入和结果；缺档或错档时从最近有效祖先重放恢复；换 FEBio 构建或环境建立标明来源的新计算记录。
- **验收**（只看到 `passed` 或退出码 0 不算交付，必须贴出真实命令与完整打印输出作为证据）：
  - 运行 `uv run pytest -s -k C06`，从 T-47 运动中状态执行分两路、杀掉一路、重试、并发更新同一引用、清光缓存后重放与崩溃恢复，打印：两个确实不同的子状态 ID 与位移差、父状态和父档前后摘要（不变）、清缓存重放后的逐帧误差、崩溃后按 ID 找回的状态、并发争引用时引用只移动一次且两个有效子状态均可找回的记录；
  - **必须失败的坏例（均须由正式入口拒绝提交或拒绝复用）**：
    1. 注入预期第 46 帧、实际走到第 70 帧（多走 24 帧）的输出；
    2. 注入重复时间记录；
    3. 注入错父档（或父档摘要不符）；
    4. 注入截断行（被杀运行残留的半条记录）；
    5. 篡改已提交结果数组或摘要（例如把位置改 `2e-5 mm` 或改坏字节）；
  - 交付最终状态跑 `uv run python tools/verify.py` 并记录实际输出。
- **不做**：不许动父档、旧状态目录、原结果摘要；失败后不得发布半个状态。
- **依赖**：T-47。
- **改动范围**：`sessions`、后端存档工作副本、`checks`、分支引用。
- **规模**：没有估。
- **完成后冻结**：**本卡通过验收后，冻结状态提交、分支和重放契约**，此时才签会话三条承诺（过去不被追加改写；同一存档可以走两条未来；失败保留最后一次成功状态）。
- **注意**：
  - Windows 实际数据卷上的断电/中断恢复故障试验（以及未来若用网络盘时的重验）属于"仍待证据的假设"；本卡按同卷暂存、关文件后整目录重命名与带预期旧值更新引用实现，并在本机数据卷做故障注入测试。

### T-49 第一条长间距边 🔴（依赖 T-46、T-48）
- **状态**：🔴 在等 T-46、T-48
- **目标**：用户可运行包含长间距软粘连的合成双组织场景，经正式 `build`、`backends/febio`（含逐点与按单元对精确合并两种写出）和 `results` 读回两侧物体结果，并按边 ID 查清逐点对应、外推系数放大指标与后端约束实现记录。
- **为什么**：演示场景绝大多数粘连隔着几毫米到几厘米（组织→组织中位 3.2 mm、最大 60.7 mm；皮肤→组织中位 8.1 mm、最大 34.7 mm），且 49 条皮肤渐变边需要逐点给刚度。已实测 FEBio 的 `tied-elastic` 一条界面只有一个罚系数，且在 15 mm、15° 旋转下与"跟着转"差 `3.9158 mm`（[13 归档](archive/13-audit-history.md) E-23）；而"目标四面体外推参考点 + 纯罚线性约束"已在本机通过事先登记的 9 项试验（[13 归档](archive/13-audit-history.md) E-23），且按单元对的 QR 等价合并已通过矩阵算术复算（32 行合并为 8 行误差 `1.42e-14`），但尚未经正式生成器实跑，也必须用检查锁住省略 `<laugon>` 导致粘连变硬等已发现的坑。
- **按照**：`[04](04-architecture.md) 第 13.3 节（数据的六种形态与契约规则）、第 13.7 节（检查与提交的分工）、第 13.9 节（粘连：三层表达与 FEBio 实现）`、`ADR-47`、`ADR-51`、`[13](13-explanations.md) E-24`、`[archive/13-audit-history.md](archive/13-audit-history.md) E-23`、`[08](08-engineering-standards.md)` 第 6、7 节。
- **输入**：
  - T-46 的 `build` / `backends/febio` / `checks` 骨架与 T-48 的完整会话续算与原子提交；
  - 合成双组织长间距场景（如 15 mm 间隙、目标四面体外推与对照配置）。
- **输出**：
  - `build` 内的逐点对应与面积加权刚度计算、外推系数与单元质量诊断报告；
  - `backends/febio` 的纯罚线性约束逐点写出与按单元对 QR 等价合并写出、实现记录及世界方向落点对照（可另含 tied 对照）；
  - `checks` 对 `<laugon>` 标签、退化单元、远端力/力矩平衡和合并等价性的核验；
  - 验收测试 `C07`。
- **做法**：
  1. **建造中的逐点对应（ADR-51）**：在源参考表面先转物理毫米再算逐顶点面积（相邻参考三角形面积的 1/3），算每点刚度 `kᵢ = K × Aᵢ × wᵢ × eᵢ`（N/mm，须非负）。在每条边指定的目标物体与选区内找落点 `q₀`（记录参考三角形、面内重心坐标、`g₀ = p₀ − q₀`）；**支撑四面体从目标落点 `q₀` 的显示绑定选**（不得直接在空间找离 `p₀` 最近的四面体，以免选错组织）。在目标四面体中算重建 `p₀` 的外推重心系数 `β`（源侧算到源四面体的 `α`），显式记录采用的参考点规律（本卡首试仿射外推，同时保留按落点算 `β` 的世界方向配置作对照）。逐边报告 `|g₀|` 分布、支撑单元厚度或质量、最大 `|βⱼ|`、`Σ|βⱼ|` 和受影响面积；**退化单元直接拒绝，严禁剪掉负系数**；
  2. **FEBio 后端逐点写出与强制校验**：软约束必须写在 `<Constraints>` 下的 `linear constraint`，显式写入 `<laugon>0</laugon>`、实际 `<penalty>` 和 `<rhs>0</rhs>`，不得写入 `<Boundary>` 消元，不得省略 `<laugon>`（本机实测不写 `<laugon>` 默认增广拉格朗日，0.1 N 位移变成 `7.5×10⁻⁸ mm` 而非 `0.2 mm` 且无警告，[13 归档](archive/13-audit-history.md) E-23）；
  3. **按单元对的 QR 等价合并（放后端，ADR-51）**：对同一边、同一有序支撑自由度组内固定系数、零右端、各向同性、非负 `kᵢ` 的纯弹性罚约束，取固定参考刚度 `k* = 1 N/mm`，令 `Dᵢ = √(kᵢ / k*) aᵢᵀ`（同一全局节点重复先相加），做 `D = QR` 分解，把 `R` 写成系数、罚系数写 `k*`（4+4 平移节点时每轴至多 8 行，原不足 8 行保留原行；不删给定自由度；不跨边合并）。记录实际写出行数、系数精度、版本和逐点回溯关系。**保留逐点模式作裁判**，对**写出再读回的系数**核对整块矩阵 `K` 与逐节点恢复力 `-KU`，并跑同一载荷和运动中续算对照；
  4. **独立力/力矩核对**：已知 FEBio 4.13 的约束力不出现在被给定位移的目标节点 `Rx` 里（合计为 0），且 `zero displacement` 不记反力、`Rx` 与支座力反号（[13 归档](archive/13-audit-history.md) E-23）。验收必须使用已知外载与**未参与约束的远端支座**（先校准反力符号），并逐点用 `cᵢ` 重建源侧 `-kᵢ α cᵢ`、目标侧 `+kᵢ β cᵢ`（注明符号、单位和取矩位置）。

### T-41 对齐物理尺度和重力，查清下垂和甩头的差距 🔴（原型机交付之后；校准数据要再上一次 Ziva 机器）
- **目标**：知道 Ziva 求解时把这张脸当成多大、重力按什么单位算，把我们的物理尺度对上，或者写明为什么不对上。
- **为什么**：重力下垂我们 0.12 mm、Ziva 整张脸 0.29 mm；甩头我们约 0.1 mm、Ziva 2.7 mm（[13](13-explanations.md) E-19）。粗格子四面体解释了嘴型（E-20），没有解释这两项：粗格子上甩头是 0.087 mm，下垂更小。🔍 一个没有核实的线索：如果 Ziva 把 1 个场景单位当 1 厘米（它的求解器变换三轴缩放是 100），按"下垂 ∝ 长度² × 密度 × 重力 ÷ 刚度"算，下垂会是我们的约 15 倍，和只留嘴唇那次量到的倍数（14.6，还没停稳）同一个量级。2026-11-15 把我们的物理尺度直接改成这个值，FEBio 不收敛（负体积），没有得到数。
- **做法**：
  1. 校准（[11](11-risks-and-questions.md) 的 D18，要上 Ziva 机器）：一段短的自由落体，加一次换了求解器缩放的运行，直接量出 Ziva 的长度尺度；D17（更长的只有重力的运行）一起做；
  2. 在我们这边查清大尺度下为什么不收敛：从 k = 0.67 逐步加大（1、2、4、8），看从哪一档开始失败、失败在哪一帧，粗格子和细网格各做一遍；
  3. 尺度有了实测值以后，重跑 `asrp compare`，下垂、甩头、逐帧差各报改之前和改之后的数；尺度是一个场景参数，默认值改不改另行决定（ADR-31 是按会议结论取的真人大小）。
- **验收**：有 Ziva 长度尺度的实测值和量法；有一张 k 对下垂、对收敛的表；改之前和改之后的对比报告各一份；不拿调材料或阻尼去凑下垂。
- **依赖**：D18、D17 的数据（项目负责人安排上机）；第 2 步不依赖。
- **改动范围**：`src/asrp_core/generate.py`（如果不收敛的原因在生成器）、`docs/05` 第 2 节、`docs/11`、`docs/13`。

### T-07 粘连做法试验（S3） 🟢（第 1、2、4 步 ✅ 2026-11-11；第 3 步推后到第二阶段）
- **目标**：验证 [05](05-ziva-to-febio.md) 第 3 节定下的两种做法（上唇 `hard`、下唇和嘴角 `spring`）写得对，并给出弹簧基础刚度的取法。第 2 步的比较如果推翻了 05 第 3 节的类型，停下来报告，不自己改。
- **已完成的步骤**（结果在 05 第 3 节"T-07 第 1、2 步的结果"和 ADR-36，复现 `uv run python tests/s3_attachment.py [--extra]`，快速部分 `uv run python -m pytest tests/test_s3_attachment.py`）：
  - 第 1 步：挂在 4 根弹簧上的方块，伸长和理论值 ρ·V·k²·g ÷（4K）比，k = 1 误差 1×10⁻⁹%、k = 2 误差 0.0165%；
  - 第 2 步：软方块用 `hard` 和 `spring` 粘在转动的板上，K 从 10⁻³ 加到 10¹⁰ N/mm，14 档单调趋近 `hard`（差 ≈ 2×10⁻³ N ÷ K）；零长度的单根弹簧不收敛，所以每个节点三根带偏移的弹簧，δ ≥ 10 × 最大滑移；
  - 第 4 步：六个自由度全固定的刚体可当颅骨用（05 第 1 节）。
- **第 3 步推后到第二阶段**（[13](13-explanations.md) E-09）：试验粘连权重小于 1 的情况，并和假设 A-23（"刚度 × 权重"，只是假设，以 Ziva 文档或实验室说明为准）一起验证。原因：嘴唇四组粘连的 807 个权重全是 1.0（`data/lab_export/lip_attachments.json`），第一阶段用不到小于 1 的权重；只有第二阶段的皮肤粘连才用（[03](03-asset.md) 第 13.5 节）。
- **弹簧基础刚度**：现在是我们定的 100 × E × h（05 第 3 节）。Ziva 的 140 个粘连全是软约束，刚度 1×10⁸ N/m³，阻尼 0.01（E-11；单位见 E-14 第 3 条，要乘一个面积才是弹簧刚度）；怎么换算并改过来是 T-37 的第 2 项，敏感度在 T-06b 的参数影响报告里量。
- **按照**：05 第 3 节；FEBio 手册（安装目录 `doc/FEBio_User_Manual.pdf`）：
  - 硬绑定：第 3.11.16 节的 `rigid` 边界条件，把一组计算点并入刚体；或者像 S1 那样让组织和刚体共用计算点；
  - 弹簧：第 3.6.7 节的 `DiscreteSet` 加第 3.16 节的 `linear spring`（刚度参数是 `E`）。弹簧的另一端需要一个计算点，再用 `rigid` 条件把这个点并入骨头。**一个弹簧材料只能有一个刚度**，所以"刚度 × 权重"要把权重分成几档，每档一种材料。
- **输出**：试验代码（放 `spikes/`），结论写进 05 和 10。
- **验收**：第 3 步做的时候（第二阶段）：有试验结果和结论写进 05，A-23 在 11 里相应更新。第一阶段不要求；A-23 在 11 里标"第一阶段用不上"。
- **不做**：用实验室资产做试验。

- **产品现在能跑什么**：求解入口拒绝第一帧不是静止姿态的运动（`src/asrp_core/generate.py` 对驱动源第 0 帧的检查，05 第 3 节"运动的第 0 帧"一行）；单独转换出的一段也不带组织的速度、应力和之前的加载历史。所以不从中性出发的段，只有拼进一条从中性开始的完整序列里才能运行。单独的一段非中性过渡暂时只是离线输入，不能直接跑：这时 `asrp run` 的报错会直接说明原因和做法（接在通向它起点的那一段后面，放进同一条从静止开始的运动里），不用去翻代码（2026-11-13 改了报错并加了测试）；要等重启或显式的初始状态协议做出来（T-30 是这项能力的试验）。

### T-20 规则格子加嵌入的四面体生成试验 🟢
- **目标**：做一个和 fTetWild 并排比较的备选生成办法：用整齐的格子罩住嘴唇表面，保留在实体内部的格子；同一格里上下唇不相连的部分，各自成格（各算各的）。
- **为什么**：现有办法（fTetWild，ADR-20）每次结果不同、偶尔崩溃、会出极小的四面体，还依赖锁了版本的第三方包；格子办法是确定的、不怕表面自相交，Ziva 自己就是这类做法。网格已经是独立的文件，换生成办法不影响下游。详见 [13](13-explanations.md) E-03 末尾。
- **触发时机**：和 T-17、T-23、T-24 三个试验一起做，在第二阶段投入之前。T-06a 的运行没有出现嘴角小四面体的问题（0 次重试、没有负体积），所以不是为了救急。
- **做法**：生成的网格过 `asrp_core.tetmesh` 同一套检查和同一个 FEBio 重力沉降测试（`tests/s2_lips_febio.py`），再和 `data/tetmesh/lips.json` 并排比较：结果（下沉量、嘴缝宽度、嘴角处的行为）、速度、稳定性（重复生成是否逐位相同、有没有极小的四面体、有没有崩溃）。
- **进展（2026-11-15，ADR-44）**：格子办法已做成产品里第二个可选的网格 `data/tetmesh/lips_lattice.json`（126 个四面体，格边 = Ziva 的 `tetSz` 换算成 25.37 mm，原点 = 表面包围盒最小角，上下唇**不**分开，文件里写明），生成 `uv run python tools/build_tetmesh.py --method lattice`，有自己的检查 `tetmesh.check_lattice`，生成两遍哈希相同。代价是上下唇是一个整体；好处是在实验室的 AA 上上唇被带动（5.5 mm，Ziva 4.80），细网格几乎不动（0.22 mm）。后来项目负责人定了（ADR-44）：面板默认用粗格子，`asrp import-asset` 命令行不加选项时仍是 `lips.json`。上面"同一格里上下唇不相连的部分各自成格"这一点**没有**做（684 个四面体的试验里它让上唇不动，ADR-42）。比较报告写进 13 的 E-03 和 11 的 A-32 仍待做。
- **输出**：试验代码（放 `spikes/`）、比较报告（写进 13 的 E-03 和 11 的 A-32）。
- **验收**：同样的输入重复生成，网格逐位相同；通过 `tetmesh.check` 全部检查；FEBio 重力沉降测试正常结束；报告有上面三项比较，并给出明确结论（换 / 不换 / 并存）。
- **不做**：换掉现有网格（换不换由项目负责人看报告决定）；改下游。
- **依赖**：T-04。
- **改动范围**：`spikes/`、`docs/13`、`docs/11`。
- **规模**：中。

### T-24 原型机上的"landmark 进物理"试验 🟢（T-09 ✅）
- **目标**：在原型机上试一个模式：让 landmark 的运动进入物理计算，而不只是事后叠加，并报告规模、耗时和稳定性。
- **为什么**：[13](13-explanations.md) E-07 的"landmark 进物理"模式。实测（E-11）表明 Ziva 自己也是事后叠加，所以这张卡不是为了和 Ziva 一致。它回答第二阶段要不要这种模式：实验室把多段过渡拼成序列时，按运动文件开环相加，蒙皮后的形状每来回一圈多偏 0.52 mm，物理层不累积（11 的 A-39）。现有的"锚 + 弹簧"可以表达这个模式，要先试规模和稳定性。
- **时机**：和 T-17、T-23 互不依赖。
- **按照**：[05](05-ziva-to-febio.md) 第 3 节（锚和弹簧）；04 第 2 节。
- **规模先数一数**（E-09 的测量，`spikes/audit_skin_identity.py`）：嘴唇每个顶点正好受 20 个 landmark 影响（10,240 × 20 个顶点–landmark 对；每个 landmark 管 197 到 1,962 个顶点）。"每个顶点–landmark 对一根弹簧"是现在 1,428 根弹簧的一两百倍。
- **做法**：
  1. **第一步先数**：对选定的方案数弹簧和刚体的个数，估出每帧耗时，再决定做不做；同时考虑另一个办法：不用弹簧，直接把蒙皮算出的目标位置按给定位移加到每个表面节点上（prescribed）；
  2. 每个 landmark 一个锚（运动取 `trajectory.json` 里这个 landmark 的运动），蒙皮权重当弹簧权重，用现有的锚 + 弹簧机制，不加新的粘连类型；规模撑不住时改用上面的另一个办法。
- **输出**：试验代码（放 `spikes/`）；报告：弹簧数、每帧耗时、稳定性；结论写进 05 和 10。
- **验收**：
  - 所有 landmark 都在静止位置时，结果等于只有物理的结果；
  - 只移动一个 landmark，周围的表面平滑地跟着动；
  - 报告弹簧数（先数的和实际的）、刚体数、每帧耗时、稳定性；
  - 和 T-09 的事后叠加结果比较，说明差别。
- **不做**：把它做进 `asrp run` 的正式流程；全脸。
- **依赖**：T-09 ✅。
- **改动范围**：`spikes/`、`docs/05`、`docs/10`、`docs/11`（A-39）。
- **规模**：中。

### T-31 让实验室的训练环境不经过 Maya 读到嘴唇形状 🟡（第一版 ✅ 2026-11-12；用真实数据的验收 ✅ 2026-11-13；剩 T-37 第 4 项的清理）

### T-33 弄清甩头要怎样才在时间步上收敛 🟢（原型机二之后）
- **目标**：让动态结果在时间步上收敛，这样甩头的幅度、峰值出现的时刻和停下来以后的衰减才有意义；或者说明在现有条件下它收敛不了、还缺什么。
- **为什么**：时间步细分（T-28 的结果，[13](13-explanations.md) E-10）表明默认设置下甩头的响应到每帧 16 步还没有收敛。Ziva 整张脸的中性到 AA 在子步 2 对 1 时最大差 0.165 mm（沉降段）和 0.075 mm（运动段），只在这一段上试过（E-14 第 5 条）；Ziva 的同一段甩头里嘴唇相对颅骨最大 2.7 mm（E-15，整张脸，不是只留嘴唇；那次只移动了颅骨和下颌，另外 8 块骨头没动，2.7 mm 不全是惯性），所以现在有了可以对照的参考，但范围不同。为什么不收敛**还没有查清**，现在有两个候选，都只是推断（🔍）：
  1. **数值阻尼随步长变小**：默认的 `rhoi` 0 每一步抹掉的振动和步长有关，步子越细抹得越少，响应就越大；没有物理阻尼时没有别的东西让它停下来。旁证：头不动的对照自己也随步数变（每帧 1 步时几乎不动，16 步时自己晃到 0.025 mm），16 步那次到第 14 帧也没沉稳。这一条和骨头怎么动无关；
  2. **骨头的运动在帧之间是折线**：生成器把每块骨头的位移写成每帧一个点的线性曲线，帧内匀速，每到一帧速度跳一次（量到最大的一跳是头最大速度的 94%）。实验室的关键帧本来是带缓入缓出的曲线。细分步长只是把这些跳变算得更清楚，去不掉它们。这个跳变量到了，但它对不收敛贡献多少没有量。
- **做法**：
  1. 分开两个候选要交叉比，单看一边分不出因果（静止的响应和受迫的响应会互相影响）。同一套设置下跑四组：头不动 / 甩头 × 折线 / 平滑曲线，每组做同样的步数细分和同样的阻尼。开始前写下比较的时间窗（比如运动段和停下后的固定帧数）和"整条曲线差多少算收敛"的门限，之后不改。现有的 28 次运行只能当起点，不够下结论；
  2. 生成器加一个选项：骨头的位移在帧之间用平滑曲线（先查 FEBio 的载荷曲线支持哪些插值；不支持就把曲线按子步取样写进去）。**默认仍是现在的折线**，所以已有的结果不变。方块上验证骨头的位置和速度收敛到解析值；
  3. 带物理阻尼、数值阻尼用 `rhoi` −2（没有数值阻尼）重做细分，看有物理阻尼时响应收不收敛。物理阻尼按 Ziva 的设置取能写进来的部分（Ziva 是刚度阻尼 0.001、质量阻尼 0；我们只有质量阻尼，见 T-37 第 3 项），取不了就标"我们定的"。数值阻尼只用 0 或 −2，不用中间的值（[05](05-ziva-to-febio.md) 坑 20）；沉降不够长就加长沉降，直到运行报告的 `tissue_settled` 为真再开始甩头。
- **验收**：
  - 默认选项下，已有运动的 `.feb` 和以前逐字节相同；
  - 一份书面结论：先定义每个候选的效应和两者的交互怎么算（四组交叉比），再按这个定义报数；两者可能互相影响，不保证能唯一分账；在什么设置下相邻两档步数之间整条曲线的最大差小于峰值的百分之几，或者到哪一档还差多少。不外推；
  - 收敛了的那一档，和 Ziva 的 2.7 mm（整张脸，只移动了颅骨和下颌）并排报告，标明范围不同；顶点掩码、基准帧、停止帧和观测时窗按 T-34 第 5 步统一；衰减按 T-34 第 5 步的两个数报。
- **不做**：调阻尼凑一个好看的幅度；把平滑插值改成默认（要等这张卡的结果）。
- **依赖**：无。
- **改动范围**：`generate.py`、`scene.py`（选项）、`tests/`、`spikes/`、`docs/05`、`docs/09`。
- **规模**：中。
- **结果**（2026-11-15，**到每帧 16 步没有收敛**）：
  - **选项**：场景参数 `solver.motion_between_frames`（`"linear"` 默认，不写等于它；`"smooth"`）。smooth 是穿过每帧取值的单调三次 Hermite 曲线（切线规则和 `tools/head_shake_motion.py` 画曲线的一样，不过冲，停着的骨头保持不动），每个子步写 4 个点。FEBio 自己有 `SMOOTH` 插值（手册 3.18.1），但手册没说它用什么切线，所以曲线在生成器里算。默认选项下三条已提交的运动（`head_shake`、`neutral_to_AA`、`tests/fixtures/s1`）加一个带阻尼、`rhoi` −2、4 子步的甩头变体，生成的 `.feb` 和改动前逐字节相同（`cmp` 对四个文件，sha256 不变，如甩头 `31ab84c6…`）。`tests/test_smooth_motion.py` 13 条；曲线对解析正弦：位置和速度误差随帧距减半缩小 4 倍以上，直线段的速度每帧跳一次，smooth 的跳变小 8 倍以上；故意去掉"极值处切线归零"那条规则，守住不过冲的测试失败。**方块上的"位置和速度收敛到解析值"是在曲线上验的，不是经 FEBio 验的**：FEBio 只在帧末写位置，帧内的速度读不出来；FEBio 里只验了骨头按 smooth 曲线走时帧末位置和直线版一致（1e-6 mm）；
  - **事先写下的**（一次性脚本和事先登记在仓库外，不进仓库）：时窗第 15 到 86 帧（第 14 帧是沉降最后一帧）；相邻两档（n 与 2n）整条曲线的最大差，除以较细一档在时窗内的峰值；门限 5 %；不外推。量法同 E-19：全部 10,240 个显示顶点、相对头、基准第 14 帧、`compare.wobble`；材料用 Ziva 实测的值（`import-asset --tissue-settings lab`）。两组阻尼：A（默认：`rhoi` 0、物理阻尼 0）；B（物理阻尼 C = 45/秒，我们定的，T-28 演示用的那个值，不是为幅度挑的；`rhoi` −2）。每组：头不动 / 甩头 × 折线 / smooth × 每帧 1、2、4、8、16 步，共 40 次运行里实际只跑了 35 次：头不动时 smooth 和折线是同一个运动，两条对照取同一次运行（A 组 n=1、2、16 上两次运行的峰值相同到小数点后四位，只验了这几档）。32 步没做（16 步一次运行已远超十分钟）。全部 `passed`，没有 FEBio 重试；
  - **整条曲线的最大差，占较细一档峰值的百分比**（门限 5 %，没有任何一对低于）：

| 组 | 运动 | 1→2 | 2→4 | 4→8 | 8→16 | 16 步的峰值 mm |
|---|---|---|---|---|---|---|
| A | 折线 | 192 | 72 | 42 | 81 | 0.567 |
| A | smooth | 91 | 67 | 45 | 56 | 0.255 |
| B | 折线 | 79 | 115 | 64 | 50 | 0.313 |
| B | smooth | 72 | 194 | 80 | 38 | 0.152 |

  - **头不动的对照**（同一个量，峰值在第 15 帧之后）：A 组 n=1、2、4 是 0.000 mm，n=8 是 0.0011，n=16 是 0.102 mm；B 组 n=1…16 是 0.361、0.168、0.026、0.0035、0.0011 mm。两组在第 14 帧**都没有沉稳**的档（`tissue_settled` 为假）：A 组 n=8 和 16（沉降最后一步 1.3×10⁻³、2.0×10⁻² mm），B 组全部五档（n=16 是 1.08×10⁻³ mm，刚好高于 10⁻³ mm 的限）。卡里说"沉降不够长就加长沉降"，**这一步没做**：要重写运动文件，基准帧、停止帧也要跟着挪，和 Ziva 的第 14、46 帧就对不上了；
  - **两个候选各占多少**（🔍 只对这两组设置，不唯一分账）：候选 2（折线）：同一档同一阻尼下 smooth 对折线的峰值，A 组 n=2…16 是 0.096/0.042、0.197/0.122、0.315/0.157、0.255/0.567；B 组 n=4…16 是 0.345/0.597、0.204/0.446、0.152/0.313（smooth/折线）。n=1 两者逐位相同，因为每帧一步时 FEBio 只用帧末的值。B 组细档上折线的峰值约是 smooth 的两倍，所以折线的速度跳变是一个量级相当的成分，不是小事；但两者的差也不是常数，不能说折线占了几成。候选 1（数值阻尼随步长变小）：A 组头不动的对照在 n=16 自己晃到 0.10 mm，和甩头峰值（0.25 到 0.57 mm）同一个量级，所以 A 组细档的"甩头"里有一大块是沉降没有结束的晃动；B 组头不动的对照随步数单调缩小到 0.001 mm，所以 B 组的非收敛不是沉降的残余。**A 组不会收敛**（🔍 推断）：`rhoi` 0 的数值阻尼随步长缩小而消失（05 坑 20），又没有物理阻尼，整条曲线上的晃动不会衰减，三秒（约 200 个振动周期）里相位误差累积，再细一两档也不会让整条曲线对齐；B 组有物理阻尼，smooth 的相邻差逐档缩小（194、80、38 %），每档约减半，但到 16 步还是峰值的 38 %，没有到门限，不外推；
  - **和 Ziva 并排**（没有收敛的档，不是收敛值）：Ziva 的 2.731 mm 是整张脸、只移动了颅骨和下颌；我们只有嘴唇。B 组 smooth 每帧 16 步，我们的 0.152 mm（第 18 帧）；折线 0.313 mm（第 45 帧）。衰减按 T-34 第 5 步的两个数（门限 0.04 mm，时窗 40 帧）：Ziva 是第一次低于 14、一直低于 28；我们 B 组 smooth 16 步是 2 和 2，折线 16 步是 6 和"时窗内没有达到"。这些数在 T-34 的两个数上有意义要等收敛，**现在不能当作我们的衰减**；
  - **没做、没验的**：32 步；加长沉降的重做；另一个物理阻尼值（只试了 C = 45，没有按 Ziva 的刚度阻尼换算；换算要先定模态，🔍 估计要大几倍，没有量）；刚度阻尼在 FEBio 里没有（05 第 4 节）；让整条曲线收敛可能还要更细的步或沉降更长，这里没有证据说多细。T-34 的并排比较保持原样（每帧 1 步、折线）；这张卡的结果不改变它的数字，只说它不能当幅度用。
