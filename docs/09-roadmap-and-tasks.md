这份文档把第一阶段拆成几个里程碑，每个里程碑再拆成任务卡。**任务卡就是交给开发者（人或 AI 开发会话）的完整说明**：拿到一张卡，加上 [README](README.md) 里开发者要读的文档，就能开工。所有任务卡都按 [templates/task-card.md](templates/task-card.md) 的格式写。

## 1. 里程碑

```
M0 基础 ✅ ──► M1 原料就绪 ✅ ──► M2 物理段 ──► M3 landmark 段 ──► M4 对比与评审 ──► M5 界面与验收 ──► 【关：T-17、T-18 复核 FEBio】──► 第二阶段投入
```

**原则：先让真实资产从头到尾跑通一次，再逐项细化。** M2 先做一个粗糙但完整的第一版（T-06a），缺的数据用标明来源的临时值，这样真正的问题（四面体质量、尺寸、稳定性）能尽早暴露。

**原型机**（项目负责人 2026-11-11 确认，11 的 P-05；**定义只写在这里**，其他文档链到这一节）：**真实嘴唇在 Blender 里被下颌带动、由 FEBio 算出、能回放**，**不含** Ziva 对比（M4）和验收流程（M5）。目标日期 **2026-11-17**（2026-11-10 会议上说的"下周二之前"，[14](14-ziva-demo-walkthrough.md) 第 3 节 17:32；此前期待的是 1–2 周）。会议上还说不需要和 Ziva 对得很齐（11 的 Q12）。

### T-01 取齐 Ziva 机器上的数据和实验室的回答 🟡（网格、权重、目标姿态、源码已拿到）
- **目标**：拿到原型需要、但 `.mb` 文件里读不出来的全部数据，以及实验室对 5 个问题的回答。
- **为什么**：Ziva 默认值不知道，运动文件和参考结果都不在文件里（[03](03-asset.md) 第 7、8 节）。
- **已完成**：清单第 1、3 项（本机 Maya，ADR-18；网格和 `.mb` 逐点核对过，权重和关节只有 Maya 自检，T-09 的精确对比才是它们的独立检查）；第 10 项目标姿态和源码（实验室源码仓库，ADR-35）。
- **负责**：项目负责人，配一位熟悉 Facial Expression Automator 的研究员。
- **做法**：
  1. 把 [12](12-lab-export-checklist.md) 第三部分那一页发给实验室（5 个问题，加第 5 项运动文件的请求，不需要 Ziva 机器）；
  2. 按 12 第二部分约 Ziva 机器，用 `tools/ziva_machine_export.py` 做第 2、4、7 项（第 5 项的逐帧关节矩阵随第 4 项导出）。**不等任何设计决定，赶在 Ziva 许可到期前做**；
  3. 第二阶段要的第 8、9 项脚本已支持（T-19），可以和上面几项同一次去做；机器时间不够就先做张嘴和甩头两条运动，其余下次补。Ziva 机器不限一次（ADR-24）。
- **输出**：`data/lab_export/` 下的全部文件，以及一份收货记录：每个文件对应清单的哪一项、收到的日期。
- **验收**：脚本最后打印 `ZIVA SESSION PASSED`。`session_report.json` 里：帧范围从 0 开始；Ziva 节点数大于 0；`motion_move` 大于 0（物理形状跟着下颌动了，说明 Ziva 真的解算了）；`frozen_frames` 为 0（中途没有停住）；`rest_offset` 小于 1（从静止形状开始，Ziva 确实重置了）；`jaw_degrees` 大于 1；`final_vs_physics` 大于 0；`ziva_maps`（导出的权重表个数）和 `ziva_meshes`（导出的网格份数）都大于 0，`notes` 里没有"网格和场景对不上"，或者研究员看过并写明原因。`gravity_sag` 很小时只给提示，要请研究员确认这个场景本来就是这样。`ziva_maps.json` 里粘连权重表的 `default` 已经查过（A-33）。清单每一项都打了勾，或者写明了为什么不需要。第 8、9 项（T-19 之后）：每个被解算的网格都有逐帧文件，帧数等于运动帧数、顶点数等于 `ziva_meshes.json` 里记的；每条运动都有第 4、5、8 项。
- **注意**：参考结果（D3）必须在 Ziva 许可到期前拿到，过期就再也做不出来了。它不是合格线（ADR-17），但研究员评审要用。脚本只在普通 Maya 上排练过，现场第一次真正解算（A-28）。

### T-04 嘴唇四面体化试验（S2） ✅
- **结果**（2026-11-06 初版，2026-11-09 复核定稿）：选定 fTetWild（ADR-20）。嘴唇网格自身穿插（05 坑 9），TetGen 不能用。fTetWild 每次结果不同（坑 12），所以网格用 `uv run python tools/build_tetmesh.py` 生成一次，提交在 `data/tetmesh/lips.json`，之后只读这个文件。定稿参数：包络 0.12 mm、边长 25.4 mm，6,747 个计算点；比较表见 ADR-20（`uv run python spikes/s2_tetmesh.py` 可重跑）；FEBio 重力沉降 `uv run python spikes/s2_lips_febio.py smoke` 通过。初版的问题、下颌张开压力测试（给 T-06a/T-07）见 [13](13-explanations.md) E-03。新问题：嘴角重叠部分和两个小孔是否和 Ziva 一致（11 的 Q11）。
- **目标**：确认能把嘴唇表面网格变成质量合格的四面体网格，并选定工具。
- **为什么**：Ziva 自己做四面体化，我们得自己做。实验室的网格在静止状态下可能有互相穿插，有些工具遇到这种网格会直接失败（A-10）。为什么绕不过去、这一步是怎么来的，见 [13](13-explanations.md) E-02。
- **按照**：[05](05-ziva-to-febio.md) 第 1 节 zTet 一行。
- **做法**：比较至少两种四面体化工具在 Windows 上的安装难度、对"不完美网格"的容忍度、网格质量和速度。边长按 `tetSz` 26.37 换算成毫米，包络和边长各试几档（定稿结果见 ADR-20）。

### T-07 粘连做法试验（S3） 🟢（第 1、2、4 步 ✅ 2026-11-11，结果在 05 第 3 节和 ADR-36；第 3 步待做）
- **目标**：验证 [05](05-ziva-to-febio.md) 第 3 节定下的两种做法（上唇 `hard`、下唇和嘴角 `spring`）写得对，并给出弹簧基础刚度的取法。第 2 步的比较如果推翻了 05 第 3 节的类型，停下来报告，不自己改。
- **为什么**：粘连决定嘴唇怎么被拉住，做错了结果会差很多。
- **按照**：05 第 3 节；FEBio 手册（安装目录 `doc/FEBio_User_Manual.pdf`）：
  - 硬绑定：第 3.11.16 节的 `rigid` 边界条件，把一组计算点并入刚体；或者像 S1 那样让组织和刚体共用计算点；
  - 弹簧：第 3.6.7 节的 `DiscreteSet` 加第 3.16 节的 `linear spring`（刚度参数是 `E`）。弹簧的另一端需要一个计算点，再用 `rigid` 条件把这个点并入骨头。**一个弹簧材料只能有一个刚度**，所以"刚度 × 权重"要把权重分成几档，每档一种材料。
- **做法**：
  1. 一个几乎不变形的方块挂在 4 根弹簧上，加重力。理论答案是每根弹簧伸长 = 方块重量 ÷（4 × 刚度），用它检查弹簧和重力的写法对不对。同一个算例再跑 k = 2（05 第 2 节）：几何毫米下的伸长理论值 = ρ·V·k²·g ÷（4K），V 是几何体积，K 是物理的弹簧刚度，误差 1% 以内；这是对 k 的做法在带弹簧时的检验；
  2. 一个软方块分别用两种做法粘在刚体上，加重力和刚体转动，比较变形、稳定性、计算时间；弹簧刚度逐步加大时，结果应该趋近硬绑定；
  3. 试验权重小于 1 的情况；
  4. （2026-11-11 已做：六个自由度全固定的刚体可用，见 05 第 1 节）把刚体整个固定（代替 S1 里"把一组计算点固定"的做法），确认颅骨可以这样处理。
- **输出**：试验代码（放 `spikes/`），结论写进 05 和 10。
- **验收**：第 1 步（k = 1 和 k = 2 各一个）和理论值误差在 1% 以内；第 2 步弹簧刚度加大时结果趋近硬绑定；给出弹簧基础刚度怎么取的规则（假设 A-23 要一起验证，或者标明待定）。
- **不做**：用实验室资产做试验。
- **依赖**：无。
- **改动范围**：`spikes/`、`docs/05`、`docs/10`。
- **规模**：小到中。

### T-17 软组织粘软组织试验（S4） 🟢
- **目标**：用合成方块试验，确认 FEBio 能做"软组织粘软组织"，并量每帧耗时和稳定性（ADR-26）。
- **时机**：随时可做。关卡设在第二阶段投入之前，不挡 M3（ADR-26）。
- **为什么**：论文里的模型有 36 个物体，肌肉、脂肪等互相粘连（4.1.3）；第二阶段要这样搭。我们现在只试过软组织粘刚体（S1，S3）。
- **按照**：[05](05-ziva-to-febio.md) 第 3 节；T-07 的结论（如果已经做完）。
- **做法**：两个软方块用粘连连在一起，一块挂在刚体上，加重力和刚体运动。粘连用两种做法试（共用计算点 / 弹簧，见 05 第 3 节）。方块的网格逐步加密，量每帧耗时随计算点数怎么增长；运动幅度加大到接近真实下颌的幅度，看会不会"负体积"或不收敛。
- **输出**：试验代码（放 `spikes/`）；结论写进 05 和 10（新的 ADR），把 11 的 A-30 更新。
- **验收**：
  - 有理论答案的小例子上，粘连后的位移和理论值一致（误差 1% 以内）；
  - 报告：计算点数 × 每帧耗时的表；最大可稳定的运动幅度；和 02 N-07 的暂定预算（每帧不慢于 Ziva 的约 2.5 秒，外推到全脸）比较，通过的方块只证明可行，不证明够快；
  - 明确写出结论：可以接受，或者不行以及原因。不行就按 ADR-26 重新评估求解器。
- **不做**：用实验室资产做试验。
- **依赖**：无（T-07 完成后更好）。
- **改动范围**：`spikes/`、`docs/05`、`docs/10`、`docs/11`。
- **规模**：小到中。

### T-18 薄壳皮肤贴在实体上的试验（S5） 🟢
- **目标**：用合成方块试验，确认 FEBio 能做"薄壳皮肤贴在实体上，带粘连"，并量每帧耗时和稳定性（ADR-26）。
- **时机**：同 T-17：随时可做，关卡设在第二阶段投入之前（ADR-26）。
- **为什么**：论文的皮肤是布料层，用 Ziva 粘连挂在内部组织上（3.7、附录 I）；手指按压要一只按给定运动走的手压在皮肤上（实验室的做法见 [03](03-asset.md) 第 13.8 节），烧伤要把皮肤刚度乘 40（4.4.7）。第二阶段要做皮肤（方案 B，ADR-32），FEBio 里要用专门算薄片的壳单元，难度更高。
- **做法**：一块实体方块，表面贴一层薄壳；壳和实体之间有粘连。试：重力下的下垂、实体被拉伸时壳跟着走、对壳上一个顶点加外力、壳刚度乘 40。壳的厚度和网格逐步变，量每帧耗时，看稳定性。
- **输出**：试验代码（放 `spikes/`）；结论写进 05 和 10，把 11 的 A-30 更新。
- **验收**：
  - 壳不贴实体时，纯壳的挠度和理论值一致（误差 5% 以内；壳的理论值本身有近似）；
  - 粘连后壳跟着实体走，偏离随粘连刚度加大而趋近 0；
  - 报告每帧耗时和稳定性，并和 02 N-07 的暂定预算比较；明确写出结论，不行就按 ADR-26 重新评估求解器。
- **不做**：用实验室资产做试验；皮肤配准。
- **依赖**：无。
- **改动范围**：`spikes/`、`docs/05`、`docs/10`、`docs/11`。
