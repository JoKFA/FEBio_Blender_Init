# 09 路线图与任务

这份文档把第一阶段拆成几个里程碑，每个里程碑再拆成任务卡。**任务卡就是交给开发者（人或 AI 开发会话）的完整说明**：拿到一张卡，加上 [README](README.md) 里开发者要读的文档，就能开工。所有任务卡都按 [templates/task-card.md](templates/task-card.md) 的格式写。

## 1. 里程碑

```
M0 基础 ✅ ──► M1 原料就绪 ──► M2 物理段 ──► 【关：T-17、T-18 复核 FEBio】──► M3 landmark 段 ──► M4 对比与评审 ──► M5 界面与验收
                 │ 网格已导出         │ 先跑通再细化                                  │ 需要 Ziva 机器    │ 需要 Ziva 机器
```

**原则：先让真实资产从头到尾跑通一次，再逐项细化。** M2 先做一个粗糙但完整的第一版（T-06 第一版），缺的数据用标明来源的临时值，这样真正的问题（四面体质量、尺寸、稳定性）能尽早暴露。

| 里程碑 | 完成后能做到 | 依赖实验室 |
|---|---|---|
| M0 基础 ✅ | 仓库、环境、自动检查；FEBio 本机可用；结果能回放到 Blender | 否 |
| M1 原料就绪 | 实验室资产能完整导入成我们的场景描述 | 否：网格、权重和关节已经导出（ADR-18），只差 T-02 和 T-05 |
| M2 物理段 | 下颌带动嘴唇的物理过程能用 FEBio 算出来、通过合理性检查并回放 | 第一版不依赖；第二版需要单位、Ziva 设置、P-01 的认可 |
| **M3 之前的关**（ADR-26） | T-17（软粘软）和 T-18（壳皮肤贴实体）两个合成方块试验做完，每帧耗时和稳定性可接受；不行就重新评估求解器，不进入 M3 | 否 |
| M3 landmark 段 | 叠加 landmark 变形，得到最终的嘴唇形状 | **是**：运动轨迹（D2，Ziva 机器）；权重已有 |
| M4 对比与评审 | 和 Ziva 并排比较，研究员评审通过（[07](07-validation.md) 第 4 节） | **是**：参考结果（D3，Ziva 机器）、研究员评审 |
| M5 界面与验收 | 研究员能在 Blender 里独立完成全流程，实验室签字验收 | **是**：试用和验收 |

### T-01 取齐 Ziva 机器上的数据和实验室的回答 🟡（网格和权重已完成；范围已扩大，ADR-24）
- **目标**：拿到原型需要、但 `.mb` 文件里读不出来的全部数据。
- **为什么**：Ziva 默认值不知道，运动轨迹和参考结果都不在文件里（[03](03-asset.md) 第 7、8 节）。
- **已完成**：清单第 1、3 项。用实验室给的非 Ziva 版场景，在本机 Maya 上导出（ADR-18）。网格和 `.mb` 逐点核对过；权重和关节只有 Maya 自检，T-09 的精确对比才是它们的独立检查。
- **负责**：项目负责人，配一位熟悉 Facial Expression Automator 的研究员。
- **做法**：按 [12 导出清单](12-lab-export-checklist.md) 第二部分约 Ziva 机器，用 `tools/ziva_machine_export.py` 做第 2、4、5、7 项，以及 ADR-24 新增的第 8、9、10 项；第 6 项的问题当面问。**Ziva 机器不限一次**（ADR-24）：脚本现在还不支持第 8、9、10 项，**先做 T-19，去 Ziva 机器之前完成**。如果 Q5 问到的许可到期日比 T-19 的完成时间还近，由项目负责人决定先带现有脚本去一次，再按 T-19 补去。**不等 P-01 等设计决定，赶在 Ziva 许可到期前做。**
- **范围（ADR-24）**：除现有项目外，还要所有被 Ziva 解算的网格（每块组织和皮肤）的逐帧结果、2 到 3 条运动（含一条甩头）、目标姿态网格、实验室源码（粘连的生成、LBS 代理、过渡表和轨迹格式）。对应 [11](11-risks-and-questions.md) 的 D9、D10、D11。
- **输出**：`data/lab_export/` 下的全部文件，以及一份收货记录：每个文件对应清单的哪一项、收到的日期。
- **验收**：脚本最后打印 `ZIVA SESSION PASSED`。`session_report.json` 里：帧范围从 0 开始；Ziva 节点数大于 0；`motion_move` 大于 0（物理形状跟着下颌动了，说明 Ziva 真的解算了）；`frozen_frames` 为 0（中途没有停住）；`rest_offset` 小于 1（从静止形状开始，Ziva 确实重置了）；`jaw_degrees` 大于 1；`final_vs_physics` 大于 0；`ziva_maps`（导出的权重表个数）和 `ziva_meshes`（导出的网格份数）都大于 0，`notes` 里没有"网格和场景对不上"，或者研究员看过并写明原因。`gravity_sag` 很小时只给提示，要请研究员确认这个场景本来就是这样。清单每一项都打了勾，或者写明了为什么不需要。新增的第 8、9、10 项：每个被解算的网格都有逐帧文件，帧数等于运动帧数、顶点数等于 `ziva_meshes.json` 里记的；每条运动都有第 4、5、8 项；目标姿态网格和实验室源码已收到（脚本不导它们，由人拷走并记在收货记录里）。
- **注意**：参考结果（D3）必须在 Ziva 许可到期前拿到，过期就再也做不出来了。它不是合格线（ADR-17），但研究员评审要用。脚本只在普通 Maya 上排练过，现场第一次真正解算（A-28）。

### T-02 资产导入 🔴（等 T-05；导出文件已经有了）
- **目标**：`asrp import-asset <导出文件夹>`，把导出的文件变成我们的场景描述（`scene.json`）和一份检查报告。
- **为什么**：需求 R-01、R-02。
- **按照**：[04](04-architecture.md) 第 5.1 节；[03](03-asset.md) 第 10 节（单位、坐标轴）；ADR-04、ADR-07、ADR-18。
- **参考**：`tools/blender_import_preview.py` 已经在真实数据上走通了读取 OBJ、换算单位、转坐标轴、找下颌铰链这几步，可以照着做，但它是预览工具，不是产品模块。
- **输入**：`data/lab_export/` 下的文件（[12](12-lab-export-checklist.md) 第一部分）；T-05 定好的格式。属性清单以后才有。
- **没有属性清单时也要能导入**：Ziva 设置还没到时，对应参数的来源标成"我们定的"，检查报告里列出缺了什么；收到以后重新导入补上。这样 T-06 第一版不用等。
- **输出**：`src/asrp_core/asset/` 下的导入模块；`scene.json`、`meshes/`（毫米、Z 轴朝上）、检查报告；测试。
- **验收**：
  - 五个网格的顶点数和 [03](03-asset.md) 第 3 节一致（10,240 / 7,426 / 28,414 / 24,608 / 24,608）；
  - **OBJ 已经是场景坐标，不能再套 `world_matrix`**（ADR-18）。导入时检查 `mesh_report.json` 里 `obj_coordinates` 是 `scene`，否则报错；只做换单位和转坐标轴；
  - 导入前跑 `tools/check_lab_export.py`，导出文件和 `.mb` 逐点一致；
  - 导入后，每个顶点等于"场景坐标 × 换算系数，再按 `(x, y, z) → (x, -z, y)` 转换"，误差小于 0.001 mm；
  - 单位换算系数是设置项，不写死（Q3）；
  - 下颌尺寸按换算系数算出来是 150.0 mm（155.92 × 0.962）；
  - 检查报告列出单位换算系数、坐标轴转换方式，以及每个参数的来源。
- **不做**：四面体化（T-04）、生成 FEBio 输入（T-06）。
- **依赖**：T-05。
- **改动范围**：`src/asrp_core/asset/`、`cli.py`（加一条命令）、`tests/`。
- **规模**：中。

### T-03 从 .mb 读取粘连，算出嘴唇被拉着的区域 🟢
- **目标**：从完整版 `.mb`（v36）里读出粘连数据，算出 P-01 方案 A 要用的"嘴唇哪些区域挂到哪块骨头上"。
- **为什么**：粘连信息只在完整版里，非 Ziva 版已经删掉了（[03](03-asset.md) 第 12 节）。`.mb` 的格式没有公开文档，所以**这份数据在 T-06 第一版里算临时值**，等 Ziva 机器上的权重表（`ziva_maps.json`）和 zBuilder 导出到了再核对（ADR-07）。
- **按照**：`tools/mb_inventory.py` 文件开头记录的格式说明；`tools/asset_report.py` 里读粘连权重的代码。
- **要读出**：
  1. 和嘴唇相连的每个粘连的逐顶点权重（[03](03-asset.md) 第 6 节的表）。注意权重记在"出发方"的顶点上；
  2. **嘴唇表面被周围组织拉着的区域**：肌肉和皮肤是"出发方"的那些粘连，算出它们带权重的顶点离嘴唇表面最近的位置，落在哪些嘴唇顶点附近。现在有真实的三角面了，用 `data/lab_export/` 里的嘴唇网格算"离表面最近的点"。皮肤网格还在文件里；6 块肌肉的网格被删了，`.mb` 里 Ziva 存的副本（zGeo）只能读出顶点数和范围。Ziva 机器导出的 `ziva_meshes/`（[12](12-lab-export-checklist.md) 第 7 项）带面，到了以后用它；先查 `ziva_meshes.json` 的 `matrix_connected`，位置矩阵没保留的，用"带粘连权重的肌肉顶点应该贴在嘴唇表面"核对位置。
- **不用再读**：landmark 权重和关节位置，它们已经由 `tools/maya_export.py` 导出。
- **输出**：`tools/` 下的一个脚本（比如 `tools/mb_weights.py`），把以上数据写成 JSON；测试（用一个小的合成数据样本）；嘴唇上被拉着的顶点总数（不重复计数）和占比，写进 03 第 6 节。
- **验收**（不需要等实验室）：
  - 每个粘连的权重都在 0 到 1 之间，权重表长度等于出发方网格的顶点数；
  - 嘴唇上带粘连权重的顶点（嘴唇作为出发方）不重复计数为 733 个，和 `tools/asset_report.py` 一致。注意：这一条和 `asset_report.py` 用的是同一个解析器，**只能发现脚本写错，发现不了解析器本身的错**；
  - 把算出的区域在 Blender 里着色显示一次，人眼确认上唇、下唇、嘴角的分布说得通。
- **之后**：真正独立的检查，是收到 `ziva_maps.json` 和 zBuilder 导出以后逐项比对。
- **不做**：解析网格的面；把它变成产品模块。
- **依赖**：无。
- **改动范围**：`tools/`、`tests/`。
- **规模**：中。

### T-04 嘴唇四面体化试验（S2） 🟢
- **目标**：确认能把嘴唇表面网格变成质量合格的四面体网格，并选定工具。
- **为什么**：Ziva 自己做四面体化，我们得自己做。实验室的网格在静止状态下可能有互相穿插，有些工具遇到这种网格会直接失败（A-10）。为什么绕不过去、这一步是怎么来的，见 [13](13-explanations.md) E-02。
- **按照**：[05](05-ziva-to-febio.md) 第 1 节 zTet 一行。
- **做法**：比较至少两种四面体化工具在 Windows 上的安装难度、对"不完美网格"的容忍度、网格质量和速度。尺寸按 `tetSz` 26.37 换算成毫米，另外试粗一倍、细一倍两档。
- **输入**：真实的嘴唇网格 `data/lab_export/mesh_middleres_OrbicularisOris.obj`。已查过：封闭、只有一块，是一个环；还没查自身穿插（A-10）。
- **输出**：试验报告（写进 05 和 11）、一个最小的四面体化模块 `src/asrp_core/tetmesh.py`。
- **验收**：嘴唇网格能稳定生成四面体，没有被压扁、体积接近 0 的坏四面体；报告写明计算点数、四面体数、耗时；三档尺寸都有数据。
- **注意**：`tetSz` 26.37 是场景坐标下的尺寸，而嘴唇最薄的方向只有约 45.8，厚度方向大约只有两层四面体，可能太粗。试验时要看这对结果的影响。
- **不做**：生成 FEBio 输入。
- **依赖**：无。
- **改动范围**：`src/asrp_core/tetmesh.py`、`spikes/`、`pyproject.toml`（新增依赖）。
- **规模**：中。

### T-05 场景描述格式定稿和校验器 🟢
- **目标**：把 [04](04-architecture.md) 第 5.1 节的场景描述写成正式格式，并提供 `asrp check`。
- **为什么**：几乎所有后续任务（T-02、T-06、T-08）都通过这个文件交接，要先定下来。
- **按照**：04 第 5.1 节；单位规则 ADR-04。
- **怎么定格式**：磁盘上用 JSON 文件，最外层有一个 `format_version` 字段（从 `"asrp-scene/1"` 开始）；代码里用 Python 的 dataclass 描述每一部分，读入时完整校验。不另外引入 JSON Schema 等工具，除非有明确理由。
- **第一版必须能表达**：单位和换算记录，其中 `units.mm_per_scene_unit`（几何，暂定 0.962）和 `units.physics_length_scale`（k，默认 1.0，来源"我们定的"）是两个独立字段（ADR-22）；1 块软组织（四面体尺寸、材料、参数来源）；4 块骨头（运动方式只有"固定"和"给定"，给定时运动来自 `trajectory.json` 的每帧 4×4 刚体变换；铰链的关节名和枢轴是可选说明，ADR-21）；粘连（两端、逐顶点权重、刚度、类型）；landmark（静止位置、蒙皮权重，物理段可以不填）；求解设置（帧率、子步、阻尼、重力、分析类型）。
- **输出**：`src/asrp_core/scene.py`、`asrp check` 命令、示例文件（把 S1 的小模型写成场景描述）、测试。
- **验收**：
  - S1 的模型能完整写成场景描述，读回来内容不变；
  - 校验器至少能发现这几类错误：缺文件、单位缺失、粘连没有有效顶点、引用了不存在的物体、版本号不认识。每类都有测试，错误提示说人话；
  - 每个参数都有"来源"字段（实验室设置 / Ziva 默认值 / 我们定的）；
  - 两个单位字段缺一个、或"给定"的骨头没有对应的运动，校验器报错；`physics_length_scale` 不写时取 1.0 并标成"我们定的"。
- **不做**：从实验室文件导入（T-02）、生成 FEBio 输入（T-06）。
- **依赖**：无。
- **改动范围**：`src/asrp_core/scene.py`、`cli.py`、`tests/`。
- **规模**：小到中。

### T-06 FEBio 场景生成器（物理段） 🔴（第一版等 T-02、T-03、T-04、T-05）
- **目标**：把场景描述翻译成 FEBio 输入文件，跑出物理段结果。
- **为什么**：需求 R-03、R-04 的核心。
- **按照**：[05 Ziva 到 FEBio 的对应](05-ziva-to-febio.md)，包括第 5 节的全部坑；物理尺度 k 的做法见 05 第 2 节（ADR-22）。
- **分两步做**：
  - **第一版：先跑通**。依赖 T-02、T-03、T-04、T-05。实验室还没给的东西，先用临时值，并在场景描述里把来源标成"我们定的"：
    - 粘连先用硬绑定（S1 验证过的做法），挂法按 P-01 方案 A。挂哪些顶点，用 T-03 第 2 步算出的"被周围组织拉着的区域"。如果 T-03 读不出肌肉的坐标，就先用粗略的几何规则：按高度分上唇、下唇，上唇挂颅骨、下唇挂下颌，嘴角按距离分配。这条规则也标成临时值；
    - 材料先用常见的软组织参数；
    - 单位先按 A-09 的 0.962 mm，物理尺度 k 先取 1.0（来源"我们定的"，ADR-22）；
    - 没有轨迹（D2）时，用一条简单的下颌运动代替：第 0 到 14 帧下颌不动、只有重力（和实验室的流程一样），之后张开再合上。用铰链生成，再写成每帧刚体变换（ADR-21）；
    - **绑定强度做成参数**（ADR-27）：下唇绑到下颌上有多紧由参数决定，**第一版不要默认权重 1 硬绑整个下唇**。landmark 层不带下颌转动，物理段硬绑可能把张嘴位移算两遍（A-29）。第一版取一个中间值并标成临时值，拿到 Ziva 的只有物理的结果后，按下唇跟随比例（07 第 4.2 节）再定。
  - **第二版：换上真实数据**。T-07 的结论、实验室属性清单（[12](12-lab-export-checklist.md) 第 2 项）、Q1 和 Q3 的回答、P-01 的认可陆续到了以后，换掉对应的临时值重新跑。换数据的工作算在 T-12。
- **输出**：
  - 生成器模块和测试；
  - [07](07-validation.md) 第 3 节的合理性检查：写在 `src/asrp_core/plausibility.py`，接进 `asrp run`，结果写进运行报告；
  - 第一次完整的原型物理段运行。
- **验收**（第一版）：
  - 用有理论答案的简单方块验证拉伸和悬挂（[07](07-validation.md) 第 2 节）；
  - 嵌入的显示网格在没有变形时和原网格完全重合；

  - 运行报告列出每一个临时值和它的来源；
  - 重力方向和下颌驱动的检查保持通过。
- **不做**：landmark 层（T-09）、和 Ziva 对比（T-11）。
- **改动范围**：`src/asrp_core/febio.py`（扩展）、新的生成器模块、`src/asrp_core/plausibility.py`、`run.py`（接入检查）、`tests/`。

### T-07 粘连做法试验（S3） 🟢
- **目标**：在 [05](05-ziva-to-febio.md) 第 3 节的"硬绑定"和"弹簧"两种做法之间做出选择。
- **为什么**：粘连决定嘴唇怎么被拉住，做错了结果会差很多。
- **按照**：05 第 3 节；FEBio 手册（安装目录 `doc/FEBio_User_Manual.pdf`）：
  - 硬绑定：第 3.11.16 节的 `rigid` 边界条件，把一组计算点并入刚体；或者像 S1 那样让组织和刚体共用计算点；
  - 弹簧：第 3.6.7 节的 `DiscreteSet` 加第 3.16 节的 `linear spring`（刚度参数是 `E`）。弹簧的另一端需要一个计算点，再用 `rigid` 条件把这个点并入骨头。**一个弹簧材料只能有一个刚度**，所以"刚度 × 权重"要把权重分成几档，每档一种材料。
- **做法**：
  1. 一个几乎不变形的方块挂在 4 根弹簧上，加重力。理论答案是每根弹簧伸长 = 方块重量 ÷（4 × 刚度），用它检查弹簧和重力的写法对不对；
  2. 一个软方块分别用两种做法粘在刚体上，加重力和刚体转动，比较变形、稳定性、计算时间；弹簧刚度逐步加大时，结果应该趋近硬绑定；
  3. 试验权重小于 1 的情况；
  4. 把刚体整个固定（代替 S1 里"把一组计算点固定"的做法），确认颅骨可以这样处理。
- **输出**：试验代码（放 `spikes/`），结论写进 05 和 10。
- **验收**：第 1 步和理论值误差在 1% 以内；给出明确的选择和理由；如果选弹簧，给出刚度怎么取的规则（假设 A-23 要一起验证，或者标明待定）。
- **不做**：用实验室资产做试验。
- **依赖**：无。
- **改动范围**：`spikes/`、`docs/05`、`docs/10`。
- **规模**：小到中。

### T-17 软组织粘软组织试验（S4） 🟢
- **目标**：用合成方块试验，确认 FEBio 能做"软组织粘软组织"，并量每帧耗时和稳定性（ADR-26）。

### T-18 薄壳皮肤贴在实体上的试验（S5） 🟢
- **目标**：用合成方块试验，确认 FEBio 能做"薄壳皮肤贴在实体上，带粘连"，并量每帧耗时和稳定性（ADR-26）。
- **为什么**：论文的皮肤是布料层，用 Ziva 粘连挂在内部组织上（3.7、附录 I）；手指按压是对皮肤顶点直接加外力（附录 S），烧伤要把皮肤刚度乘 40（4.4.7）。第二阶段要做皮肤，FEBio 里要用专门算薄片的壳单元（P-01 方案 B 里已经提到难度更高）。
