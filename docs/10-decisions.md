# 10 决策记录

项目里做过的关键决定都记在这里。每条写清楚：**定了什么、为什么、放弃了什么**。以后有人问"为什么不用 X"，先查这里。

要推翻一条已定的决策，新增一条记录说明原因，并把旧的那条标记为"已被 ADR-xx 取代"，不要直接删改旧记录。

状态：✅ 已定；⏳ 待定（链接到 [11](11-risks-and-questions.md) 的待决问题）。

---

### ADR-01 物理计算用 FEBio ✅ 2026-10-27
- **决定**：用 FEBio 替换 Ziva。以后如果需要第二个求解器做交叉验证，首选 ArtiSynth。
- **原因**：FEBio 专为生物力学开发，有已发表的验证；源码开源（MIT 许可），每一步计算都能检查；输入输出都是文件，适合独立运行；自带刚体、动力学和多种软组织材料。
- **放弃了**：AdonisFX、Houdini Otis（闭源，没有生物力学方面的有效性声明，本质上和 Ziva 是同一类工具）；SOFA、PolyFEM（在 Windows 上安装风险高）；自己写有限元（验证工作量太大）。
- **附注**：官方安装包的许可只允许单机安装和内部使用，不允许再分发（已读安装附带的许可协议）。

### ADR-02 操作和显示用 Blender ✅ 2026-10-27
- **决定**：用 Blender 替换 Maya 作为操作界面。
- **原因**：免费开源，Python 接口完整，任何人都能装；Ziva 停售以后，Maya 对这个项目已经没有不可替代的价值。
- **放弃了**：继续用 Maya（许可费用，而且原来就是因为 Ziva 才绑定在 Maya 上）。
- **附注**：核心程序不依赖 Blender，以后需要的话可以再加 Maya 界面。

### ADR-03 求解在独立程序里运行，靠文件交换数据 ✅ 2026-10-27
- **决定**：Blender 插件只管界面，所有计算在独立的核心程序里，两者通过运行文件夹里的文件交换数据。
- **原因**：求解崩溃不影响 Blender；不开 Blender 也能批量运行，以后控制器也能直接调用；每一步的输入输出都能单独检查和重算。
- **证据**：`tools/check_blender_addon.py` 验证了 Blender → 子进程 → 核心程序 → 结果返回这条链路。

### ADR-04 单位统一为毫米、牛顿、兆帕、秒 ✅ 2026-10-27
- **决定**：导入时换算一次，之后全部用这一套。
- **原因**：生物力学常用的单位组合，数值大小合适；只换算一次，可以避免多处换算导致的错误。

### ADR-05 用动力学分析，不用准静态 ✅ 2026-10-28
- **决定**：按时间逐帧推进，考虑惯性。
- **原因**：实验室的流程有重力沉降（第 0 到 14 帧）和甩头时的惯性效果；Ziva 本身就是逐帧推进的。
- **取代**：最初计划用准静态（更简单、更稳定），看过论文和资产以后改了。

### ADR-06 原型直接用实验室资产 ✅ 2026-10-29
- **决定**：不自己建模下颌和嘴唇，直接用实验室提供的 Maya 场景。
- **原因**：结果能直接和实验室的 Ziva 结果对比；不需要额外的建模工作。

### ADR-07 产品用的数据一律来自实验室导出的开放格式；.mb 只用来核对 ✅ 2026-10-29
- **决定**：网格由实验室导出成 OBJ（或 FBX、Alembic），Ziva 设置导出成属性清单，蒙皮权重导出成权重文件。我们从 `.mb` 里读出的东西（结构、顶点坐标、权重）**只用来核对**这些导出，不作为产品的数据来源。
- **原因**：`.mb` 的格式没有公开文档。顶点坐标和大部分属性我们读出来了，但网格的"面"读不出来，还有 41 个数据块的格式没认出来。产品不能建立在猜出来的格式上，Maya 版本一换就可能失效。
- **更正**：本条的早期版本说"下颌有 3 个坏点、颅骨有 14,204 个坏点"，那是读错了顶点数（把坐标数值的个数当成了顶点数）造成的，按正确的读法没有坏点。
- **放弃了**：继续破解 `.mb` 的网格编码。

### ADR-08 landmark 作为物理计算之后的一层蒙皮变形 ✅（待实验室确认）2026-10-29
- **决定**：FEBio 只算物理（下颌带动、重力、粘连），landmark 的变形在物理结果之后单独叠加。
- **原因**：资产里的连接关系显示，Ziva 的输出进入 skinCluster7，再由 300 个 landmark 关节变形（[03](03-asset.md) 第 4 节）；论文公式 22 也是纯蒙皮公式。
- **风险**：如果实验室确认 landmark 实际上参与了物理计算，物理段的设计要改。所以把它列为问题 Q1，**在 T-06 开工前确认**。

### ADR-09 结果回放用"表面网格 + 点缓存" ✅ 2026-10-28
- **决定**：结果打包成表面网格加每帧点位置文件（PC2 格式），由 Blender 自带的 Mesh Cache 修改器播放。
- **原因**：Blender 原生支持，不需要每帧重建网格；数据保持毫米，只缩放显示。
- **证据**：`tools/check_playback.py`，逐帧误差小于 0.000001 mm。

### ADR-10 写入 FEBio 时重力反号 ✅ 2026-10-27
- **决定**：写进 FEBio 的重力（作用在整个体积上的力）取"物理方向的相反数"。
- **原因**：实测 FEBio 4.13 中，填 -9810 反而往上推，和按手册第 3.13.3 节公式推出的方向相反（[05](05-ziva-to-febio.md) 坑 1）。
- **守护**：S1 的"组织应该往下沉"检查，每次自动检查都会跑。

### ADR-11 FEBio 一律加 -noconfig 运行 ✅ 2026-10-27
- **原因**：避免每台电脑上的个人配置影响结果，保证可复现。

### ADR-12 以文档为唯一依据协作 ✅ 2026-10-29
- **决定**：这套文档是项目的唯一依据。改设计先改文档；任务通过任务卡分配；人和 AI 开发会话遵守同样的规范。
- **原因**：项目会有多人参与，大家需要一个共同的、可以查证的依据，而不是靠聊天记录。

### ADR-16 导入顺序固定为：先套变换，再换单位，再转坐标轴 ✅ 2026-10-29
- **决定**：每个网格先套用它自己在 Maya 里的变换得到场景坐标，再乘长度换算系数，最后从 Y 朝上转成 Z 朝上。
- **原因**：实验室的骨骼和嘴唇网格都带着放大 2.54 倍和旋转，场景里不同物体的放大倍数还不一样（[03](03-asset.md) 第 10 节）。论文的单位换算对应的是场景坐标（下颌 155.92 吻合）。顺序一错，尺寸和方向就全错，而且不会报错。
- **守护**：T-02 的验收检查"下颌在场景坐标下 z 方向为 155.92"。

### ADR-15 复现的标准是"坐标一致"，不是"文件一致" ✅ 2026-10-29
- **决定**：判断两次运行是否相同，比较解析出的每帧坐标（差别 ≤ 1×10⁻⁹ mm）和回放文件，不比较 FEBio 的原始日志。
- **原因**：实测同一模型跑两次，日志不同（里面有时间戳），坐标最大差 1×10⁻¹³ mm，回放文件逐位相同（11 的 A-24）。
