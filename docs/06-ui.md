# 06 界面设计

这份文档规定 Blender 里 ASRP 面板的样子和用法。它是界面开发（任务 T-13）的依据。面板上的每个按钮都对应 [04 系统设计](04-architecture.md) 第 7 节的一条命令。

线框图里的数字（误差、帧数、尺寸等）都只是示例，不是实测值。

**面板上的文字是英文**（项目负责人的决定，2026-11-12）。本文照常用中文写，引用面板上的字时用英文原样。下面第 3 节里还没做的小节（3.1、3.2、3.5）线框图上的中文标签只是设计时用的名字，做的时候要给它们配英文标签，现在不翻译。

## 1. 设计原则

1. **按研究员的工作顺序排列**：导入 → 检查 → 运行 → 回放 → 对比，从上到下。
2. **每一步都有明确的状态**：没开始、可以做、正在做、完成、出错。没完成前一步，后一步的按钮是灰的，并提示为什么。
3. **说人话的提示**：出错时说"嘴唇和下颌之间的连接没有任何顶点，请检查导出"，不说"AttachmentError: empty weight map"。
4. **不藏东西**：每个参数都显示它的来源（实验室 / Ziva 默认 / 我们定的），研究员能一眼看出哪些是"估的"。
5. **不卡界面**：计算在后台进行，期间可以转动视角、查看其他东西。

## 2. 面板位置

Blender 3D 视图右侧的侧边栏（按 N 键打开），标签名 **ASRP**。面板分成五个可以折叠的小节。

**现状（2026-11-12）**：面板（`blender_addon/asrp_blender/__init__.py`、`session.py`）有主面板 ASRP（按钮 Load result 和 Check backend）和三个小节：**Run**（3.3）、**Results**（3.4）、**Checks**（显示每次运行的五项合理性检查，3.4 末尾）。下面第 3 节的 3.1 资产、3.2 物理设置、3.5 对比**还没做**，对应的命令行有的已有（`asrp import-asset`、`check`），对比（`asrp compare`）命令还没有（T-11）。进度见 [09](09-roadmap-and-tasks.md) 的 T-13 卡。

面板是**先算完整个动作，再回放**，不是逐帧互动的（面板上固定写着 "Computes the whole motion, then replays it. Not frame-by-frame."）：逐帧接着算（每按一次键物理往前走一帧，实验室的"钢琴界面"要用）取决于试验 T-30，没有做。面板自己不算任何东西：它启动命令行，读命令行写出的文件。

### 3.3 运行（Run）

已做的样子：

```
┌ Run ─────────────────────────────────┐
│ Scene                                  │
│ [ scene.json 的路径 ]                    │
│ Motion (trajectory.json)               │
│ [ trajectory.json 的路径 ]               │
│ Runs folder                            │
│ [ 留空 = 项目里的 runs ]                  │
│ Run name                               │
│ [ 可不填 ]                              │
│ [ Run ]                               │
│                                       │
│ ████████████░░░░░░░░  Frame 23 / 51    │
│ 130 s elapsed                          │
│ [ Cancel ]                            │
└───────────────────────────────────────┘
```
（线框里的数字是示例。）

- **Run** 在后台启动 `asrp run`（子进程、一个读输出的线程、Blender 的定时器每 0.25 秒取一次输出），界面不卡。进度条和 "Frame N / M" 来自命令行打印的 `progress` 行，下面一行是已用秒数。
- **状态**：运行中显示进度（Preparing... 或 Frame N / M），结束后是 Complete、Failed、Cancelled、Could not start 之一。后三个不成功的结束状态都带 "No results were loaded."，并给出原因。
- **Cancel**：在运行文件夹里写一个名为 `cancel` 的文件（04 第 9 节）。运行文件夹要等命令行打印出 `run folder` 那一行才知道；在那之前点 Cancel，会记下来，知道文件夹的那一刻就写。
- **成功**：自动把这次运行加进 Results 列表（3.4）。运行完成但合理性检查有不通过的，照样加载，同时用红字提示 "A plausibility check failed (see Checks below). The results are loaded."；具体哪一项看 Checks。
- **完成但加载失败**：状态显示 "Complete, but the results could not be loaded"，并写出原因。
- **开始新运行时，列表里正显示的结果先被隐藏**（包括用 Load result 加载的），旧结果不会被当成这次运行的结果留在屏幕上（04 第 9 节）。
- **启动失败**：进程还没建起来就失败（比如找不到 `uv`，或运行文件夹建不了），显示 "Could not start" 和原因，并清掉上一次运行的结果状态。
- **取消来得太晚**：取消的请求到时运行已经算完，面板说明取消来得太晚，这是一个完整的结果，并把它加载。
- **`run COMPLETE` 之后退出码不是 0 也不是 1**（0 是完成，1 是有合理性检查不通过）：按失败处理，不加载。
- **一次运行进行时打开另一个 .blend**：运行继续被跟踪，完成后加载到此刻打开的那个文件的场景里。
- **运行进行时退出 Blender 或停用插件**：插件卸载时取消这次运行：写 `cancel`，最多等 3 秒，还没停就结束整个进程树（包括 FEBio）；运行文件夹还不知道时直接结束进程树。所以退出 Blender 最多会多等 3 秒。
- **点了 Cancel 但运行文件夹一直没出现**：等 10 秒后结束进程树，状态记为 Cancelled，面板不会一直停在取消中。

设计里有、还没做（设计名，做的时候配英文标签）：
- 运动下拉框（从 `data/lab_export/trajectories/` 列出轨迹文件并显示帧数和来源）：现在 "Motion (trajectory.json)" 是填文件路径；
- 失败时的"打开运行文件夹"按钮。

### 3.4 结果（Results）和检查（Checks）

已做的样子：

```
┌ Results ─────────────────────────────┐
│ run_A                                  │
│ [●] Physics only                  [x]  │
│ [ ] Final shape                   [x]  │
│ run_B                                  │
│ [ ] Final shape                   [x]  │
│ [ Load run folder ]                    │
└───────────────────────────────────────┘
┌ Checks ──────────────────────────────┐
│ Run: run_A                             │
│ (a) Motion completed            PASS   │
│ (b) Hard attachments follow bones PASS │
│ (b2) Spring anchors follow bodies PASS │
│ (c) Gravity sag                 FAIL   │
│     （失败的一项带说明，红色）             │
│ (d) Tet mesh valid            NOT RUN  │
│ Landmark layer: applied (……)           │
│ Surface (final): N flipped faces, ……   │
│ Settle: tissue moved X mm in the ……    │
│ ☐ Show every check's message           │
└───────────────────────────────────────┘
```
（线框里的名字和结果是示例；条目本身是 Show，右边的 x 是 Remove。）

- 列表按运行分组：每个加载过的运行文件夹先有一行小标题（运行名，只写一次），标题下面是它的版本行 "Physics only"；回放包带 landmark 层的最终版本时，再有一行 "Final shape"。运行按加载的先后排列。两种版本的区别见 [04](04-architecture.md) 第 2 节。
- **Load result**（主面板的老按钮）也走这个列表：它加载的物体同样遵守"同一时刻只显示一条"，开始新运行时同样被隐藏。
- **同一时刻只显示一条**（视口和渲染都只有它；Show 也会取消物体在视图层里被眼睛图标隐藏的状态），点一条就切换过去，并把时间轴设成它的帧数和帧率。Remove 把这一条从列表里移除并删掉它的物体。
- **Load run folder** 把以前的运行加进来；加载中途出错时，这次已经加进来的条目和物体全部撤回。
- 在视口里删掉了一条结果的物体，面板不再把它当成"正在显示"，列表里这一条标出 "(object deleted)"。
- **比较两种 AA 做法**就靠这个：把两次运行都加载进来，在 "Physics only"、A 的 "Final shape"、B 的 "Final shape" 之间切换。
- **Checks** 读正在显示的那一条所属运行的 `run_report.json`，列出五项各自是 PASS、FAIL 还是 NOT RUN（右对齐），失败和没跑的带说明。每项用面板里固定的短名，不用报告里的长名：(a) "Motion completed"、(b) "Hard attachments follow bones"、(b2) "Spring anchors follow bodies"、(c) "Gravity sag"、(d) "Tet mesh valid"；报告里出现不认识的检查键时，那一行显示报告自己的 `name`。勾上 "Show every check's message" 时，通过的检查也显示说明，并带上报告里的长名。之后是一行 Landmark layer 的情况（叠上了没有、移动了几个 landmark、最大平移多少毫米，或没叠上的原因）。报告读不了（文件不在，或形状不像运行报告）时，面板写出一句说明，不会出错。
- Landmark layer 下面还有两行**只是报告出来的数，不是检查**：`surface_health` 里最后一帧的表面情况（有最终版本就用最终版本，否则用 physics），写成 "Surface (final): N flipped faces, M edges < 0.5x, K edges > 2x"；`settled_shape.tissue_step_max_mm`，写成 "Settle: tissue moved X mm in the last settle frame"。`settled_shape.tissue_settled` 为 false 时，另有一行红字 "Tissue not settled at the settle frame"。旧报告没有这些键时，这几行都不出现。

设计里有、还没做（设计名，做的时候配英文标签）：
- 按运行名挑选的下拉框（现在是列表）；
- "显示"单选框里的"两者叠加"（现在一次只显示一条，没有叠加）；
- 单独的"加载"按钮和"用 Blender 时间轴播放"按钮（现在加载后自动设好时间轴，用 Blender 自己的播放键）。

**怎么检查过**：
- `tools/check_panel.py`（命令行下的 Blender，`tools/verify.py` 每次都跑）：用同一份会话代码、用循环代替定时器（Blender 的定时器在 `--background` 里不触发）。对真实的 `asrp run` 进程：一次完整的运行（进度、结果加进列表、切换、读五项检查，老的 Load result 加载的物体在同一个列表里）；启动不了的运行，以及进程建起来之前就失败的启动（旧的结果状态被清掉）；运行文件夹知道之前和之后的取消；运行文件夹还不知道时关闭会话，整个进程树都没了；运行中途加载另一个文件。对一个打印同样行的替身命令（测的是面板对输出的读法，不是真的失败的运行）：`run COMPLETE` 之后退出码 1（结果加载、失败的检查列出）和退出码 3（按失败处理）、来得太晚的取消、加载失败时的回滚。另外：行构造函数对残缺报告的处理、被删物体不算"显示"、插件里没有中日韩字符。
- `tools/panel_windowed_check.py`（带窗口的 Blender，要有显示器，**要手动跑，不在验证门里**）：真实嘴唇，只通过面板的操作和插件自己的定时器，2026-11-12 做过一次。两次运行（A、B）都完成并加载；在 physics only、A final shape、B final shape 之间切换，看到的形状不同（取一个下唇顶点在最后一帧的位置比较：A final 和 B final 差 14.60 mm，A final 和 physics 差 4.45 mm，B final 和 physics 差 10.46 mm）；第三次运行从操作里取消：退出码 2，列表没变，它的任何东西都没显示；运行中途打开另一个文件，运行完成后加载到新场景。**这些毫米数来自当时打印的一次输出，没有存进仓库。**
- `tools/panel_windowed_check.py --installed --quit-midrun`（命令在脚本开头的说明里）：按用户的方式安装并启用插件，运行中途让 Blender 退出，再手动用进程列表确认这次运行的进程树（含 FEBio）都没了。2026-11-12 手动做过一次（进程都没了，运行记为 cancelled），输出没有存档；这一步不在验证门里。
- 试验 `spikes/blender_background_run.py`（带窗口的 Blender 5.2.1）：运行期间定时器一直在响；从取消到进程退出用了约 2 秒。这些数也没有存档。

## 5. 以后的界面（第二阶段，现在不做）

实验室现在在 Maya 里用的"Facial Expression Automator"面板（见演示视频）有这些功能，以后在 Blender 里复刻时参考：

- 显示当前姿态和帧号；
- 音素按钮（如 AA、N、V）；
- FACS 动作单元下拉选择；
- 表情选择（开心、难过、惊讶）；
- 键盘"钢琴模式"：不同按键区对应音素、动作单元、表情，可以同时按两个键组合；
- 输入一句话，自动转成一串音素。

这些功能背后的两件事现在各有一个家：每按一次键物理往前走一帧，能不能做是 T-30（可行性试验），界面本身在 T-32；一串音素怎么按重叠拼成一条运动，也列在 T-32（02 第 4 节的对照表）。

第一阶段的面板设计要给这些功能留出位置：新增一个"表情控制"小节就行，不要改动前五个小节的结构。
