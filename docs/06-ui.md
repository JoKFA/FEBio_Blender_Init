# 06 界面设计

这份文档规定 Blender 里 ASRP 面板的样子和用法。它是界面开发（任务 T-13）的依据。面板上的每个按钮都对应 [04 系统设计](04-architecture.md) 第 7 节的一条命令。

线框图里的数字（误差、帧数、尺寸等）都只是示例，不是实测值。

## 1. 设计原则

1. **按研究员的工作顺序排列**：导入 → 检查 → 运行 → 回放 → 对比，从上到下。
2. **每一步都有明确的状态**：没开始、可以做、正在做、完成、出错。没完成前一步，后一步的按钮是灰的，并提示为什么。
3. **说人话的提示**：出错时说"嘴唇和下颌之间的连接没有任何顶点，请检查导出"，不说"AttachmentError: empty weight map"。
4. **不藏东西**：每个参数都显示它的来源（实验室 / Ziva 默认 / 我们定的），研究员能一眼看出哪些是"估的"。
5. **不卡界面**：计算在后台进行，期间可以转动视角、查看其他东西。

## 2. 面板位置

Blender 3D 视图右侧的侧边栏（按 N 键打开），标签名 **ASRP**。面板分成五个可以折叠的小节。

**现状（2026-11-12）**：面板（`blender_addon/asrp_blender/__init__.py`、`session.py`）有主面板 ASRP（"加载结果"和"检查后端"两个按钮）和三个小节：**运行**（3.3）、**结果**（3.4）、**检查**（显示每次运行的五项合理性检查，3.4 末尾）。下面第 3 节的 3.1 资产、3.2 物理设置、3.5 对比**还没做**，对应的命令行有的已有（`asrp import-asset`、`check`），对比（`asrp compare`）命令还没有（T-11）。进度见 [09](09-roadmap-and-tasks.md) 的 T-13 卡。

面板是**先算完整个动作，再回放**，不是逐帧互动的：逐帧接着算（每按一次键物理往前走一帧，实验室的"钢琴界面"要用）取决于试验 T-30，没有做。面板自己不算任何东西：它启动命令行，读命令行写出的文件。

## 3. 各小节

### 3.1 资产

```
┌ ① 资产 ──────────────────────────────┐
│ 导出文件夹： [ D:\lab_export\v36   ] 📁 │
│ [ 导入资产 ]                          │
│                                       │
│ ✔ 已导入：5 个网格，300 个 landmark     │
│   变换：导出时已套用，OBJ 是场景坐标     │
│   单位：1 单位 = 0.962 mm（设置项）     │
│   物理尺度 k = 0.67（真人大小，设置项）  │
│   坐标轴：Y 朝上 → Z 朝上（已转换）      │
│   [ 查看检查报告 ]                     │
└───────────────────────────────────────┘
```
- 导入后，场景里出现颅骨、下颌、牙齿、嘴唇和 landmark 小点，按角色着色：骨头灰白、软组织红色、landmark 黄色。
- 检查报告在 Blender 的文本编辑器里打开。

### 3.2 物理设置

```
┌ ② 物理设置 ───────────────────────────┐
│ 软组织                                 │
│   嘴唇（OOR）  四面体尺寸 25.4 mm  [查看] │
│     材料：neo-Hookean  E=? (Ziva 默认) ⚠ │
│ 骨头                                   │
│   下颌   跟随 jaw01 转动          [查看] │
│   颅骨   固定                     [查看] │
│   上牙/下牙  只显示                     │
│ 连接                                   │
│   嘴唇 → 下颌   76 个顶点         [查看] │
│   ……                                  │
│ 求解：动力学  30 帧/秒  子步 ?  阻尼 ?    │
│ [ 检查设置 ]   ✔ 没有发现问题            │
└───────────────────────────────────────┘
```
- [查看]：在 3D 视图里高亮对应物体；点连接时，用颜色显示每个顶点的权重。
- ⚠ 标出所有来源是"默认值"或"我们定的"、还没经过实验室确认的参数。
- 第一阶段**只读**，不能在面板上改参数；改参数要改场景描述文件。这样每次运行都有据可查。

### 3.3 运行

已做的样子：

```
┌ 运行 ────────────────────────────────┐
│ 场景：       [ scene.json 的路径 ]      │
│ 运动：       [ trajectory.json 的路径 ] │
│ 运行文件夹： [ 留空 = 项目里的 runs ]     │
│ 名称：       [ 可不填 ]                  │
│ [ 运行 ]                              │
│                                       │
│ ████████████░░░░░░░░  第 23 / 51 帧     │
│ 已用 130 秒                            │
│ [ 取消 ]                              │
└───────────────────────────────────────┘
```
（线框里的数字是示例。）

- **运行**在后台启动 `asrp run`（子进程、一个读输出的线程、Blender 的定时器每 0.25 秒取一次输出），界面不卡。进度条和"第 N / M 帧"来自命令行打印的 `progress` 行，下面一行显示已用秒数。
- **取消**：在运行文件夹里写一个名为 `cancel` 的文件（04 第 9 节）。运行文件夹要等命令行打印出 `run folder` 那一行才知道；在那之前点取消，会记下来，知道文件夹的那一刻就写。
- **成功**：自动把这次运行加载进"结果"列表（3.4）。运行完成但合理性检查有不通过的，照样加载，同时用红字提示"有合理性检查没有通过"，具体哪一项看"检查"小节。
- **失败、没有开始、被取消**：显示原因，**什么都不加载**。
- **开始一次新运行时，列表里正显示的结果先被隐藏**，旧结果不会被当成这次运行的结果留在屏幕上（04 第 9 节）。

设计里有、还没做：
- "运动"下拉框（从 `data/lab_export/trajectories/` 列出轨迹文件并显示帧数和来源）：现在是填文件路径；
- 失败时的"打开运行文件夹"按钮。

### 3.4 结果（回放）和检查

已做的样子：

```
┌ 结果 ────────────────────────────────┐
│ [●] run_A · 只有物理              [x]  │
│ [ ] run_A · 最终形状              [x]  │
│ [ ] run_B · 最终形状              [x]  │
│ [ 加载运行文件夹 ]                      │
└───────────────────────────────────────┘
┌ 检查 ────────────────────────────────┐
│ 运行：run_A                            │
│ (a) …: PASS                            │
│ (b) …: PASS                            │
│ (b2) …: PASS                           │
│ (c) …: FAIL    （失败的一项带说明，红色）  │
│ (d) …: NOT RUN                         │
│ landmark 层：已叠加（……）               │
│ ☐ 显示每项检查的说明                     │
└───────────────────────────────────────┘
```
（线框里的名字和结果是示例。）

- 列表里每个加载过的运行文件夹有一条"<运行名> · 只有物理"；运行的回放包带 landmark 层的最终版本时，再有一条"<运行名> · 最终形状"。"只有物理"和"最终形状"的区别见 [04](04-architecture.md) 第 2 节。
- **同一时刻只显示一条**（视口和渲染都只有它），点一条就切换过去，并把时间轴设成它的帧数和帧率。右边的 x 把这一条从列表里移除并删掉它的物体。
- "加载运行文件夹"把以前的运行加进来。
- **比较两种 AA 做法**就靠这个：把两次运行都加载进来，在"只有物理""A 最终形状""B 最终形状"之间切换。
- **检查**小节读正在显示的那一条所属运行的 `run_report.json`，列出 (a)(b)(b2)(c)(d) 五项各自是 PASS、FAIL 还是 NOT RUN，失败和没跑的带说明，另有一行 landmark 层的情况（叠上了没有、移动了几个 landmark、最大平移多少毫米，或没叠上的原因）。文件读不到时，明说读不到。

设计里有、还没做：
- 按运行名挑选的下拉框（现在是列表）；
- "显示"单选框里的"两者叠加"（现在只有一次显示一条，没有叠加）；
- 单独的"加载"按钮和"用 Blender 时间轴播放"按钮（现在加载后自动设好时间轴，用 Blender 自己的播放键）。

**怎么检查过**：
- `tools/check_panel.py`（命令行下的 Blender，`tools/verify.py` 每次都跑）：用同一份会话代码、用循环代替定时器（Blender 的定时器在 `--background` 里不触发），对真实的 `asrp run` 进程跑四种情形：一次完整的运行（两条结果加进列表、来回切换）；启动不了的运行（什么都没加进列表，之前显示的结果被隐藏了）；被取消的运行（退出码 2、没有 `playback.json`、什么都没加进列表）；运行文件夹还不知道时就要求取消。
- `tools/panel_windowed_check.py`（带窗口的 Blender，要有显示器，**要手动跑，不在验证门里**）：真实嘴唇，只通过面板的操作和插件自己的定时器，2026-11-12 做过一次。两次运行（A、B）都完成并加载；在"只有物理""A 最终形状""B 最终形状"之间切换，看到的形状不同（取一个下唇顶点在最后一帧的位置比较，A 最终和 B 最终差 14.60 mm，A 最终和只有物理差 4.45 mm，B 最终和只有物理差 10.46 mm）；第三次运行从操作里取消：退出码 2，列表没变，它的任何东西都没显示。**这些毫米数来自当时打印的一次输出，没有存进仓库。**
- 试验 `spikes/blender_background_run.py`（带窗口的 Blender 5.2.1）：运行期间定时器一直在响；从取消到进程退出用了约 2 秒。这些数也没有存档。

### 3.5 对比

```
┌ ⑤ 和 Ziva 对比 ───────────────────────┐
│ Ziva 参考： [ ziva_neutral_to_AA ▾ ]   │
│ [ 对比 ]                              │
│                                       │
│ 平均差别 0.31 mm  最大 1.8 mm           │
│ 95% 顶点差别 < 0.9 mm（只作参考）        │
│ 显示： ☑ 差别热力图   ☐ Ziva 结果（半透明）│
│ [ 打开对比报告 ]  [ 写评审 ]             │
└───────────────────────────────────────┘
```
- 热力图：蓝色表示差别小，红色表示差别大；颜色条标出毫米数。
- 不显示"合格 / 不合格"：第一阶段不设数值合格线（ADR-17）。
- "写评审"打开 [07](07-validation.md) 第 4.4 节的评审表，填完存进这次运行的文件夹（`review.md`）。

## 4. 状态栏和提示

- 面板最上方一行显示环境状态：FEBio ✔、单位换算 ✔ 或 ⚠。点击可以展开（已经实现的"检查后端"按钮就在这里）。
- 所有长时间的操作都显示进度，并且可以取消。
- 所有提示用中文；技术细节（FEBio 原文）收在"详细信息"里，默认折叠。

## 5. 以后的界面（第二阶段，现在不做）

实验室现在在 Maya 里用的"Facial Expression Automator"面板（见演示视频）有这些功能，以后在 Blender 里复刻时参考：

- 显示当前姿态和帧号；
- 音素按钮（如 AA、N、V）；
- FACS 动作单元下拉选择；
- 表情选择（开心、难过、惊讶）；
- 键盘"钢琴模式"：不同按键区对应音素、动作单元、表情，可以同时按两个键组合；
- 输入一句话，自动转成一串音素。

这些功能背后的两件事现在各有一个家：每按一次键物理往前走一帧，能不能做是 T-30（可行性试验），界面本身在 T-32；一串音素怎么按重叠拼成一条运动，也列在 T-32（02 第 4 节的对照表）。

第一阶段的面板设计要给这些功能留出位置：新增一个"表情控制"小节就行，不要改动前五个小节的结构。
