## 2. 这个文件是什么

它是实验室**完整面部 Ziva 场景的精简版**。从文件名（"dev proxy jaw oor"，即"开发用的下颌 + 嘴唇代理场景"）和内容来看，实验室删掉了大部分肌肉的网格，只保留了下颌和嘴唇相关的部分。

但是 Ziva 自己的设置**大多还留在文件里**：

| Ziva 设置 | 数量 | 是什么 |
|---|---|---|
| zTissue | 41 | 软组织（会变形的部分） |
| zBone | 10 | 骨头（不变形，只跟着动） |
| zCloth | 2 | 布料式的薄层，其中一个是皮肤 |
| zAttachment | 140 | 两样东西之间的"粘连" |
| zMaterial | 43 | 材料参数 |
| zTet | 41 | 四面体网格的设置 |
| zFiber | 18 | 肌肉纤维方向（主动收缩用） |
| zEmbedder | 1 | 把精细的显示网格"嵌"进粗的计算网格 |

41 个软组织里，有 34 个的原始网格已经被删掉了，但它们和求解器之间的连接还在。这一点很重要，见第 6 节和问题 Q7。

## 3. 原型要用的部分

顶点数和尺寸取的是**静止形状**，也就是 Maya 里名字以 `ShapeOrig` 结尾的那份网格，它是 Ziva 和蒙皮的输入。

尺寸有两种说法，一定要分清：
- **物体坐标**：网格自己记录的坐标；
- **场景坐标**（也叫世界坐标）：网格放进场景以后的坐标。五个网格都带着同一个"变换"：**放大 2.54 倍**，绕 X 轴转 -90°、绕 Z 轴转 180°，再整体下移约 75.4。Ziva 读的是场景坐标。

| 原型里的名字 | Maya 里的网格 | 在物理里的角色 | 顶点数 | 场景坐标下的尺寸（x / y / z，单位见第 10 节） |
|---|---|---|---|---|
| 嘴唇肌肉（口轮匝肌，简称 OOR） | `middleres_OrbicularisOris` | 软组织 zTissue1，四面体尺寸 26.37 | 10,240 | 92.3 / 75.2 / 45.8 |
| 下颌 | `middleres_Jaw` | 骨头 zBone1，由下颌关节 `jaw01` 带动 | 7,426 | 196.8 / 146.5 / **155.9** |
| 颅骨 | `middleres_skull` | 骨头 zBone2 | 28,414 | 225.2 / 252.7 / 311.0 |
| 上牙 | `middleres_TeethUp` | 骨头 zBone3，**只用于显示**（和嘴唇之间没有粘连，碰撞也是关的） | 24,608 | 86.8 / 30.5 / 78.5 |
| 下牙 | `middleres_TeethDown` | 骨头 zBone4，跟着下颌动，**只用于显示** | 24,608 | 80.2 / 23.4 / 70.1 |
| 嘴唇控制点 | `oor_01` … `oor_300` | 300 个 landmark 关节 | — | — |

两处交叉核对：
- 嘴唇的顶点数 10,240，和 Ziva 嘴唇四面体设置（zTet1）里逐顶点权重表的长度完全一致；
- 下颌在场景坐标下 z 方向的尺寸是 **155.92**，和论文附录 V 里"下颌宽 155.92 个单位"完全一致。说明论文的单位换算，量的就是这个模型的场景坐标（见第 10 节）。

物体坐标下的尺寸（变换之前）也由第 9 节的命令打印出来，比如下颌是 77.5 / 61.4 / 57.7。

文件里还有一些原型用不到的东西：眼周肌肉、两个圆球（可能是眼球）、手（论文里手指按压实验用的）、皮肤布料、灯光和摄像机。

## 4. 运动是怎么传递的

从节点之间的连接关系，可以完整地还原出实验室场景里运动的传递路线：

```
① 下颌关节 jaw01 转动
      │ 蒙皮（skinCluster1、skinCluster2）
      ▼
② 下颌骨和下牙跟着转（Ziva 骨头 zBone1、zBone4 读取它们的位置）
      │ 粘连（attachment）
      ▼
③ Ziva 计算嘴唇软组织的变形：重力、惯性、被下颌和周围组织拉扯
      │ zEmbedder 输出
      ▼
④ 再叠加 300 个 landmark 关节的蒙皮变形（skinCluster7）
      │
      ▼
⑤ 最终看到的嘴唇形状
```

**关键结论：landmark 不参与物理计算，而是在物理结果上再叠一层变形（第④步）。** 这和论文公式 22 的写法一致。对我们来说，FEBio 只需要算第③步；第④步是一个独立的、纯几何的计算。

这是从连接关系推断出来的，需要实验室一句话确认，见 [11](11-risks-and-questions.md) 的 Q1。

## 6. 嘴唇被什么固定住（头号设计问题的来源）

嘴唇在 Ziva 里不是"挂"在骨头上，而是被周围很多东西一起拉着。

先说明一个读表要注意的地方：每个粘连有"出发方"和"目标方"，**权重表记在出发方的顶点上**。出发方的这些顶点会被拉向目标方表面上离它最近的位置。所以下表分成两类：

| 嘴唇连到 | 方向 | 粘连个数 | 权重大于 0 的顶点 |
|---|---|---|---|
| 颅骨 | 嘴唇 → 颅骨 | 1 | **0 个嘴唇顶点（不起作用）** |
| 下颌 | 嘴唇 → 下颌 | 1 | 76 个嘴唇顶点 |
| 两侧口角（modiolus，嘴角处几块肌肉汇合的地方，两块小组织） | 嘴唇 → 口角 | 2 | 348、309 个嘴唇顶点 |
| 周围 6 块肌肉（网格已被删掉） | 肌肉 → 嘴唇 | 6 | 每块 32 到 52 个**肌肉的**顶点，粘在嘴唇表面上 |
| 皮肤 | 皮肤 → 嘴唇 | 9 | 每个 36 到 516 个、合计 2,185 个**皮肤的**顶点，粘在嘴唇表面上 |

嘴唇自己的顶点里，带有粘连权重的一共 **733 个**（不重复计数），占 10,240 个的 7%。肌肉和皮肤粘在嘴唇表面的**哪些位置**，文件里没有直接记录，要用"离得最近的点"另外算出来（任务 T-03）。

**这意味着：** 原型如果只保留"嘴唇 + 骨头"，嘴唇只剩下颌上的 76 个顶点挂着，在重力下的表现会和 Ziva 完全不同，对比就失去了意义。怎么处理需要你和实验室决定，选项和推荐见 [11](11-risks-and-questions.md) 的 P-01。

## 7. landmark 和运动轨迹

- 300 个 `oor_NN` landmark 都在文件里，挂在 `joint_oor` 下面；
- 文件里有 12,134 条动画曲线：12,120 条各有两个关键帧，分别在**第 0 帧和第 14 帧**；另外 14 条只有一个关键帧，在第 15 帧；
- **所有曲线的数值都不随时间变化。** 也就是说，文件里只有 landmark 和关节的**静止位置**，没有运动；
- 论文附录写的是第 0 到 14 帧留给重力沉降，和第 14 帧这个关键帧对得上；
- 演示视频的日志显示，运动轨迹是运行时从实验室网络盘上的数据文件读进来的。**所以轨迹要另外向实验室要**（D2）。

## 9. 怎么复现本文的数字

```bash
uv run python tools/mb_inventory.py "assets/v36 dev_proxy_jaw_oor V3 more aggressive delete done.mb" data/asset_inventory.json
uv run python tools/asset_report.py data/asset_inventory.json
```

第一条命令把整个场景读成一份清单，约 40 MB，存在 `data/` 目录，太大而且能重新生成，所以不提交；第二条打印本文用到的全部事实。两个工具都只用于分析，不是产品代码，也不需要安装 Maya。

## 10. 单位和坐标轴（导入时必须处理）

**先套变换，再换单位，再转坐标轴。** 顺序固定，不能省：

1. **套用每个网格自己的变换**（放大 2.54 倍、旋转、平移），得到场景坐标。**这一步现在由 `tools/maya_export.py` 完成，导出的 OBJ 已经是场景坐标，导入时不能再套一次**（ADR-18）。每个网格的变换矩阵仍然写在 `mesh_report.json` 里，用来和 `.mb` 核对。场景里不同物体的放大倍数并不一样：解剖结构是 2.54，皮肤约 1.185，手约 6.28。所以**绝不能假设"所有东西同一个比例"**。
2. **换算长度单位**。文件标的是厘米，但论文附录 V 说 1 个单位 ≈ 0.962 毫米。它量的是"下颌宽 155.92 个单位，对应作者自己的 15 厘米"，而 155.92 正好是这个下颌在**场景坐标**下 z 方向的尺寸（第 3 节）。注意 z 在这个场景里是前后方向，左右方向是 196.8，所以论文说的"宽"和这里的方向不一样，要在 Q3 里一起确认。所以 0.962 mm 对应的是场景坐标的单位。
   - ⚠️ 但按这个换算，颅骨左右约 217 mm、前后约 299 mm，比一般成年人（宽约 140–150 mm）大约 1.5 倍，模型可能整体偏大。这会直接影响重力和质量的效果。**实验室确认之前，换算系数做成设置项，不写死**（Q3）。
3. **转坐标轴**：场景是 Y 轴朝上，脸朝 -Z 方向（已从场景确认，Q9）；Blender 和我们的计算是 Z 轴朝上。换算公式是 `(x, y, z) → (x, -z, y)`，转完以后脸朝 +Y 方向，写进检查报告。这是一次旋转，不是镜像，左右不会对调。

另外，**Ziva 求解器的缩放是 100**，它对单位的影响要请实验室说明（Q3）。

## 11. 资产使用规则

- 实验室的原始 `.mb` 只放在 `assets/`，**绝不提交**；
- 导出和派生的文件放在 `data/`。`data/lab_export/`、`data/preview/`、`data/briefing/` 提交到私有仓库，其余不提交（ADR-19）。这些文件含有完整的网格和权重，等于资产的另一种格式；
- 除了这个私有仓库，不发到任何网盘、聊天软件或公开位置，除非实验室书面同意；
- 文档里可以引用节点名和数字，不能把网格、贴图或渲染截图贴到公开场合；
- 论文还在审稿，内容和图表不对外引用。


这个预览只转骨头，嘴唇不会跟着动。**让嘴唇跟着动，正是 FEBio 要做的事。**
