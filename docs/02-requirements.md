# 02 需求

给谁看：项目负责人、开发者与实验室成员。
读完能知道：ASRP 的替代目标、要满足的产品能力、不可妥协的通用约束（`N-01`–`N-07`），以及实验室论文中每项用法如何映射到我们的系统。
架构实现见 [architecture/README.md](architecture/README.md)，参数速查见 [00](00-current-settings.md)，进度与顺序见 [09](09-roadmap-and-tasks.md)。

## 1. 谁会用

| 使用者 | 核心动作 | 背景 |
|---|---|---|
| **实验室研究员** | 打开已有或新建的面部场景，运行单段或连续运动，回放两层结果并与 Ziva 并排评审 | 熟悉解剖、表情与 Maya/Ziva，不一定会写代码 |
| **控制器研究者** | 在实验室训练代码里进程内调用 `asrp_query` 读取嘴唇、两眼、额肌与下颌形状 | 熟悉 Python 与控制算法 |
| **开发者（含 AI 会话）** | 按独立任务卡实现核心、验证与宿主接口 | 熟悉编程，不一定懂解剖或有限元 |

## 2. 替代目标（ADR-45，项目负责人 2026-11-16 定）

1. **先打稳可长期演进的地基**：地基 = 在实验室**原本**用 Ziva 的方式下真正替代物理层，且核心能一路长下去，不必每加一项能力就重写核心。
2. **以实验室自己的实验为根本验收标准**：产品要让实验室能继续做原本的实验，而不把 Ziva 数值当硬合格线（[ADR-17](decisions/ADR-17.md)）；比 Ziva 更好的进阶特性（肌电对照、渲染出片、开源或商用扩展）排在地基打稳之后。
3. **两层分明、口径如实**：能量化比对的是物理层以及叠加 landmark 层后的最终形状（美术目标姿态本身不作数值合格线）。
4. **宿主开放**：优先 Blender（开源可控），Maya 保留为可选适配宿主（经同一核心 CLI/Python 接口对接）；除资产迁移外，物理层、管线和实验室源码对接必须在开发过程中证实可落地。

## 3. 产品能力需求

### 3.1 基础能力（`R-01`–`R-06`，单嘴唇原型已跑通，地基向多物体扩展）

| 编号 | 能力 | 验收要点 |
|---|---|---|
| **R-01** | 打开场景资产 | 模型与 300 个（地基扩展至 4 组 1,200 个）landmark 位置、大小与 Maya 一致；单位统一为毫米；产出含顶点数、换算系数和缺项的导入报告/台账 |
| **R-02** | 检查物理设置 | 列出软组织、骨头、皮肤与粘连边并支持视口高亮；每参数标明来源（实验室设置 / Ziva 默认值 / 我们定的）；提供通俗易懂的预检 |
| **R-03** | 后台运行仿真 | 后台计算不卡界面、能看进度、能取消；失败给出人话原因且不残余旧结果；每次运行/每段留完整可重算档案并自动跑合理性检查 |
| **R-04** | 逐帧回放 | 播放与求解输出逐帧一致（误差 `< 0.001 mm`）、`30 帧/秒`；支持切换 `physics`（纯物理）与 `final`（物理 + 已验证显示层） |
| **R-05** | 与 Ziva 并排对比 | 物理层与最终形状分开报每帧平均/P95/最大毫米差、热力图与双物体并排播放；附两项不依赖 Ziva 的参考指标（到目标姿态距离、下唇跟随比例）；由研究员按 [07](07-validation.md) 评审，**不设对 Ziva 数值合格线** |
| **R-06** | 复现运行 | 记录全部输入指纹（哈希值）、软件版本与参数；(a) 同环境同输入及拷贝目录重跑坐标差 `≤ 1×10⁻⁹ mm`（4 线程），`--threads 1` 逐位相同；(b) 跨 Windows 电脑重跑容差先量再定（[T-14](tasks/T-14.md)）；细四面体网格离线生成一次锁哈希（[ADR-20](decisions/ADR-20.md)） |

### 3.2 地基与长期能力（2026-11-24 收敛及留位）

- **多组织、两层皮肤与长间距粘连**：承接完整演示场景（41 组织 / 2 皮肤 / 10 骨 / 140 条含渐变权重与重叠顶点的长间距粘连边）及不带皮肤的训练族场景，同时保留旧嘴唇 `legacy-v1` 兼容。
- **连续段推进与会话管理**：支持从任意已提交状态续算、分叉、失败隔离、删缓存重放与回中性（承接钢琴界面连续按键）。
- **独立训练查询包（`asrp_query`）**：Python 3.9 进程内一次载入静态数据反复查询四组 landmark 网格（嘴唇、左眼、右眼、额肌）加下颌，默认静止基底，避免每步起子进程。
- **支持从零搭建全新模型**：Ziva 停售之后新模型不再来自 Maya/Ziva，自有场景版本（`asrp-scene/2`）才是长期核心；研究员可在 Blender 里直接标角色、建粘连并发布新场景版本（[T-39](tasks/T-39.md)）。
- **长期留位**：可选第二个求解器（如 ArtiSynth）作交叉验证、主动肌肉纤维输入与每组织应变能诊断（延至地基之后，[ADR-33](decisions/ADR-33.md)）、Maya 可选宿主、进阶肌电/渲染。

## 4. 通用硬约束（无论哪一阶段都必须满足）

| 编号 | 约束 | 原因 |
|---|---|---|
| **N-01** | 内部单位统一为 **毫米、牛顿、兆帕、秒（`mm、N、MPa、s`）**，只在导入时换算一次 | 单位错一位重力和刚度差十倍且不报错 |
| **N-02** | 求解在 **Blender 之外**的独立核心程序里运行 | 求解崩溃不拖垮界面，支持无界面批处理 |
| **N-03** | 任何结果均可追溯到产生它的输入与设置 | 论文复现与审稿需要 |
| **N-04** | 只在 **Windows 11** 上保证可用（当前阶段） | 开发与实验室主力环境均为 Windows |
| **N-05** | **不联网**也能用（FEBio 启动自带匿名使用统计除外） | 实验室数据不外传 |
| **N-06** | 原始 `.mb`、未发表论文、录像与实验室源码绝不进仓库；派生导出文件仅放私有仓库（[ADR-19](decisions/ADR-19.md)） | 商业模型许可与审稿保密 |
| **N-07** | **计算时间目标**：单嘴唇一段 `50 帧` 运动在 `10 分钟` 以内（已远达标）；全脸暂定目标不慢于 Ziva 整张脸实测（求解日志每步 `1.47–1.60 s`） | 正向推进与演示可用（详情见下） |

**N-07 速度口径说明**：
- 实验室 Ziva 实测（16 逻辑核机器，Maya 设 16 线程，Ziva 实际线程未量 🔍，[E-15](archive/explanations/E-15.md)）：求解日志整张脸（41 组织）每步平均 `1.47–1.60 s`（单步有 `>3 s`），只留嘴唇最后 46 行平均 `0.0095 s`；含写文件导出另算（整张脸 `2.55 s/帧`、只留嘴唇 `1.03 s/帧`），两类数不混用；“1.5–1.75 s/帧”与“696 步 1.65 s”无原始日志可复算 🔍。
- 我方默认 4 线程（本机 51 帧细网格 1/4/8/16 线程实测 `56.2 / 26.8 / 29.7 / 38.6 s`），跨机器跨线程只能看量级；现行具体耗时只记在 [15](15-prototype.md) 第 3 节。
- 全脸是否要求交互速度待问实验室 [Q12](11-risks-and-questions.md)；此预算针对正向推进，训练不推进物理（[ADR-30](decisions/ADR-30.md)）。
- 按 Ziva 的四面体尺寸估的整脸规模，和由此推的每步耗时，见 [E-22](explanations/E-22.md)“和 Ziva 比速度”一节。
