# 02 需求

给谁看：开发者和实验室负责人。读完能知道：我们做的东西要能干什么、怎样才算做到、哪些是第二阶段。怎么做不在这里，见 [04 系统设计](04-architecture.md)；做到哪了只看 [09](09-roadmap-and-tasks.md)。

## 1. 谁会用

| 使用者 | 他们要做的事 | 他们熟悉什么 |
|---|---|---|
| **实验室研究员** | 在 Blender 里打开模型，跑一段运动，看结果，和 Ziva 的结果并排比较，判断能不能用于研究 | 解剖、表情、Maya 和 Ziva 的操作；不一定会写代码 |
| **控制器研究者** | 用实验室自己的训练代码调用我们给的嘴唇形状函数（T-31） | Python、论文里的控制算法 |
| **开发者** | 按任务卡（在 [09](09-roadmap-and-tasks.md)）实现功能 | 编程；不一定懂解剖或有限元 |

## 2. 第一阶段（v0.1 原型）要支持的场景

每个场景后面的"做到了的标准"是验收时逐条检查的内容。编号（R-xx）会在 [09](09-roadmap-and-tasks.md) 的任务卡里引用。

### R-01 打开实验室资产
研究员在 Blender 里一键导入实验室的下颌原型资产：颅骨、下颌、上下牙、嘴唇肌肉，以及 300 个嘴唇控制点（landmark）。

做到了的标准：
- 五个网格都出现在场景里，位置、大小和在 Maya 里看到的一致（用同一视角截图对比）；
- 300 个 landmark 显示为小点，位置和 Maya 里一致；
- 单位已经换算成毫米，界面上能看到这一点；
- 导入后自动生成一份检查报告：网格顶点数、landmark 数量、单位换算系数、发现的问题。

### R-02 检查物理设置
研究员能看到每样东西在物理计算里扮演什么角色：哪个是软组织、哪个是骨头、它们怎么连着、用什么材料参数。

做到了的标准：
- 面板上列出所有软组织、骨头和连接（attachment），每项都能点选并在 3D 视图里高亮；
- 每个参数都标明来源：来自实验室的 Ziva 设置、来自 Ziva 默认值，还是我们自己定的；
- 有一个"检查"按钮，能发现明显错误（比如单位不对、连接没有任何顶点），并用通俗的话说明问题出在哪。

### R-03 运行一段运动
研究员选一条运动轨迹（比如"中性 → AA 音"），点 Run，FEBio 在后台计算。

做到了的标准：
- 运行期间 Blender 不卡死，能看到进度（第几帧/共几帧），能取消；
- 计算失败时给出看得懂的原因，不显示上一次的旧结果；
- 每次运行都在单独的文件夹里留下全部输入、输出和日志，事后能检查、能重算；
- 每次运行自动做合理性检查（[07](07-validation.md) 第 3 节），不通过的项在报告和面板上标出来。

### R-04 回放结果
运行结束后，在 Blender 的时间轴上逐帧播放嘴唇的变形。

做到了的标准：
- 播放的形状和 FEBio 算出的结果逐帧一致（误差小于 0.001 mm）；
- 帧率和 Ziva 一致（30 帧/秒）；
- 能同时显示"只有物理"和"物理 + landmark 变形"两个版本，方便分析。

### R-05 和 Ziva 并排比较
把同一段运动在 Ziva 下的结果导入进来，和 FEBio 的结果并排比较，供研究员评审。目标是让实验室能继续做研究，不是复刻 Ziva，所以**不设数值合格线**（ADR-17）。

Ziva 的参考结果已经有了：2026-11-12 在实验室的 Ziva 机器上，用实验室真实的中性到 AA 运动算出[蒙皮前和蒙皮后](glossary.md)的嘴唇，整张脸一次、只留嘴唇一次，还有 Ziva 的全部设置（[13](13-explanations.md) E-11）。参考数据有什么、缺什么，比什么和什么，见 [07](07-validation.md) 第 4.1、4.2 节。

做到了的标准：
- 输出一份对比报告：每帧的平均差别、最大差别、95% 顶点的差别（单位毫米），只作参考；物理段（蒙皮前）和最终形状分开报告；
- 在 Blender 里用颜色显示每个顶点的差别大小（热力图），并且能把 Ziva 的结果作为第二个物体同时播放；
- 研究员按 [07](07-validation.md) 第 4.4 节的问题评审，没有"不能接受"的项；
- 报告里还有两个不依赖 Ziva 的指标（ADR-25，口径见 [07](07-validation.md) 第 4.2 节）：**最终形状到美术目标姿态的距离**（实验室论文的指标，只报告给实验室，不是我们的验收线），以及物理段的**下唇跟随比例**（Ziva 和 FEBio 各报一个）。

### R-06 复现别人的运行
另一个人拿到某次运行的文件夹，能得到相同的结果。分两层：(a) 同环境，(b) 跨环境。

做到了的标准：
- 运行文件夹里记录了所有输入文件的指纹（哈希值）、软件版本和全部参数；
- **(a) 同环境复现**：同一台机器，用同一份输入重跑，每帧每个点的坐标差不超过 1×10⁻⁹ mm（默认 4 线程；实测最多差 1×10⁻¹⁰ mm，ADR-38）；需要回放文件逐位相同时用 `--threads 1`（单线程重复运行的差别约为 1×10⁻¹³ mm，见 11 的 A-24）；把运行文件夹拷到另一个目录，只用它自己的文件重跑，每帧坐标也在这个范围内（能发现对绝对路径的依赖）；
- **(b) 跨环境复现**：另一台 Windows 电脑、另一个文件夹，只用运行文件夹自己的文件重跑。容差先量再定，M5 验证（11 的 A-38）。不要求逐位相同：CPU 指令集和求解器的多线程使跨机器逐位相同不现实；而换一个人、换一台机器重跑是真实用法；
- 不依赖任何个人电脑上的特殊设置；
- **四面体网格是带哈希的输入**：fTetWild 之类的工具同一输入多次运行结果不同（实测），所以四面体网格要显式生成一次、落盘并记录哈希，运行时只读，不在运行中重新生成（细节见 ADR-20 和 [13](13-explanations.md) E-03）。

## 3. 不论哪个功能都要满足的要求

| 编号 | 要求 | 为什么 |
|---|---|---|
| N-01 | **单位统一为毫米、牛顿、兆帕、秒**，在导入时换算一次，之后不再换 | 单位错一位，重力和刚度的效果就差十倍，而且不会报错 |
| N-02 | **求解在 Blender 之外的独立程序里运行** | 求解崩溃不拖垮 Blender；没有 Blender 也能批量运行 |
| N-03 | **任何结果都能追溯到产生它的输入** | 论文和审稿需要 |
| N-04 | **只在 Windows 11 上保证可用**（第一阶段） | 实验室和开发都在 Windows 上 |
| N-05 | **不联网也能用**（FEBio 启动时自带的使用统计除外） | 实验室数据不外传 |
| N-06 | **实验室的原始场景文件（`.mb`）、未发表论文和演示视频不进代码仓库**。从它们导出、派生的文件可以进私有仓库（ADR-19） | 资产可能是付费购买的商业模型，论文还在审稿 |
| N-07 | **一段 50 帧的运动，计算时间目标在 10 分钟以内**（单块组织，嘴唇；说明见下面） | FEBio 比 Ziva 慢一些可以接受，但要能在会议上演示 |

**N-07 的说明**：

1. **Ziva 的实测速度**（2026-11-12，实验室的 Ziva 机器，[13](13-explanations.md) E-11）：整张脸（41 块组织）每帧 1.5 到 1.75 秒（696 步平均 1.65 秒）；只留嘴唇一块时每步约 0.01 秒；
2. **比什么和什么**：研究员在 Ziva 里的使用感受对应整张脸的 1.5 到 1.75 秒每帧；我们的求解器现在只算嘴唇，对应 Ziva 只留嘴唇的约 0.01 秒每步。两者不能交叉比。我们只算嘴唇时的速度和 Ziva 只留嘴唇的比较在 T-34 里量；
3. 我们现在的用时、每帧用时和线程数只记在 [15](15-prototype.md) 第 3 节，这里不抄。真实嘴唇 51 帧远在 10 分钟之内（11 的 A-18）。运行报告只报告耗时，不和别的数并排（ADR-38）；默认 4 线程；
4. **全脸的暂定预算**（第二阶段评估求解器时用；全脸还没有开发）：不慢于 Ziva 整张脸的实测 1.5 到 1.75 秒每帧。是否要求更快（交互式），问实验室（11 的 Q12）；
5. 这是正向推进的预算，不是控制器训练的预算：训练时源码不推进时间（ADR-30 及其修订）。

## 4. 第二阶段及以后（现在不做，但设计时要留好位置）

- **给实验室代码的两个接口**（和实验室代码怎么对接见 [04](04-architecture.md) 第 12 节）。实验室的控制器、训练和钢琴式表情界面都是实验室的，我们不做。我们只交两样：
  1. **训练接口**（T-31，提前到第一阶段，11 的 P-08）：一个函数，让实验室的训练代码不经过 Maya 就读到嘴唇形状。训练时源码不推进物理（ADR-30），同一帧里转下颌 Ziva 也不重新求解（11 的 Q20，[13](13-explanations.md) E-11），所以函数的基底是"**第 14 帧沉降后的形状**"，它是控制器优化的起点；
  2. **从上一帧接着算**（T-30，第二阶段）：实验室的钢琴界面每按一次键，Ziva 往前推进一帧物理（[14](14-ziva-demo-walkthrough.md) 第 1 节第 19 步、第 3 节）。界面要换成用 FEBio 时，物理层要能从上一帧的状态接着算。速度要求因此来自正向推进，预算见 N-07；
- **在 Blender 里直接搭建新模型**：Ziva 停售以后，实验室的新模型不会再从 Maya 和 Ziva 来。从 Ziva 导入只是一次性的迁移，我们自己的场景描述（`scene.json`）才是长期的核心；
- **更多组织**：其余 40 块面部组织、皮肤层、眼周肌肉，还没有开发（第二阶段要做的清单收在 T-32）；
- **第二个求解器**：比如 ArtiSynth，用来交叉验证；
- **是否保留 Maya**：除了"全部搬到 Blender"，还有一个选项：**保留 Maya，通过桥接调用核心程序**（Maya 里的 Python 调命令行 `asrp`，和 Blender 插件的做法一样，ADR-02 附注，ADR-03）。Ziva 停用后实验室还要不要 Maya，现在不知道（11 的 Q14）；核心程序不依赖任何界面，所以这个选项不需要现在决定，也不影响第一阶段。

| **音素序列、同一段过渡来回多次**（实验室的需求，不是论文的小节）：实验室的脚本把相邻音素按 `overlap_ratio` 叠起来拼成一条运动（[13](13-explanations.md) E-08），拼法是实验室的。Ziva 里中性到 AA 来回 10 次：物理每次回到起点 0.049 mm 以内；蒙皮后每圈多偏 0.52 mm，原因是运动文件里去程和回程的 landmark 偏移加起来不为零，不是物理（E-11） | 同一段过渡来回播很多次，物理形状不漂 | 第一阶段 |
| **皮肤配准**（3.6、图 1e）：把通用皮肤模板，用物理仿真一次性配准到个人的内部组织上，离线预处理 | 需要皮肤、碰撞（论文用距离场生成的碰撞面）和软粘软；我们的第一、二阶段都没有碰撞。是否要做，问实验室（哪些实验必须能重做，11 的 Q13） | 以后，不在当前范围 |

**怎么读这张表**：第一阶段（嘴唇 + 骨头）要提供：被动物理、颅骨的平移（甩头）、改材料重跑（烧伤的肌肉部分）、每个 landmark 各自的平移（不对称表情）、第 14 帧的形状和训练接口、逐帧的顶点输出、作为报告项的应变能、来回多次不漂。论文里"一整张脸"的东西（皮肤、软粘软、手指按压、全脸速度）属于第二阶段，还没有开发；ADR-26 规定投入之前先用 T-17、T-18 试做法、估速度。
