# 02 需求

这份文档说明做出来的东西要能干什么，以及怎样才算做到了。它只描述"要什么"，不描述"怎么做"；怎么做见 [04 系统设计](04-architecture.md)。

## 1. 谁会用

| 使用者 | 他们要做的事 | 他们熟悉什么 |
|---|---|---|
| **实验室研究员** | 在 Blender 里打开模型，跑一段运动，看结果，和以前 Ziva 的结果并排比较，判断能不能用于研究 | 解剖、表情、Maya 和 Ziva 的操作；不一定会写代码 |
| **控制器研究者** | 用自己的 Python 程序批量调用物理计算（第二阶段） | Python、论文里的控制算法 |
| **开发者** | 按任务卡实现功能 | 编程；不一定懂解剖或有限元 |

## 2. 第一阶段（v0.1 原型）要支持的场景

每个场景后面的"做到了的标准"是验收时逐条检查的内容。编号（R-xx）会在任务卡里引用。

### R-01 打开实验室资产
研究员在 Blender 里一键导入实验室的下颌原型资产：颅骨、下颌、上下牙、嘴唇肌肉，以及 300 个嘴唇控制点（landmark）。

做到了的标准：
- 五个网格都出现在场景里，位置、大小和在 Maya 里看到的一致（用同一视角截图对比）；
- 300 个 landmark 显示为小点，位置和 Maya 里一致；
- 单位已经换算成毫米，界面上能看到这一点；
- 导入后自动生成一份检查报告：网格顶点数、landmark 数量、单位换算系数、发现的问题。

### R-02 检查物理设置
研究员能看到每样东西在物理计算里扮演什么角色：哪个是软组织、哪个是骨头、它们怎么连着、用什么材料参数。

做到了的标准：
- 面板上列出所有软组织、骨头和连接（attachment），每项都能点选并在 3D 视图里高亮；
- 每个参数都标明来源：来自实验室的 Ziva 设置、来自 Ziva 默认值，还是我们自己定的；
- 有一个"检查"按钮，能发现明显错误（比如单位不对、连接没有任何顶点），并用通俗的话说明问题出在哪。

### R-03 运行一段运动
研究员选一条运动轨迹（比如"中性 → AA 音"），点"运行"，FEBio 在后台计算。

做到了的标准：
- 运行期间 Blender 不卡死，能看到进度（第几帧/共几帧），能取消；
- 计算失败时给出看得懂的原因，不显示上一次的旧结果；
- 每次运行都在单独的文件夹里留下全部输入、输出和日志，事后能检查、能重算；
- 每次运行自动做合理性检查（[07](07-validation.md) 第 3 节），不通过的项在报告和面板上标出来。

### R-04 回放结果
运行结束后，在 Blender 的时间轴上逐帧播放嘴唇的变形。

做到了的标准：
- 播放的形状和 FEBio 算出的结果逐帧一致（误差小于 0.001 mm）；
- 帧率和 Ziva 一致（30 帧/秒）；
- 能同时显示"只有物理"和"物理 + landmark 变形"两个版本，方便分析。

### R-05 和 Ziva 并排比较
把同一条轨迹在 Ziva 下的结果导入进来，和 FEBio 的结果并排比较，供研究员评审。目标是让实验室能继续做研究，不是复刻 Ziva，所以**不设数值合格线**（ADR-17）。

做到了的标准：
- 输出一份对比报告：每帧的平均差别、最大差别、95% 顶点的差别（单位毫米），只作参考；
- 在 Blender 里用颜色显示每个顶点的差别大小（热力图），并且能把 Ziva 的结果作为第二个物体同时播放；
- 研究员按 [07](07-validation.md) 第 4.4 节的问题评审，没有"不能接受"的项；
- 报告里还有两个不依赖 Ziva 的指标（ADR-25，口径见 [07](07-validation.md) 第 4.2 节）：**最终形状到美术目标姿态的距离**（论文自己的指标，需要目标姿态网格，见 11 的 D9），以及物理段的**下唇跟随比例**（下唇位移 ÷ 同处下颌位移，Ziva 和 FEBio 各报一个）。论文里的"降到初始距离的 11%"只作参考，不当合格线。

### R-06 复现别人的运行
另一个人拿到某次运行的文件夹，能得到完全相同的结果。

做到了的标准：
- 运行文件夹里记录了所有输入文件的指纹（哈希值）、软件版本和全部参数；
- 用同一份输入重跑，每帧坐标的差别不超过 0.000000001 mm（实测重复运行的差别约为 1×10⁻¹³ mm，见 11 的 A-24），回放文件逐位相同；
- 不依赖任何个人电脑上的特殊设置；
- **四面体网格是带哈希的输入**：fTetWild 之类的工具同一输入多次运行结果不同（实测），所以四面体网格要显式生成一次、落盘并记录哈希，运行时只读，不在运行中重新生成（细节见 ADR-20 和 [13](13-explanations.md) E-03）。

## 3. 不论哪个功能都要满足的要求

| 编号 | 要求 | 为什么 |
|---|---|---|
| N-01 | **单位统一为毫米、牛顿、兆帕、秒**，在导入时换算一次，之后不再换 | 单位错一位，重力和刚度的效果就差十倍，而且不会报错 |
| N-02 | **求解在 Blender 之外的独立程序里运行** | 求解崩溃不拖垮 Blender；没有 Blender 也能批量运行 |
| N-03 | **任何结果都能追溯到产生它的输入** | 论文和审稿需要 |
| N-04 | **只在 Windows 11 上保证可用**（第一阶段） | 实验室和开发都在 Windows 上 |
| N-05 | **不联网也能用**（FEBio 启动时自带的使用统计除外） | 实验室数据不外传 |
| N-06 | **实验室的原始场景文件（`.mb`）、未发表论文和演示视频不进代码仓库**。从它们导出、派生的文件可以进私有仓库（ADR-19） | 资产可能是付费购买的商业模型，论文还在审稿 |
| N-07 | **一段 50 帧的运动，计算时间目标在 10 分钟以内** | 实验室论文第 4.4.4 节写的是 Ziva 正向播放 35 帧约 23 秒；FEBio 慢一些可以接受，但要能在会议上演示。实测后再调整，见 11 的 A-18。**这条是单块组织（嘴唇）的目标**；论文里全脸 35 帧约 23 秒是 Ziva 正向播放的数，全脸要多快、是否要求交互，待定（11 的 Q12） |

## 4. 第二阶段及以后（现在不做，但设计时要留好位置）

- **控制器接入**：实验室的 Python 控制器直接调用我们的物理计算，不再依赖 Maya。论文的主流程用可微的 LBS 代理求解析梯度，优化时不调物理，所以主流程不要求物理很快；只有数值备用流程每步都要算物理（11 的 Q2，下面的对照表有数字）；
- **在 Blender 里直接搭建新模型**：Ziva 停售以后，实验室的新模型不会再从 Maya 和 Ziva 来。从 Ziva 导入只是一次性的迁移，我们自己的场景描述（`scene.json`）才是长期的核心；
- **钢琴式表情界面**：在 Blender 里复刻实验室 Maya 面板（Facial Expression Automator）的操作：按键触发音素、动作单元、表情；
- **更多组织**：完整的面部肌肉、皮肤层、眼周肌肉；
- **第二个求解器**：比如 ArtiSynth，用来交叉验证；
- **是否保留 Maya**：除了"全部搬到 Blender"，还有一个选项：**保留 Maya，通过桥接调用核心程序**（Maya 里的 Python 调命令行 `asrp`，和 Blender 插件的做法一样，ADR-02 附注，ADR-03）。项目最早的技术基线文档就把"Maya 桥接 + 外部 FEM"列为正式的迁移候选。Ziva 停用后实验室还要不要 Maya，现在不知道（11 的 Q14）；核心程序不依赖任何界面，所以这个选项不需要现在决定，也不影响第一阶段。

### 论文里的用法 → 物理层要做什么

2026-11-09 对照论文（*Beneath the Skin*）逐项核对的结果。论文小节号写在第一列，细节和解释见 [13](13-explanations.md) E-04。状态：✅ 已有；🔶 方案已定、待实现；❓ 还没有把握，要先做试验或等实验室回答。

| 论文里的用法（小节） | 物理层要做什么 | 哪个阶段 | 状态 |
|---|---|---|---|
| **嘴唇被动物理**：下颌带动嘴唇，加重力和惯性（4.1.3） | 骨头给定运动，软组织在重力和粘连下变形（R-03） | 第一阶段 | 🔶 T-06；FEBio 的动力学和刚体已由 S1 验证 |
| **组织互相牵拉（软粘软）**：36 个物体，肌肉、脂肪等互相粘连（4.1.3） | 软组织和软组织之间的粘连，不只是挂在骨头上 | 第二阶段 | ❓ FEBio 做得到、速度可接受吗？M3 之前用 T-17（S4）复核（ADR-26，A-30） |
| **皮肤层**：布料层，用 Ziva 粘连挂在内部组织上；嘴唇处改用曲线，肌肉用 wrap 带动曲线、线变形器带动皮肤，这一段是纯几何（3.7、附录 I） | 薄壳皮肤贴在实体上，带粘连；嘴唇处的曲线段不进 FEBio，做成纯几何层 | 第二阶段 | ❓ 壳加粘连用 T-18（S5）复核；几何段的算法在实验室源码里（11 的 D10） |
| **钢琴界面的正向播放**：结果预先算成过渡表，界面只做正向播放，全脸 35 帧约 23 秒（4.4.4；论文标题里有 Interactive） | 先离线算好，播放时只读结果；全脸算一次要多快，没有定 | 第二阶段 | ❓ 速度目标待定（11 的 Q12）；单块组织的目标见 N-07 |
| **甩头**：整个头平移（4.4.6） | 骨头每帧完整刚体变换，包括平移；有惯性（ADR-21） | 第一阶段能做（颅骨按给定运动平移） | 🔶 T-05、T-10；需要实验室的甩头运动（ADR-24） |
| **手指按压**：对皮肤顶点直接加外力（附录 S） | 在选定顶点上加外力载荷 | 第二阶段（要有皮肤层） | ❓ 载荷本身 FEBio 支持，皮肤层见上 |
| **烧伤**：皮肤刚度乘 40，肌肉杨氏模量乘 10（4.4.7） | 只是改材料参数。**第一阶段就能演示**：把嘴唇的杨氏模量乘 10，改 `scene.json` 重跑，比较下垂和跟随；皮肤乘 40 要等皮肤层 | 第一阶段演示肌肉；皮肤在第二阶段 | 🔶 不需要新代码，T-06 做完就能做 |
| **不对称表情**：左右不同的 AU 组合（4.4.8） | 物理层没有特别要求，只要 landmark 的轨迹能给每个 landmark 各自的变换；力沿皮肤传到另一侧要靠软粘软和皮肤 | 轨迹第一阶段；传播第二阶段 | 🔶 / ❓ |
| **控制器优化**：主流程用可微的 LBS 代理求解析梯度，约 200 次迭代、4 到 5 分钟，**优化时不调物理**；数值备用流程约 2 万次迭代、1 小时，每步轮询 Maya 仿真器（3.4、3.5、4.4.3、附录 D、G） | 主流程：物理只需正向算结果，不要求快。备用流程：按论文数字，每次约 0.18 秒（3600 秒 ÷ 2 万次得出的上限估算）。FEBio 能否达到，要等实测（T-17、T-18）和 Q2 的回答 | 第二阶段 | 🔶 部分解决：只剩"备用流程还用不用"（11 的 Q2） |
| **皮肤配准**：把通用皮肤模板，用物理仿真一次性配准到个人的内部组织上，离线预处理（3.6、图 1e） | 需要皮肤、碰撞（论文用距离场生成的碰撞面）和软粘软；我们的第一、二阶段都没有碰撞 | 以后，不在当前范围 | ❓ 是否要做，待实验室回答（哪些实验必须能重做，11 的 Q13） |

**怎么读这张表**：第一阶段（嘴唇 + 骨头）能覆盖这几项：被动物理、甩头、肌肉烧伤的演示、不对称表情的轨迹。论文里"一整张脸"的东西（皮肤、软粘软、手指按压、全脸速度）都在第二阶段，而且 FEBio 能不能撑起来还没有试验，所以 ADR-26 在 M3 之前设了一道复核。

## 5. 需求变更

需求有变化时，修改这份文档并在 [10 决策记录](10-decisions.md) 里写明原因。已经开工的任务受影响时，要在任务卡上注明。
