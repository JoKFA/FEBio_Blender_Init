# ADR-03：求解在独立程序里运行，靠文件交换数据

| **关联决策** | [ADR-46](ADR-46.md)、[ADR-49](ADR-49.md)、[ADR-52](ADR-52.md)、[ADR-53](ADR-53.md) |

## 当前生效结论

- **进程解耦**：Blender 插件只管界面，所有计算在独立的核心程序里，两者通过运行文件夹里的文件交换数据；物理推进仍走独立核心和会话状态目录（[ADR-49](ADR-49.md)）。
- **界面交互边界（2026-11-24 补充）**：插件不再直接解析 `scene.json`，运行前读核心发布的场景视图、运行后读结果清单，后台子进程对象改称 `RunJob`。
- **训练查询例外（2026-11-24 补充）**：训练查询不再经子进程交换文件，改由独立 Python 3.9 包 `asrp_query` 进程内一次载入、反复查询。

## 依据与边界

- **原因**：求解崩溃不影响 Blender；不开 Blender 也能批量运行，以后控制器也能直接调用；每一步的输入输出都能单独检查和重算。
- **证据**：`tools/check_blender_addon.py` 验证了 Blender → 子进程 → 核心程序 → 结果返回这条链路。

## 历史与修订

- **2026-10-27**：初版定案，规定插件与核心通过运行文件夹里的文件交换数据。
- **2026-11-24（[ADR-46](ADR-46.md)、[ADR-52](ADR-52.md)、[ADR-53](ADR-53.md) 补充）**：细化界面读取场景视图与结果清单、改称 `RunJob`，并将训练查询分流至进程内 `asrp_query` 包。
