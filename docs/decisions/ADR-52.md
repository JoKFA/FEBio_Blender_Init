## 当前生效结论

1. **固定两个公开结果层与统一读取维度**：
   - 核心对外公开的结果层名固定为 **`physics`** 和 **`final`**（生产者与适用表面表见 [会话、检查与结果规范](../architecture/sessions-and-results.md)，原 [04](../architecture/README.md) 第 13 节）。
   - 数组按**状态、对象、参考表面、结果层、绝对帧**读取，核心数组保持几何毫米、Z 向上、原序世界坐标。
   - 每段数组沿用 float64 `.npy` 加 JSON 头，按对象、表面、层分别存；结果清单格式 `asrp-results/1`（待实现）；PC2 是派生回放文件。
2. **网格密度与处理阶段分开**：
   - 粗壳和细显示面用不同的**参考表面 ID** 区分，不另造层名；处理阶段用层名区分。
   - 有声明输出面的组织、皮肤（原序布料面和绑定的细显示面）及给定运动的刚体（包括下颌、手，由实际变换产生）均有 `physics` 层。
   - 仅作为建造内部网格生成的粗壳节点数组属诊断数据，除非实验室读取的布料网格本身就是该壳。
3. **`final` 层只发布已声明且已验证的显示处理**：
   - 嘴唇、两眼、额肌等有 landmark 绑定的对象在对应组验证后发布；皮肤最终显示面在取得并验证“最终嘴唇 → 包裹曲线 → 皮肤蒙皮”数据后发布。
   - 无该步骤的骨头直接读 `physics`；缺少数据时结果清单写明原因，读取 `final` 明确失败，**禁止用 `physics` 冒充缺失的 `final`**。
4. **实验室自有产物核心不发布**：按压脚本改过的皮肤、实验室额外牙舌显示修正、控制器或训练程序自己的产物归实验室拥有，其改动不写回物理状态。
5. **读取与回放必须核对完整身份**：
   - 结果清单写明场景版本、建造、状态、对象、参考表面 ID、层、生产者、绝对帧与秒、坐标约定、数组形状和摘要。
   - 给 Blender 的网格在导入时写入场景版本、表面 ID 和逐顶点原始行号，接缓存前核对行号、参考网格有序静止坐标与连接关系（合法逐帧重三角化允许回放），不再只比顶点数。
6. **现在不定**：
   - 皮肤 `final` 层所需的“最终嘴唇 → 包裹曲线 → 皮肤蒙皮”数据，以及眼周、额肌和下颌在对应场景家族上的逐表面原序参考，等补取实验室数据后验证。
   - 眼周、额肌在对应显示处理验证后可发布 `final`；下颌没有显示后处理，训练查询用本家族原序参考验，会话中的下颌由实际变换生成其表面的 `physics` 顶点，补到下颌参考不会凭空产生 `final`。

## 依据与边界

- **原因**：
  - 实验室既会读皮肤物理布料面，也会读蒙皮后的细显示面，还会读下颌、手等刚体表面；只靠顶点数分不清同点数对象或不同表面，为每种网格密度造新层名会让接口膨胀。
  - 现行 Blender 回放只按顶点个数接缓存、靠组织名找嘴唇，交换两行坐标或换错资产查不出来。
- **证据（源码核实，[E-23](../archive/explanations/E-23.md)）**：插件（`blender_addon/asrp_blender/asset.py`）第 791 行回放只核对顶点个数。
  - 实验室分析、甩头和按压脚本读取的表面及改点行为见实验室源码核查（[03](../03-asset.md)、[E-23](../archive/explanations/E-23.md)）。
- **重开条件**：出现实验室真实读取操作，现有的“对象 + 参考表面 ID + 处理阶段（`physics`/`final`）”无法无歧义表示其所需数据时，重开本条。

---

## 历史与修订

- **放弃的方案**：
  - 为粗壳、细面等不同网格密度各造一层名：把表面身份和处理阶段混在一起，难以维护；
  - 用 `physics` 层冒充缺失的 `final` 层：掩盖数据缺失，误导下游；
  - 把实验室按压脚本等下游改点归为核心层或回写物理历史：混淆边界并破坏物理重放；
  - 回放只核对顶点数或面索引哈希：漏掉错资产与坐标行对调。
