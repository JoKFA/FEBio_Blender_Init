## 目标与范围

- **目标**：用户可在 Blender 里打开旧场景、高亮粘连、切换结果层、另存 `.blend`、编辑参数、关闭重开，并在后台运行中途切换到另一份 `.blend` 而不串结果。
  - 核心发布**场景视图**（运行前）和**结果清单**（运行后）；插件不再直接解析 `scene.json`，并按顶点身份阻止错网格或重排顶点回放。
- **输入**：
  - [T-43](T-43.md) 封存的旧嘴唇基线与旧运行结果；
  - 现行 `asrp_core.scene`、结果写出与 Blender 插件代码。
- **产出明细**：
  - `scene` 模块的版本库实现（内容摘要定版、大文件按摘要共享、规范化序列化、发布与引用校验）和 v1 场景视图适配；
  - `results` 模块的结果清单（`asrp-results/1`，文件 `results.json`，待实现；公开层名固定为 `physics` 与 `final`）及顶点身份校验；
  - 更新后的 Blender 插件（`RunSession` 改称 `RunJob`，通过 CLI 与场景视图/结果清单完成打开、高亮、换层、另存、编辑、重开与作业归属；删去对应直接读 `scene.json` 的逻辑）；
  - 本卡新增命令（待实现，旧场景和旧运行由相应适配器打开）：
    - `asrp scene inspect <revision> --store <dir>`
    - `asrp scene edit <revision> --store <dir> --patch <json>`
    - `asrp results inspect <results.json>`
    - `asrp results export-playback <results.json> --object <id> --surface <id> --layer <name> --out <dir>`
  - 验收测试 `C02`（待新增）。
- **不做**：不许动物理生成、旧数据、源显示顶点顺序。

## 约束与接口

- **场景版本落盘（[`ADR-46`](../decisions/ADR-46.md)）**：
  - 项目数据目录保存持久 `store_id`；`scenes/<revision>/scene.json` 存规范化清单，版本号为规范化清单的 SHA-256；`blobs/<sha256>` 按内容摘要共享有序网格、权重、绑定等大文件，清单写明用途、格式、摘要和长度。
  - 规范化 JSON 固定 UTF-8、键序和有限数规则，保留有意义的数组顺序，拒绝重复键和非有限数，并用固定样本锁住规范化字节。
  - 时间、绝对路径、提交者、编辑说明及父版本记在版本外的历史记录（场景库 `history/` 下一次编辑事件一份 JSON；同内容经两条历史到达就保留两条事件；这些信息不参与内容摘要）。
  - 编辑发布先写并校验缺少的大文件，再同卷暂存并发布清单，最后更新发起编辑的引用；单字节损坏必须报摘要错误，不得静默替换。
  - 已发布版本首版不自动删除（关闭 Blender、删分支、另存为均不触发回收，只可另行清理暂存失败文件）。
- **`.blend` 引用与 `RunJob`**：
  - `.blend` 保存 `store_id + revision`、相对 `.blend` 的仓库路径提示，以及会话、状态 ID。
  - 普通"另存为"重算路径提示并继续引用同一不可变版本；从任一 `.blend` 编辑参数时经核心生成新版本，只更新发起编辑的文件；搬家后重新定位必须核对 `store_id` 与版本身份；缺外部文件时指出具体缺项。
  - 后台作业类 `RunSession` 改称 `RunJob`，启动时绑定发起文件、场景版本和父状态；运行中途切换 `.blend`，结果仍归发起者，回到原文件可取回。
- **场景视图、结果清单与安全回放（[`ADR-52`](../decisions/ADR-52.md)）**：
  - 核心先从旧 v1 场景适配生成运行前**场景视图**（物体、参考表面、参数、粘连参与顶点、landmark 组）和运行后**结果清单**（按状态、对象、参考表面、层 `physics`/`final`、绝对帧索引，含场景版本、建造、时间、坐标约定、生产者、形状及摘要；旧运行由旧版读取器兼容回放）。
  - 导入 Blender 的网格写入场景版本、表面 ID 和逐顶点原始行号；接缓存前核对原始行号、参考表面静止坐标与连接关系（宿主浮点转换按导入时同一表示核对）。
  - 因对应关系建立在静止参考表面上，合法的逐帧重新三角化必须可以通过回放。
  - v1 用只读适配器暴露旧运行身份和可核对的场景、表面、层、帧；旧记录缺少的建造、父状态按旧格式标明，不得编造 ID；旧回放不得充当续算父档；旧数据不足以确认点序时明示验证范围。
- **兼容与术语约束**：
  - 现有 `asrp_core.asset` 保留为兼容导入入口，不为了改名先做全仓重命名；插件 `asset.py` 可按打开场景、选择和高亮职责整理。
  - 严格守 [glossary.md](../glossary.md) 用词："场景版本"不写"资产版本"，运行前清单称"场景视图"不称"资产视图"，"资产"只指实验室原始材料。

## 验收条件

> 只看到 `passed` 或退出码 0 不算交付，必须贴出真实命令与完整打印输出作为证据。

- **正向验收**：
  - 运行 `uv run pytest -s -k C02`，调用真实 Blender（无窗口 `--background`）执行打开旧场景、高亮、换层、另存、编辑、重开以及运行中切换 `.blend`。
  - 打印两份 `.blend` 编辑前后的场景版本摘要、后台作业 `RunJob` 的发起者与结果归属、参考表面身份及已知非零运动点的读回数值。
  - 以下场景须全部通过：合法逐帧重新三角化可回放；旧运行经旧版读取器仍可回放；同内容不同编辑历史得到同一摘要；另存后只有发起编辑的文件升级；移走仓库再定位时核对 `store_id` 通过；对象改成中文名、两个对象同名两例中，旧结果仍指向原对象。
- **必须失败的坏例**：
  1. 同顶点数但属于不同参考表面的网格接入缓存，必须失败；
  2. 只交换两行顶点坐标（面连接不变），必须失败；
  3. 错帧或 `physics` / `final` 错层，必须失败；
  4. 同名但 `store_id` 不同的仓库，必须失败；
  5. 改坏清单或共享大文件中的单个字节，必须报摘要错误（不得报"找不到"并替换）。
- **门禁验证**：因改动 `blender_addon/`，交付最终状态必须跑全量 `uv run python tools/verify.py` 并记录实际输出。

## 历史与备注

- **为什么做**：已核实源码中插件多处直接依赖旧场景结构（`lips_object()` 按组织名找物体；`asset.py` 第 791 行 `show_layer()` 回放时只按顶点个数接缓存，同名同点数但顶点行重排的网格查不出来）；另外若 `.blend` 另存为后编辑参数改坏原文件、或后台作业中途切换 `.blend` 把结果写回错文件，会静默污染实验记录。
- **中断注入范围**：本卡在本机数据卷上对场景版本发布和另存搬家做中断注入；网络盘不在本卡，状态发布和分支引用的中断归 [T-48](T-48.md)；进程中断通过只证明所测故障，不签突然断电。本卡按 [`ADR-46`](../decisions/ADR-46.md) 的同卷暂存发布与 `store_id + revision` 校验实现。
