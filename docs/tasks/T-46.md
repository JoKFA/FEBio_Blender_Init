## 一、目标与命令入口（先看这里）

- **目标**：切开 `generate.build()`，让新建造路径先生成并落盘不可变的**建造记录**（含有效建造配置、计算网格、显示绑定、粘连实现、预分配的骨头驱动通道和 FEBio 编号表），再由 `backends/febio` 写出首份 `.feb` 并经 `checks` 核验输出；两种旧嘴唇场景（`ours`、`ziva-soft`）回归误差均在 `1e-9 mm` 以内。
- **T-46 完成时，各命令怎么走**：
  - 普通 `asrp run`（即 `asrp run <scene> <motion>`）：**仍走旧冷启动**（本卡不切换）。
  - 新建造迁移测试入口：本卡新增临时选项 `asrp run <scene> <motion> --candidate-build`（待实现）。
  - `asrp run --feb`：全程直调底层执行器，不虚构建造。
  - 新增建造命令：`asrp build <revision> --store <dir> --profile <profile> --out <dir>`（待实现）。
- **什么时候切旧入口**：等 [T-47](T-47.md) 补完[建造与粘连](../architecture/build-and-attachments.md) 第 4 节第 2 类（"先静后动"跨段对照，依赖会话续算）用例，并在同一最终状态重跑 `C01`、`C04`、`C05` 后，两类都过才将普通 `asrp run` 一次切到"新建会话 → 提交一段 → 导出"并移除 `--candidate-build`；[T-48](T-48.md) 随后验证分支与恢复并冻结会话。

## 二、施工必读（读本卡加这几处即可开工）

- **建造与网格**：[建造、网格与通道预分配](../architecture/build-and-attachments.md)（原 [04](../architecture/README.md) 第 13.5、13.8、13.13 节）
- **边界与检查**：[地基总览](../architecture/README.md)（第 1、2 节）、[会话与结果](../architecture/sessions-and-results.md)（第 2 节）
- **决策依据**：[`ADR-47`](../decisions/ADR-47.md)、[`ADR-48`](../decisions/ADR-48.md)、[`ADR-50`](../decisions/ADR-50.md)、[`ADR-44`](../decisions/ADR-44.md)
- **验证与规范**：[07 第 1.2 节](../07-validation.md)（官方算例）、[08 第 4、5、6 节](../08-engineering-standards.md)、[13 归档 / E-23](../archive/explanations/E-23.md)

**为什么做**：
- 已核实源码 `generate.py` 第 326–343 行把整次实验固定的模型和本段运动混在同一个 `build()` 里，并按"本段有没有驱动"决定把骨头写成固定还是可动（"第一段静止、第二段才动下颌"会建错模型）；同时旧做法把模型翻译细节散在运行中，删缓存或换算法后无法对照与重放。
- 本机对原型中性到 AA（粗格子，224 节点，46 帧，1 线程）的一次实测显示，颅骨从固定改为给定零位移时，日志里的坐标（已乘物理尺度 0.67）最大差 `1×10⁻¹⁰`，是日志 12 位有效数字的最后一位，换算成几何毫米约 `1.5×10⁻¹⁰ mm`。
- 只试了这一个模型一段运动（[13 归档 / E-23](../archive/explanations/E-23.md)），具备取消兼容开关的初步依据，但切换旧入口前必须补全受力方式与细网格对照（[建造与粘连](../architecture/build-and-attachments.md) 第 4 节的第 1 类用例，本卡）及第 2 类用例（[T-47](T-47.md)）。

**输入**：[T-43](T-43.md) 封存的三份旧嘴唇基线与独立比较器、[T-44](T-44.md) 的 `scene` 版本库与 `results` 清单、[T-45](T-45.md) 的导入与场景声明结构、离线生成的细网格（如 `data/tetmesh/lips.json`）及规则格子参数（[`ADR-44`](../decisions/ADR-44.md)）。

**交付产物**：
1. `build` 模块：`prepare(revision, profile)` 返回不可变并落盘的建造记录；随代码发布版本化的 `legacy-v1` 建造配置 JSON。
2. `backends/febio`：首段写出与编号表（`prepare_model()`、`write_initial()` 等，首次与重启共享一份编号表）。
3. `checks` 模块：从 `simulate.py` 迁入 `_physics_checks` 等校验逻辑，按执行门槛 / 物理合理性 / 显示面质量 / Ziva 对照分工。
4. CLI：新增临时迁移测试选项 `asrp run <scene> <motion> --candidate-build` 与建造命令 `asrp build <revision> --store <dir> --profile <profile> --out <dir>`（均待实现）。
5. 官方算例比较入口："正式生成器 → 真实 FEBio → 对发布参考值"，用旧后端已经能表达的 FEBio 官方算例验证一次（所选算例和参考值列入报告）。
6. 验收测试 `C04`（待新增）。

## 四、实施要点（完整契约见"施工必读"）

1. **不可变建造记录（[`ADR-47`](../decisions/ADR-47.md)）**：
   - 把静态模型构建移入 `build`，落盘完全展开后的有效配置、来源和摘要、实际计算网格及内容摘要、显示绑定、粘连对应和实现记录、有效材料/刚度/物理尺度、驱动通道、FEBio 编号表及足以重放的数组。
   - 建造清单落在 `session/build/`，数组和网格按摘要放进同一项目库的 `blobs/` 共享，清单必须能找到并验证全部真实字节。
2. **`legacy-v1` 建造配置（[`ADR-47`](../decisions/ADR-47.md)、[`ADR-48`](../decisions/ADR-48.md)）**：
   - 两种旧嘴唇场景（`ours`、`ziva-soft`）共用一份 `legacy-v1` 建造配置，由已识别的 v1 格式和文件里实际的 `hard`、`spring` 声明决定执行硬加弹簧或四组全软（上唇硬、其余三组弹簧的文件执行硬加弹簧，四组全软的文件执行四组全软）。
   - 严格沿用已落盘的 N/mm 刚度、硬优先、节点冲突处理和分档，改文件夹名不改变实现，**改场景材料不重算旧弹簧**。
   - 改材料须先发布新场景版本再建造并新开会话；仅改建造配置时可复用原场景版本。
3. **计算网格规矩（[`ADR-47`](../decisions/ADR-47.md)）**：
   - 细四面体网格只按引用加载并核对摘要，**禁止缺失时调用 fTetWild 或静默回退粗格子**；规则格子允许建造时生成，但节点、单元、顺序、参数（含格子原点，[`ADR-44`](../decisions/ADR-44.md) 已证实格子位置影响嘴唇运动）和生成器版本全封存入建造记录。
   - 缺细网格、摘要不符或格子无有效单元报到具体对象 ID。
   - 选型优先级：明确建造配置优先 → 配置写"用场景首选"取场景首选引用 → 两者都未给且没有具名的配置默认值时按对象报缺；有效选择、来源和摘要写入建造记录，引用损坏不得回退到别的网格。
4. **骨头通道预分配与第 1 类用例（[`ADR-48`](../decisions/ADR-48.md)）**：
   - 声明为可驱动且纳入本次建造的骨头，从第一段起分配完整通道、首段无运动时给定零位移，不设"本段缺驱动则固定"的兼容开关（真正声明为永久固定的骨头仍按场景语义处理）。
   - 补跑[建造与粘连](../architecture/build-and-attachments.md) 第 4 节第 1 类用例（补受力方式与细网格）：覆盖两种旧嘴唇（含承受上唇硬连接反力的静止骨和只承受软弹簧的静止骨），至少补一例已有细网格，加重力沉降与一段非零载荷；固定版、给定零版、同输入自重复三者同环境对比，分记 1 线程与默认线程，全帧全原序点几何毫米差须 `≤ 1e-9 mm`（PC2 另按 float32 验）。
5. **检查分工（[`ADR-50`](../decisions/ADR-50.md)）**：
   - 后端保留原始顺序与全部记录，`checks` 须先核对全部实际物理时间、完整行、节点身份、有限值与倒置四面体等硬门槛（不得在挑选预期帧之后才查），再输出物理合理性与逐层表面质量报告（保留 `_surface_health` 只报告语义与独立 `asrp compare`）。
6. **嘴唇专用检查**：
   - `tetmesh.check` 的通用质量检查对所有组织生效；沿 x 的上下唇分开检查只对要求该项的嘴唇网格生效，保留旧细网格验收和粗格子的既有语义（修掉现有代码即使 `separation_applicable=False` 也把"不适用"计入失败的问题）。
7. **官方算例比较入口（[07 第 1.2 节](../07-validation.md)）**：
   - 建立"正式生成 → 真实 FEBio → 对发布参考值"的比较入口，用旧后端已能表达的官方算例验证一次；没有同物理能力的官方算例时列明缺口，不把原样跑通算作生成器通过。

## 五、验收与必须失败的坏例

> 只看到 `passed` 或退出码 0 不算交付，必须贴出真实命令与完整打印输出作为证据。

**正向验收**：
- 运行 `uv run pytest -s -k C04`，三份旧样本（`ours`、`ziva-soft`、只改材料）均经正式候选路径 `asrp run <scene> <motion> --candidate-build` 运行并与 [T-43](T-43.md) 基线比较，打印：
  - 逐帧最坏点、最坏帧与分量、单位（几何 mm）、`≤ 1e-9 mm` 判定结果、实际线程数、有效建造配置及网格摘要；
  - 只改材料样本：材料确实改变、旧弹簧 N/mm 和分档未变、逐帧两层误差；
  - 第 1 类用例固定/给定零位移补测（含至少一例细网格、1 线程与默认线程、同输入自重复对照）及 PC2 float32 读回结果；
  - 改变规则格子原点的好例：配置摘要和建造身份确实改变（[`ADR-44`](../decisions/ADR-44.md)）；
  - 两个会话按摘要共享同一份网格内容；
  - 官方算例比较结果（所选算例、发布参考值、实测值）。
- 交付最终状态跑 `uv run python tools/verify.py` 并记录实际输出。

**必须失败的坏例**：
1. 移走或篡改细网格文件，必须报到对象 ID 并失败（不得启动 fTetWild 或回退粗格子）。
2. 改动旧场景材料后触发旧弹簧刚度被重算，必须失败。
3. 建造记录漏分配静止但可驱动骨头的通道，必须失败。
4. 应分开却闭合的旧细嘴唇，嘴唇专用检查必须失败；无唇缝的正常组织必须通过通用检查（不因"不适用"被判失败）。

## 六、不做与红线

- **不做**：不许动旧弹簧刚度、旧平滑样本、[T-43](T-43.md) 基线、细网格离线生成规矩。
- **超限红线**：若第 1 类用例超出 `1e-9 mm`，**不得私自加兼容开关或放宽门限**，必须停下来定位差异来源（位移、单位、日志精度、硬连接或求解差异），保留旧入口并向项目负责人报告。
