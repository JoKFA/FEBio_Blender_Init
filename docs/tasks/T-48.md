## 目标与范围

- **目标**：用户可从运动中的已提交状态开出两条不同未来、在运行中途杀掉一路后安全重试、并发提交同一分支而不丢状态，并可清光 FEBio `.dmp` 缓存后只凭已提交记录重放恢复且核对结果。
- **输入**：
  - [T-47](T-47.md) 的可续算单嘴唇会话与运动中状态；
  - 两组分叉运动输入及用于故障注入的坏例数据（多走 24 帧、重复时间、错父档、截断行、篡改结果）。
- **产出明细**：
  - `sessions` 完整能力（独立尝试目录与父档副本复制/校验、同卷暂存整目录原子发布、带预期旧值的分支引用更新、`checkout()`、`replay()`、`drop_cache()`、失败恢复与已校验提交复用）；
  - `checks` 的提交前硬门槛校验（全实际时间表、精确结束时间、重复时间、截断行、父档/建造身份、摘要与重放数值参照核对）；
  - 本卡新增命令（待实现）：
    - `asrp session checkout <session> --state <id>`
    - `asrp session advance … --branch <name> --expect <old-state>`
    - `asrp session replay <session> --state <id>`
    - `asrp session drop-cache <session>`
  - 验收测试 `C06`（待新增）。
- **不做**：不许动父档、旧状态目录、原结果摘要；失败后不得发布半个状态。

## 约束与接口

- **独立工作副本与提交前检查（[`ADR-49`](../decisions/ADR-49.md)、[`ADR-50`](../decisions/ADR-50.md)）**：
  - 每次尝试新建独立 `attempts/<attempt-id>/`，校验父档摘要后复制到工作副本，禁止 FEBio 写父档原路径。
  - 后端交出原始顺序与全部记录，`checks` 必须在取整、去重和挑预期帧**之前**核对：正常结束、全部实际物理时间、精确结束时间、完整行、节点身份、有限值、网格健康（倒置四面体等）、未列出警告、父状态与建造身份。
  - 硬门槛失败或必做检查缺失时，绝不发布子状态，尝试目录仅留诊断，父状态与父档保持可用；独立副本保护 `.dmp`，`-noappend` 另管旧 `.xplt` 的重新打开，两者分别核验。
- **原子发布与并发分支**：
  - 先在同卷临时目录写齐结果、清单和摘要并关闭文件，再一次重命名发布整个子状态目录 `states/<state-id>/`，最后带预期旧值更新 `refs/` 分支引用。
  - 同一父状态允许多个成功子状态；两个任务争更新同一分支引用时，引用只移动一次，后到者收到分支已移动的提示，两个有效子状态都能按 ID 找回。
  - 崩溃后未发布目录不算状态，已发布但分支未移动的子状态可按 ID 找回；相同父状态与相同有效输入重试时复用已校验提交。
- **删档重放与缓存清理**：
  - 状态身份覆盖父 ID、建造与环境身份、有效设置、物理样本及显示输入。
  - 字节摘要抓文件损坏，数值参照按登记容差（位置 `1e-5 mm`、速度 `1e-4 mm/s`、应力 `1e-6 MPa`）抓重算漂移。
  - `drop_cache()` 清光 `cache/` 时不删任何已提交输入和结果；缓存缺失或损坏时拒用坏缓存，能从最近有效祖先重放就恢复，已提交结果本身损坏则报告并拒绝复用；建造清单引用的共享内容也不删。
  - 搬走或导出会话时，要么连同所引用内容一起打包，要么明确校验并定位同一项目库，只复制一张摘要表不算可重放；换 FEBio 构建或环境建立标明来源的新计算记录。

## 验收条件

> 只看到 `passed` 或退出码 0 不算交付，必须贴出真实命令与完整打印输出作为证据。

- **正向验收**：
  - 运行 `uv run pytest -s -k C06`，从 [T-47](T-47.md) 运动中状态执行分两路、杀掉一路、重试、并发更新同一引用、清光缓存后重放与崩溃恢复。
  - 打印：同父同输入的重试只得到一个有效状态、两个确实不同的子状态 ID 与位移差、父状态和父档前后摘要（不变）、清缓存重放后的逐帧误差、崩溃后按 ID 找回的状态、并发争引用时引用只移动一次且两个有效子状态均可找回的记录。
- **必须失败的坏例（均须由正式入口拒绝提交或拒绝复用）**：
  1. 注入预期第 46 帧、实际走到第 70 帧（多走 24 帧）的输出；
  2. 注入重复时间记录；
  3. 注入错父档（或父档摘要不符）；
  4. 注入截断行（被杀运行残留的半条记录）；
  5. 篡改已提交结果：分别注入（a）字节损坏，（b）文件自身摘要正确、但重算值偏离封存参照（例如位置偏 `2e-5 mm`）两例，都必须被拒绝复用。
- **门禁验证**：交付最终状态跑 `uv run python tools/verify.py` 并记录实际输出。

## 历史与备注

- **为什么做**：
  - 本机 FEBio 会话实测（[13 归档 / E-23](../archive/explanations/E-23.md)）已抓到致命故障：若续算直接改写起点存档路径，进程被杀后再重试，**12 次里有 11 次"正常结束"且健康检查通过，实际却从第 33–35 帧接着多走 24 帧停在第 70 帧（预期第 46 帧）**。
  - 而在独立副本上重试、同档分两路、删档重放则全部与基线一致（误差 0 或 `1e-10 mm`）。不先落实独立工作副本、提交前全时间检查和原子整目录发布，就不能签会话三条承诺。
- **中断注入范围**：本卡在本机实际数据卷上分别于写数组、状态已发布而引用未移、竞争更新引用三处注入中断，并验证同父同输入的重试只得到一个有效状态；场景发布与另存搬家归 [T-44](T-44.md)；进程中断通过只证明所测故障，不签突然断电；网络盘不在本卡，未来若用网络盘须重验。
