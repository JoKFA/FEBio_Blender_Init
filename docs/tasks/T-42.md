## 目标与范围

- **目标**：一次修掉 2026-11-16 审计列出的 8 项小问题（前 7 项经两位审计者确认，第 8 项来自同一份审计的建议）：
  - 拦住错的对比、错的运动转换、退化的四面体网格和截断或损坏的回放包；
  - 把耗时说法改准；
  - 补上 Python 3.9 导入、`uv` 检查与离线调用，以及 cp936 下的测试编码。
- **改动文档**：同步更新 [06](../06-ui.md)、[15](../15-prototype.md) 与 `docs/15-prototype.en.md`。
- **不做**：
  - 不往现有的单组织、整段运行结构上加新功能；
  - 不处理导入时丢掉的粘连阻尼 0.01（归第 2 节穿插行 / [T-41](T-41.md)）；
  - 不处理 FEBio 接触配对警告（归结构改动 A，[E-21](../archive/explanations/E-21.md)）。

## 约束与接口

按 2026-11-16 审计项逐项落实（括号内编号为原审计文件编号，汇总见 [2026-11-16 审计汇总](../archive/explanations/E-23.md)）：

1. **`asrp compare` 核对两边是不是同一条运动（R4）**
   - 现状只查帧范围，拿我们的 AU12 比 Ziva 的 AA 仍报 `compare DONE`（平均差 5.41 mm），AA 对 EH 也照常通过。
   - 改为把我们运行的下颌运动与 Ziva 导出 `motion.json` 里的 `jaw01`（`ziva_export.body_transforms`）比对，超过约定容差就报错拒绝。
   - 依据：[13 / E-19](../13-explanations.md) 实测同一条运动两边差约 1e-13。
2. **`asrp convert-motion --starts-at-rest` 真正校验起点（R5）**
   - 现状该参数只是一句声明；实验室 84 个运动文件里只有 18 个从中性出发，另外 66 个带着该参数也会无报错转换并给出错的结果。
   - 改为检查起点确实从中性出发，否则报错拒绝。
3. **检查 (d) 查四面体体积与物理层退化（R6）**
   - 现状检查 (d) 不看四面体体积，细网格上物理层出现 4–5 倍体积比、翻转面和过长边时仍判通过。
   - 补上校验，让这类退化不能通过检查。
4. **回放包加载校验截断和损坏（R9）**
   - 现状截断的点缓存仍能加载，损坏的 `playback.json` 只报 `'cache'`。
   - 加载时校验点缓存完整性，损坏的 `playback.json` 给出清楚可读的报错。
5. **改准粗格子耗时的文字（P3）**
   - 实测粗格子单次运行为 3.3–3.6 s，但多处写死了偏低或固定的耗时：
     - 面板里的 "About 1 s per run"；
     - [06](../06-ui.md) 里的 "About 1 s per run" / "About 30 s per run" 与"时间是写死的说法"；
     - [15](../15-prototype.md) 里的"一两秒"及 `docs/15-prototype.en.md` 里的 "after about two seconds"。
   - 面板改为按本次运行的实测耗时生成文字，不再写死固定秒数，并同步更新 [06](../06-ui.md)、[15](../15-prototype.md) 和 `docs/15-prototype.en.md`。
6. **修复核心程序在 Maya 2023（Python 3.9）下的导入（U5）**
   - `tetmesh.py` 的 `float | None` 注解在 Python 3.9 的 dataclass 求值时报错，导致核心在实验室的 Maya 2023（Python 3.9）里导入失败。
   - 改成 Python 3.9 下可正常导入的写法。
7. **`asrp doctor` 检查 `uv`，面板调 `uv run` 加 `--no-sync`（U4 代码部分）**
   - 现状 `asrp doctor` 不查 `uv`，面板调 `uv run` 不带 `--no-sync`，新机器第一次 Run 可能触发联网。
   - 在 `asrp doctor` 里加入 `uv` 检查，面板调 `uv run` 时加上 `--no-sync`。
8. **给读文件的测试补上 `encoding=`**
   - 部分测试读文件没写 `encoding=`，在 cp936 代码页下失败。
   - 把这些文件读写调用显式补上 `encoding=`。

## 验收条件

1. **R4**：新增不依赖仓库外数据的合成对照测试（两组下颌运动不同的合成运行与导出，测试里写明容差），另加仓库外数据对比测试（AU12 对 Ziva 的 AA，以及 AA 对 EH，均需仓库外数据）。
   - 改前报 `compare DONE`（AU12 对 AA 平均差 5.41 mm）；改后超过容差必须报错拒绝。
2. **R5**：新增测试，用合成的不从中性出发的运动文件（无仓库外数据时也能运行）带 `--starts-at-rest` 调 `asrp convert-motion`，另用实验室 84 个运动文件里不从中性出发的文件（66 个之一，需仓库外数据）做同样测试。
   - 改前无报错转换并给出错结果；改后必须报错拒绝，18 个从中性出发的文件仍能通过。
3. **R6**：新增测试，输入物理层存在 4–5 倍四面体体积比、翻转面或过长边的结果。
   - 改前检查 (d) 判通过；改后必须不通过。
4. **R9**：新增测试，分别加载截断的点缓存和损坏的 `playback.json`。
   - 改前截断缓存照常加载、坏 `playback.json` 只报 `'cache'`；改后截断缓存必须报错拒绝，坏 `playback.json` 必须给出明确可读的错误信息。
5. **P3**：新增测试，喂给面板一份带已知耗时的运行报告，检查面板文字显示该实测耗时；另加检查确认面板、[06](../06-ui.md)、[15](../15-prototype.md) 和 `docs/15-prototype.en.md` 不再留有上述写死耗时说法。
   - 须清除的说法："About 1 s per run"、"About 30 s per run"、"时间是写死的说法"、"一两秒"、"after about two seconds"；改前失败，改后通过。
6. **U5**：在真实的 Python 3.9 解释器下 `import asrp_core`（例如 `uv run --python 3.9`）。
   - 改前因 `tetmesh.py` 的 `float | None` 注解在 dataclass 求值时报错而失败；改后通过。
7. **U4**：新增测试，验证缺少 `uv` 时 `asrp doctor` 失败，且面板拼出的 `uv run` 命令带有 `--no-sync`。
   - 改前两项均失败，改后通过。
8. **cp936**：新增遍历 `tests/` 的测试（AST 或文本扫描），凡是 `open(`、`read_text(`、`write_text(` 未传 `encoding=` 即失败；或用 `-X warn_default_encoding -W error::EncodingWarning` 跑 pytest。
   - 改前失败，改后通过。
9. 最终执行 `uv run python tools/verify.py` 通过。
