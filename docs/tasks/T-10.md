## 目标与范围

- **目标**：把实验室控制器输出的运动文件转换成 `trajectory.json`，包括 `landmarks` 一节（格式在 [04](../archive/prototype/04-v1-architecture.md) 第 5.2 节写定）。
- **分工边界**：
  - 最小格式（`"asrp-trajectory/1"`、每个驱动源每帧 4×4 刚体变换）和铰链运动生成函数由 [T-05](../archive/tasks/T-05.md) 做好；
  - `landmarks` 一节的读取和校验由 [T-09](../archive/tasks/T-09.md) 加；这张卡只做转换；
  - 从中性出发的单段过渡由 [T-34](../archive/tasks/T-34.md) 先做，这张卡做其余的；
  - `tools/placeholder_jaw_motion.py` 写出的代用运动是同一种格式的现成样子。
- **产品现在能跑什么**：
  - 求解入口拒绝第一帧不是静止姿态的运动（`src/asrp_core/generate.py` 对驱动源第 0 帧的检查，[05 归档](../archive/prototype/05-v1-attachment-trials.md)“T-06a 的实现”表中"运动的第 0 帧"一行）；
  - 单独转换出的一段也不带组织的速度、应力和之前的加载历史；不从中性出发的段，只有拼进一条从中性开始的完整序列里才能运行；
  - 单独的一段非中性过渡暂时只是离线输入，不能直接跑：`asrp run` 的报错会直接说明原因和做法（接在通向它起点的那一段后面，放进同一条从静止开始的运动里），不用去翻代码（2026-11-13 改了报错并加了测试）；
  - 地基入口做出来以后（续算语义归 [T-47](T-47.md)），可从已知父状态提交非中性的后续段，也可从根提交有时间的非中性初始化；
  - v1 单文件冷启动仍需从静止开始，只有运动文件却不知道本段参考时仍只解码；纯眼额运动和实验室按键的对接归 [T-52](T-52.md)；原样回放与照界面修正的转换区别留在本卡。

## 关键规格与约束

- **输入**：运动文件 `combined_checkpoints.pkl`，格式由源码确定（[03](../03-asset.md) 第 3 节：每帧 3,603 个数，相对**本段参考**的累计偏移）。
  - 文件是一串向量，里面没有起始姿态；"相对静止位置"只对从中性出发的段成立。
  - 取回的是 97 个条目，对应 84 个文件、82 份不同的内容，长度有 3、10、22、25、36、43、46 步（[E-11](../explanations/E-11.md)、[E-14](../archive/explanations/E-14.md) 第 1 条）。
  - 文件在仓库外，`.local/ziva_trip_pointer.json` 指向它们。
- **两种合同**（`trajectory.json` 的来源里写明用的是哪一种；起始姿态不知道的文件只做解码、检查格式，不假定从中性出发）：
  - **原样回放**（raw replay）：起始姿态是同一条序列里前一段的末尾（序列从中性开始）；段与段之间的接头显式处理并写进来源；
  - **照界面修正的回放**（UI-corrected replay）：另外存目标和修正的规则（实验室界面会给目标下颌加线性修正，也会把修正反馈到 landmark 组，看模式而定；实验室 `h99-UI-mayascipt-V1.py` 第 1496 到 1523、1554 到 1617 行，读源码得出）。
- **转换规则**：
  - **帧对应（从中性出发的段）**：第 0–14 帧没有运动，补成不动（驱动源是单位变换，landmark 平移为 0）；数据的第 i 个元素（从 0 数）对应第 15 + i 帧（[03](../03-asset.md) 第 3 节，`UI:1453-1459`）。不从中性出发的段没有这 15 帧，只能接在同一条序列里前一段的末尾，起始姿态就是前一段最后一帧（见上面"产品现在能跑什么"）；
  - **起始姿态**：不从中性出发的过渡，不能当成从中性出发来播（[13](../13-explanations.md) [E-14](../archive/explanations/E-14.md) 第 1 条）。例子：AA 到中性的文件最后一项是 +4.36°，从中性起步会把下颌转到错的方向；
  - **landmark 平移**：乘 `mm_per_scene_unit` 并转坐标轴，换算只用 `asset/coords.py` 那一份（N-01）；
  - **下颌**：转成绕铰链的刚体变换。
    - 从中性出发的单段过渡，按文件里的俯仰增量绕世界 X 轴转（上机时就是这样放进 Ziva 的，[E-11](../explanations/E-11.md)；钢琴界面里下颌只用俯仰的相对转动，[03](../03-asset.md) 第 3 节）。
    - 三个轴都有转动的运动（实验室训练时三个轴都转，[03 源码](../03-lab-source.md) 第 13.2 节），欧拉角的轴顺序还没对过，用取回的文件核对，并在 `trajectory.json` 的来源里写明；
  - **格式**（[ADR-21](../decisions/ADR-21.md)）：每个驱动源每帧一个 4×4 刚体变换（毫米、Z 轴朝上），包含平移和旋转；不只存关节角度。甩头（整个颅骨平移）和下颌平移都要能表达。
    - **`trajectory.json` 用列向量约定，Maya 的矩阵是行向量约定**，从 Maya 来的矩阵要转置（[ADR-34](../archive/decisions/ADR-34.md)）；
  - **安全**：运动文件是 Python pickle，普通的加载会执行代码。用 [T-34](../archive/tasks/T-34.md) 加的受限读取器（只允许基本容器和 numpy 数组）；只读实验室直接给的文件；转换成我们的 JSON 以后，产品不再读 pickle。

## 验收条件

- **参考数据核对**：对照 Ziva 在同一段运动上的回放（[E-11](../explanations/E-11.md)；都是我们的脚本照运动文件播的）。
  - 每一帧 f，Ziva 同一帧的蒙皮前 + 权重 × 转换后第（f − 15）步的 landmark 位移，应等于 Ziva 同一帧的蒙皮后（误差小于 0.01 mm）。
  - 对有 Ziva 回放的每一段做一次：中性到 AA，以及 EH、IY、UW、V、N、T。
  - IY、UW、T 的 Ziva 参考标成"上机脚本的回放"：脚本按现存文件播了 36、36、10 步，界面源码对从中性出发的过渡要 22 步，不一定是界面实际播的那一条（[E-14](../archive/explanations/E-14.md) 第 2 条）。
  - Y 分两种来源列出：Ziva 的点只有第 0 到 33 帧，关键帧（`keys_*.json`）有 47 帧；只在第 0 到 33 帧比，不拿关键帧代替 Ziva 的点。
- **全量解码**：全部 84 个运动文件（82 份不同的内容）都能读入、通过格式检查，读到的份数大于 0 并打印出来；起点已知的才转换，起点不知道的只报"已解码、未转换"。
- **从中性出发的段**：第 0–14 帧不动，数据的第 0 个元素落在第 15 帧（有测试）。这一条只对从中性出发的文件查。
- **不从中性出发的段（原样回放）**：把真实的中性到 AA 和 AA 到中性拼成一条从中性开始的序列，一次跑完；两段在接头处的下颌角度和 landmark 位置连续，接头怎么处理写进来源。再把同一段 AA 到中性单独给求解入口（第一帧不是单位变换），必须被拒绝，并报出清楚的错误。验收不拿没有经过界面修正的回程终角当标准；要对照界面修正后的终角，用照界面修正的回放，并存下目标和修正规则。
- **铰链与矩阵约定**：
  - 驱动源如果带铰链说明（比如 `jaw01`），检查它的变换和铰链的转动一致（误差小于 0.001 mm）；
  - 故意不转置，检查应该失败；
  - 有一条含平移的运动（甩头或下颌平移）能完整读入；
  - **下颌不是纯铰链转动时**：嘴角锚由 `jaw01` 的运动派生，取整个刚体运动的一部分（[ADR-38](../decisions/ADR-38.md) 第 6 条），三个轴都转的下颌也能算。
- **转轴变化前置试验**：用转轴随时间变化的运动之前做一个方块试验，检查 FEBio 的刚体运动是否逐帧精确（转动向量 Ru、Rv、Rw 给的是总转动，不是增量，[05](../05-ziva-to-febio.md) 第 3 节），以及帧与帧之间的行为（刚体的平移和转动向量在帧间线性插值，对固定铰链是精确的，转轴变化时不是）。试验通过以后才能用这类运动。

## 历史与修订

- **上机时我们是怎么播的**（[E-11](../explanations/E-11.md)）：
  - 从第 14 帧的世界位置起，每帧给 landmark 打绝对位置的关键帧；下颌按相邻两步的俯仰差绕世界 X 轴转；单段不加目标修正。
  - 来回 10 次是接着上一段末尾的 landmark 位置往下播，另加一个俯仰的线性修正。IY、UW、T 按现存文件播了 36、36、10 步，不是界面实际播的那一条过渡（界面从中性出发要 22 个检查点）。
- **实验室界面在文件之外还做了什么**（读源码得出 🔍，`h99-UI-mayascipt-V1.py` 第 1330 到 1371、197、277 行；我们上机的回放没有做这些）：
  - 每个检查点先跳到目标帧，再绕世界 X 轴转、打关键帧；可以给牙齿和舌头的 `_RENDER` 网格额外加转动；反馈和牙齿两个开关在界面源码里默认是开的。
  - 所以从我们导出的两路嘴唇，推不出研究员在界面上看到的完整画面（[14](../14-ziva-demo-walkthrough.md)）。
