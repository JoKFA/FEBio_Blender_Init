## 目标与范围

- **目标**：研究员在真实环境中一次载入可独立安装的 Python 3.9 训练查询包 `asrp_query` 并在内存里反复读取四组 landmark 网格及下颌（五个输出），同时经正式会话入口完成非中性初始化、纯眼额运动、连续两次按键和回中性操作，并按四项分别登记研究员签收。
- **输入**：
  - 查询移植支路：[T-44](T-44.md)、[T-45](T-45.md) 提供场景身份、表面和可用绑定（静态查询数据的生成器和独立读取包由本卡交付）；
  - 连续操作支路：[T-48](T-48.md) 的完整会话与 [T-50](T-50.md) 的多物体运行能力；
  - 带皮肤签收支路：[T-51](T-51.md) 的皮肤小片能力；
  - 实验室真实运动（含纯眼额、非中性初始化、连续两次按键）与实验室实际运行环境。
- **产出明细**：
  - 独立打包、Python 3.9 进程内可调用的 `asrp_query`：`asrp_query.open_query(static_path)` 一次载入、可反复按姿态查询（待实现）。
    - 现有 `rest_model(scene_json_path)` 和 `final_shape(model, jaw_rotation, landmark_positions, …)` 的调用方式与嘴唇返回形状保持兼容；五表面的新查询用独立方法，不把旧函数的单个数组改成五项。
  - 3.13 核心生成的静态查询数据（`asrp-query-data/1`：入口文件 `query.json`，引用带摘要的数值 `.npy`，记录场景版本、表面及原序身份、坐标单位、绑定和枢轴；命令 `asrp query export <revision> --store <dir> --out <dir>`；均待实现）及与 `asrp_query` 共享几何运算的适配；
  - 支持四组 landmark 与下颌通道（含纯眼额运动）、非中性初始化、连续两次按键和回中性的对接入口，以及给研究员的插值差别说明（照 [04](../architecture/README.md) 第 13.12 节末尾给研究员的那段话原样提供）；
  - 按**训练查询、连续表情、带皮肤被动动力学、回中性**四行分别登记的研究员签收记录；
  - 验收测试 `C10`（待新增）。
- **不做**：不许动实验室控制器、钢琴交互逻辑、训练判据、按压后处理（按压脚本修改显示面由实验室拥有，不回写物理历史）。

## 约束与接口

- **独立打包 `asrp_query`（[`ADR-53`](../decisions/ADR-53.md)）**：
  - 将公开入口 `asrp_query/__init__.py`、静态数据读取与身份校验、坐标转换、蒙皮、刚体枢轴变换及其全部传递依赖和包安装元数据严格守在 Python 3.9 兼容线内（交付要求），首版限制为只依赖标准库及实测兼容的 NumPy（本卡的选择）。
  - 训练只走静态模型，不需要状态、帧或结果清单；核心 3.13 负责从场景版本生成查询所需静态数据，`results` 复用同一份几何运算；场景迁移、会话、FEBio、Blender、Ziva 比较和沉降运行读取器留在核心。
  - 默认使用静止基底（不跑 FEBio），输出保持实验室约定（绝对世界位置、场景单位、Y 向上），覆盖四组 landmark 网格（嘴唇、左眼、右眼、额肌）及下颌共五个输出。
- **两级查询验证**：
  - 开发机用**真正的干净 Python 3.9 解释器**只装 `asrp_query` 与所需 NumPy，在仓库外导入并做非零 landmark 查询、偏心枢轴转动和连续两次不同输入，对照 3.13 与手算原序点。
  - 实验室实际训练进程执行同一查询用例，记录真实解释器、NumPy 版本、载入时间和热查询耗时。
- **四个真实实验室动作**：
  - 读入一条纯眼额运动（不得静默忽略）；
  - 跑通一次第 0–14 帧非中性初始化起步段（纯重力沉降检查标"不适用"）；
  - 跑通连续两次按键（默认分段线性、样本封存，把 [04](../architecture/README.md) 第 13.12 节末尾给研究员的插值说明原样提供）；
  - 跑通回中性（按实验室流程从中性根重走指定初始化，仅在完整初始化输入、设置及后续同一动作核对相符时才复用已存起点）。
- **分别登记参考与签收**：
  - 现有 145 份存档只给嘴唇查询作证，其余四张表面各自需要本家族本操作的原序参考，缺本家族参考的格子明确保留"未核实"。
  - 研究员签收按训练查询、连续表情、带皮肤被动动力学、回中性四行分别登记（写清场景家族、起步、观察对象与层、参考是否齐备、工程是否通过、研究员结论）。
  - 被动动力学一行按实际动作填驱动与读取面：甩头记录头部驱动，按压记录手及皮肤，并注明实验室额外改动的点；回中性一行填现场实际使用的家族、复位路径和初始化输入，分别与冷启动核对；两族都能表达该操作，不等于两族都已有操作证据；[T-51](T-51.md) 的小片通过不能代签整场被动动力学。

## 验收条件

> 分开发机验收和上机验收；只看到 `passed` 或退出码 0 不算交付，必须贴出真实命令与完整打印输出作为证据。
> 同一编号分三条可分别完成的支路：**查询移植**（训练查询一行）、**连续操作**（连续表情、回中性两行）、**带皮肤签收**（带皮肤被动动力学一行）；每行独立记工程检查、同条件参考和研究员结论，缺哪一行的前提，就只那一行待验。

- **开发机验收**（干净 Python 3.9 环境、合成输入；这一段过了，卡标 🟡）：
  - **查询移植**：运行 `uv run pytest -s -k C10`，打印开发机干净 Python 3.9 独立安装与仓库外导入结果、调用环境（Python 与 NumPy 版本）、五个输出（嘴唇/左眼/右眼/额肌/下颌）逐表面参考对照结果（缺本家族参考的格子显式打印 `未核实`）和热查询耗时；缺第二家族数据时，合成验收照常完成，该家族的实测待验。
  - **连续操作**：打印纯眼额运动的非零输出、非中性初始化起步记录、两次连续按键的接头控制值与等待时间（首帧可见、整段可读）以及回中性核对。
  - **带皮肤签收**：只验 [T-51](T-51.md) 的小片能力在合成输入上走得通，不代签整场被动动力学。
  - **必须失败的坏例**：
    1. 故意让 `asrp_query` 入口导入 `asrp_core`，在干净 3.9 环境下必须失败；
    2. 左右眼（或左右侧 landmark）组互换，单侧扰动检查必须失败；
    3. 输入只动眼或额头的真实运动却生成空动作，必须失败；
    4. 把沉降后的嘴唇基底喂给既有静止训练入口，必须失败；
    5. 已知偏心枢轴转动下颌时坐标轴或旋转顺序错误，下颌逐点检查必须失败。
- **上机验收**（实验室实际进程；开发机会话做不到，不在开发机会话里勾掉）：
  - 实验室实际训练进程再执行同一查询用例，记录真实解释器、NumPy 版本、载入时间和热查询耗时；
  - 研究员在实际操作里走一遍非中性初始化、连续两次按键和回中性，记录各行的参考齐备情况、工程检查和研究员结论。
- **门禁验证**：交付最终状态跑 `uv run python tools/verify.py` 并记录实际输出。

## 历史与备注

- **为什么做**：
  - 已知实验室的 Maya 自带 Python 3.9（实际训练调用的进程和 NumPy 构建待 [11](../11-risks-and-questions.md) D22），而核心是 3.13。
  - 本机 3.13 实测单次起空 CLI 子进程就要约 `275 ms`（`274–275 ms`），而进程内载入一次（`219–272 ms`）后内存热查询只需 `3.1–3.6 ms`（[13 归档 / E-23](../archive/explanations/E-23.md)）；并且今天 `final_shape.py` 顶层导入整个 `scene`，无法独立安装。
  - 同时实验室训练实际读取 4 组 landmark 网格加下颌（现有 145 份存档只给嘴唇作证），84 份运动中有 12 份只动眼或额头（[E-23](../archive/explanations/E-23.md)），现行转换器会静默略过并产出看似成功的空表情。
- **本卡涉及的现在不定项及当前做法**：
  1. 实验室最终调用的 Python 解释器、NumPy 构建（等上机确认）：在此之前开发机按干净 Python 3.9 + 标准库 + 实测兼容 NumPy 独立打包并验收；
  2. 研究员对首帧可见、整段可读和热查询的可接受等待门限（等实验室实际操作确认）：本卡如实记录分项耗时，不自定通过毫秒线；
  3. 除嘴唇外四张网格的本家族原序参考、第二家族完整静态导出及连续两次按键接头速度是否显著影响研究任务（等上机取证）：缺参考的格子在报告中保留"未核实"，不拿演示场景或嘴唇 145 份代签。
