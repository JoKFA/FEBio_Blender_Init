# 术语表

按出现频率大致排序。解释以"够用"为准，不追求教科书式的严谨。

## 软件和工具

| 词 | 意思 |
|---|---|
| **Maya** | Autodesk 公司的商业 3D 软件，实验室目前在用 |
| **Ziva（Ziva VFX）** | 装在 Maya 里的肌肉和软组织仿真插件。已于 2024 年停售，本项目要替换的就是它 |
| **Blender** | 免费开源的 3D 软件，本项目用它代替 Maya 做操作和显示 |
| **插件（add-on）** | 装进 Blender 的扩展程序。本项目的插件只负责界面 |
| **FEBio** | 美国犹他大学开发的开源有限元软件，专门用于生物力学，本项目用它代替 Ziva 做物理计算 |
| **FEBio Studio** | FEBio 的图形界面程序，安装它会附带 FEBio 本体 |
| **ArtiSynth** | 另一个开源生物力学仿真软件，有现成的下颌模型，是以后的备选 |
| **zBuilder** | Ziva 自带的工具，能把整套 Ziva 设置存成一个文件 |
| **zGeo** | Ziva 给每个软组织、骨头、皮肤各存的一份网格。原来的 Maya 网格删掉以后它还在，见 12 第 7 项 |
| **权重表（weight map，Maya 里叫 weightList）** | 逐顶点的一串 0 到 1 的数，比如粘连里"哪些顶点粘着、粘多紧"。推断：Maya 只把和默认值不同的元素写进文件，没写的取默认值。粘连权重的默认值按 1.0 读（强推断，03 第 6 节）：没存的顶点算粘着，根本没存权重表的粘连等于整块都粘着 |
| **uv** | Python 的包管理工具，用来安装依赖、运行程序 |
| **git / 仓库 / 分支 / 合并请求** | 代码版本管理。仓库是项目代码的家；分支是开发某个任务时的独立副本；合并请求是"请审查我的改动，然后合并进主分支" |

## 文件格式

| 词 | 意思 |
|---|---|
| **.mb** | Maya 的二进制场景文件，实验室的资产就是这种格式 |
| **mayapy** | Maya 自带的命令行 Python，不打开界面就能运行 Maya 脚本。我们用它跑 `tools/maya_export.py` |
| **非 Ziva 版场景** | 实验室删掉全部 Ziva 节点后的场景副本，普通 Maya 就能打开，见 03 第 12 节 |
| **Ziva 机器** | 实验室里装着 Ziva 许可的那台电脑，大约 4 个人轮流用 |
| **Alembic（.abc）** | 存放"每一帧的网格形状"的开放格式，Ziva 参考结果用它导出 |
| **OBJ / FBX / Alembic（.abc）** | 通用的 3D 文件格式。OBJ 存单个静态网格；FBX 能带关节和动画；Alembic 擅长存每帧都在变的网格 |
| **.feb** | FEBio 的输入文件，描述要算的模型 |
| **回放包（playback.json + playback.pc2）** | 一次运行交给 Blender 的结果：`playback.json` 存嘴唇显示网格的静止顶点和面，`playback.pc2` 存每一帧每个顶点的位置。插件的 Load result 按钮读它（04 第 5.3 节，ADR-09） |
| **PC2（点缓存）** | 一种简单的文件格式，存"每一帧每个顶点在哪"。Blender 用它播放我们的结果 |
| **JSON** | 一种常见的纯文本数据格式，人和程序都能读 |
| **运动文件（`combined_checkpoints.pkl`）** | 实验室钢琴界面运行时读的运动数据：每帧一个 3,603 个数的向量，是 landmark 和下颌相对起始位置的累计偏移（03 第 7 节）。不在源码仓库里，在 Ziva 机器上取（11 的 D2）。和我们自己的运动文件 `trajectory.json` 不是一回事 |
| **`dataV22_*`** | 实验室源码里的目标姿态文件：5 个网格的两组坐标。`…0` 是静止形状本身（和我们导出的静止网格逐点相同，没有重力沉降，不能当沉降参考），`…1` 是目标形状（03 第 13.7 节，11 的 A-34） |
| **换行符 / `core.autocrlf`** | Windows 的文本文件每行末尾是 CRLF 两个字节，其他系统是 LF 一个字节。git 的 `core.autocrlf=true` 会在检出时把 LF 改成 CRLF，文件的哈希就变了。仓库的 `.gitattributes` 让 `data/` 和 `tests/fixtures/` 一律按字节检出（08 第 10 节） |

## 几何和网格

| 词 | 意思 |
|---|---|
| **网格（mesh）** | 用很多小面片拼成的物体表面，就像用三角形纸片糊成的模型 |
| **顶点** | 网格上的点 |
| **四面体网格（tet mesh）** | 把一个实心物体切成很多小四面体（四个面的小块），有限元在这些小块上计算。"四面体化"就是做这个切分 |
| **四面体尺寸（tetSz）** | 小四面体大概多大。越小越精确，但算得越慢 |
| **嵌入（embedding，Ziva 里叫 zEmbedder）** | 显示用的网格很精细，计算用的四面体网格很粗。嵌入就是让精细网格"长"在粗网格里，跟着它一起动 |
| **重心坐标** | 嵌入时用的方法：每个显示顶点记住自己在哪个四面体里，离四个角各有多近 |
| **嵌入的四面体** | 显示顶点嵌入时落在的那个四面体（在外面的取最近的边界四面体）。粘连也用它的 4 个计算点和重心坐标，所以 `hard` 的显示顶点能精确跟着骨头走（05 第 3 节，ADR-36） |
| **8 分细分** | 把每个四面体切成 8 个小的（每条边取中点），边界形状不变。用来做网格加密对比，是网格敏感性报告的一项（07 第 6 节） |
| **网格敏感性报告** | 换网格、细分网格、缩小时间步，看结果变多少的报告。只报告，不设通过线，但要交研究员判断"差别会不会改变研究判断"（07 第 6 节步骤 2，ADR-23） |
| **哈希值（指纹）** | 根据文件内容算出的一串字符。文件改一个字节，指纹就会变，用来确认"是不是同一份输入" |
| **节点（两种意思）** | ① Maya 里的"节点"是场景中的一个对象，比如一个网格、一个关节、一个 Ziva 设置；② 有限元里的"节点"是计算点，也就是四面体的角。文档里说"计算点"时指第②种 |
| **计算点** | 有限元计算网格上的点（四面体的角），见上一条 |
| **面** | 网格上由几个顶点连成的小三角形或四边形。`.mb` 里网格的面我们读不出来，所以要用 Maya 导出 |
| **坏四面体（退化单元）** | 被压扁、体积接近 0 的四面体，会让计算出错或变慢 |
| **包围盒** | 正好把一个物体装进去的长方体，用它的长宽高粗略表示物体大小 |
| **变换** | 把一个网格放进场景时做的放大缩小、旋转和平移。实验室的骨骼和嘴唇都被放大了 2.54 倍并转过 |
| **物体坐标 / 场景坐标（世界坐标）** | 物体坐标是网格自己记录的坐标；套上变换以后，在场景里的坐标叫场景坐标。Ziva 用的是场景坐标 |
| **静止形状（ShapeOrig）** | Maya 里网格变形之前的原始形状，名字通常以 `ShapeOrig` 结尾 |

## 物理和仿真

| 词 | 意思 |
|---|---|
| **有限元（FEM）** | 一种计算物体受力变形的方法：把物体切成小块，每块单独算，再拼起来 |
| **求解器** | 做这种计算的程序。本项目里指 FEBio（以前是 Ziva） |
| **软组织** | 会变形的组织，比如肌肉、脂肪。Ziva 里叫 zTissue |
| **刚体** | 不会变形、只会整体移动或转动的物体，比如骨头。Ziva 里叫 zBone |
| **粘连（attachment）** | 把一个物体的一部分顶点"粘"在另一个物体上。每个顶点有一个 0 到 1 的权重，表示粘得多紧 |
| **材料参数** | 描述组织有多硬、多不可压缩、多重的数字 |
| **zMaterial** | Ziva 里挂在软组织上的材料节点，存杨氏模量、泊松比、密度和材料模型。场景里有 43 个，都没存数值，很可能是 Ziva 默认值（03 第 5 节，13 E-06） |
| **杨氏模量** | 硬度。数字越大越硬 |
| **刚度** | 弹簧或粘连有多"紧"：拉开同样的距离，刚度越大需要的力越大 |
| **体力（body load）** | 作用在物体整个体积上的力，比如重力 |
| **薄片单元（壳单元）** | 专门用来算很薄的东西（比如皮肤）的计算单元 |
| **弹簧单元** | FEBio 里连接两个计算点的"弹簧"，用来实现软的粘连 |
| **数值阻尼** | 计算方法本身带的一点"刹车"，让晃动逐渐停下。FEBio 里用 `rhoi` 设置 |
| **泊松比** | 被拉长时变细的程度。接近 0.5 表示几乎不可压缩，像橡胶 |
| **密度** | 单位体积有多重 |
| **neo-Hookean** | 一种常用的软组织材料公式，适合大变形 |
| **动力学 / 准静态** | 动力学考虑惯性，物体会晃、会过冲；准静态假设每一刻都已经停稳。本项目用动力学 |
| **时间步 / 子步** | 计算时每次往前推多长时间。一帧可以拆成几个子步来算，更稳定 |
| **阻尼** | 让晃动逐渐停下来的"摩擦"效果 |
| **收敛 / 不收敛** | 求解器在某一步能不能算出稳定的答案。不收敛就是算不下去了 |
| **碰撞** | 物体之间互相挤压、不能穿过。实验室在 Ziva 里关掉了 |
| **mm、N、MPa、s** | 毫米、牛顿、兆帕、秒，本项目统一使用的单位 |

## 面部和控制

| 词 | 意思 |
|---|---|
| **OOR（口轮匝肌，orbicularis oris）** | 环绕嘴唇的肌肉，原型里的"嘴唇" |
| **ooc（眼轮匝肌，orbicularis oculi）** | 环绕眼睛的肌肉，原型里不用 |
| **landmark（控制点）** | 实验室控制器用来驱动表情的点。嘴唇上有 300 个，在 Maya 里是关节 |
| **关节（joint）** | Maya 里可以移动、旋转的控制对象。landmark 和下颌都是用关节表示的 |
| **蒙皮（skinning，Maya 里叫 skinCluster）** | 让关节按权重带动网格顶点。实验室用它让 landmark 带动嘴唇 |
| **控制器** | 实验室论文的成果：给定目标表情，算出 landmark 每一帧该怎么动 |
| **运动轨迹** | 每一帧下颌和 landmark 的位置、角度 |
| **音素（phoneme）** | 发音单位，比如 "AA"（张嘴的 a 音） |
| **FACS / 动作单元（AU）** | 面部动作编码系统，把表情拆成一个个编号的动作单元，比如 AU12 是嘴角上扬 |
| **静止形状 / 静止位置** | 什么都还没动时的样子 |
| **蒙皮权重** | 每个顶点受每个关节影响的比例，一个顶点的全部权重加起来通常等于 1 |
| **关键帧 / 动画曲线** | 动画里指定"某一帧某个值是多少"的点叫关键帧；把关键帧连起来、给出每一帧数值的就是动画曲线 |
| **口角（modiolus）/ 口角 node** | 嘴角处几块肌肉汇合的地方。资产里是两块小组织 zTissue4、zTissue5（粘连名里叫 node），嘴唇连到它们，它们再经 zTissue2/3 连到颅骨和下颌（03 第 6 节） |
| **锚（嘴角的锚）** | 第一阶段代替整条口角链的近似：一个不显示、没有网格的刚体，运动介于颅骨和下颌之间（按混合比例 α 跟着下颌转），嘴角顶点用弹簧连到它上。`scene.json` 的 `anchors` 一节（05 第 3 节，04 第 5.1 节，ADR-32）。另有"弹簧的锚点"：弹簧另一端并入刚体的计算点，两者不是一回事 |
| **派生驱动源** | 不带自己运动的驱动源，写成"驱动源 X 的整个刚体运动的 factor 倍"（`blend`），由 X 的运动算出来，X 不需要铰链。嘴角的锚跟随的就是一个 α = 0.5 的派生驱动源（04 第 5.1 节，ADR-38 第 6 条） |
| **Hill 肌肉模型** | 一种经典的肌肉力公式：力取决于激活程度、肌肉长度和收缩速度。实验室代码里它是控制器目标函数里的一项，不驱动物理（03 第 13.4 节，ADR-33） |
| **应变能** | 物体被拉伸、压缩时储存在材料里的能量。第一阶段物理段每帧报告每块组织的应变能，只作诊断输出，不进优化（ADR-33） |
| **重力沉降 / 沉降形状 / 第 14 帧的形状** | 每条运动前，第 0 到 14 帧下颌不动、只有重力，组织在重力下静下来；第 14 帧的形状是控制器优化的起点（ADR-30）。我们的运行把它写成 `physics/settled_frame{n}.*`，n 来自运动文件的 `settle_until_frame`（见下面该条，07 第 3 节） |

## 项目管理

| 词 | 意思 |
|---|---|
| **资产** | 实验室提供的 Maya 场景和导出的数据 |
| **参考结果** | 同一条运动在 Ziva 下算出来的结果，用来和我们的结果并排比较。它是"以前的样子"，不是标准答案 |
| **容差** | 和参考结果差多少以内算合格。本项目第一阶段**不设**和 Ziva 比较的数值容差（ADR-17） |
| **研究员评审** | 研究员把 Ziva 和 FEBio 的结果并排播放，按几个固定问题判断能不能接受，是第一阶段的合格标准之一（07 第 4.4 节） |
| **试验（spike）** | 为了验证一个不确定的假设而写的一次性小程序，验证完就把结论写进文档 |
| **任务卡** | 交给开发者的完整任务说明，见 09 |
| **自动检查（verify）** | 每次改代码后跑的一组检查（`uv run python tools/verify.py`），全部通过才能合并 |
| **里程碑** | 一组任务完成后达到的阶段性目标，见 09 |
| **合理性检查** | 粗略判断结果"大致对不对"的检查，用来发现单位错十倍这类错误。每次 `asrp run` 做五项 (a)(b)(b2)(c)(d)，每项的定义和标准只写在 07 第 3 节；结果是通过、失败或"没运行"（`passed` 为 `null`，不算失败），(b)、(b2) 是防回归用的，不是物理对的证据（ADR-37、ADR-38） |
| **命令行 / 子进程** | 命令行是在终端里输入命令来运行程序；子进程是一个程序启动的另一个程序。Blender 插件就是用子进程调用核心程序 |
| **ruff / PEP 8** | PEP 8 是 Python 代码的通用书写规范；ruff 是自动检查和整理代码格式的工具 |
| **LTS** | 长期支持版本，会持续修复问题，适合长期项目使用 |
| **远程仓库 / 分支保护** | 远程仓库是放在网上、大家共用的代码仓库；分支保护是规定"主分支只能通过审查过的合并请求来改" |
| **溯源** | 记录一个结果是用什么输入、什么版本、什么参数得到的 |
| **ADR（决策记录）** | 记一个关键决定：定了什么、为什么、放弃了什么，见 10 |
| **场景描述（scene.json）** | 我们自己定义的文件，完整描述一个要计算的模型，见 04 |
| **运行文件夹** | 每次计算一个文件夹，装着这次的全部输入、输出和记录 |
| **刚体变换（4×4）** | 用一个 4×4 的数表同时记下一块骨头的平移和旋转。ADR-21 规定每个驱动源每帧一个这样的变换（毫米、Z 轴朝上），"给定"的骨头跟着它走 |
| **列向量 / 行向量约定** | 4×4 矩阵乘点的两种写法：列向量约定平移在最后一列（`trajectory.json` 用这种），行向量约定平移在最后一行（Maya 用这种）。两者互为转置（T-10） |
| **驱动源** | 带动骨头的东西，`trajectory.json` 里每帧的刚体变换按它的名字存。实验室资产里就是关节，比如 `jaw01` 同时带动下颌和下牙（ADR-21） |
| **λ̂ 和 δ（弹簧粘连的两个量）** | λ̂ 是显示顶点的重心坐标经截负值、归一、再和平均分配各取一半的结果，保证嵌入的四面体四个角都有弹簧刚度；δ 是弹簧另一端的锚点偏出计算点的距离。公式和取法只写在 05 第 3 节（ADR-36） |
| **刚度分档** | FEBio 里一种弹簧材料只有一个刚度，所以一组弹簧的刚度按对数分成几档，每档一种材料（05 第 3 节） |
| **物理尺度（physics_length_scale，k）** | 求解器"以为"模型比几何尺寸大几倍；几何和输出仍是毫米，和几何换算 `mm_per_scene_unit` 是两回事。做法（节点坐标 × k，参数不缩放，读回 ÷ k）只写在 05 第 2 节（ADR-22、ADR-36） |
| **LBS（线性混合蒙皮）** | 让关节按权重带动网格顶点的最常见公式，Maya 的 skinCluster 就是这种。论文的控制器用可微的 LBS 代理来求解析梯度 |
| **解析梯度 / 数值梯度** | 优化时算"往哪个方向调"。解析梯度由公式直接给出，快；数值梯度要反复试探，慢。实验室源码里四种组织都走解析梯度，名字不认识时才走数值梯度的旧路径（ADR-30） |
| **物理不在环** | 优化的每一步都不调用物理计算。实验室控制器训练时是这样：物理只在开头算到第 14 帧（ADR-30）。钢琴界面则每步都推进物理；同一帧里改关节后 Ziva 会不会重新求解还没验证（Q20） |
| **过渡表** | 论文里预先算好的"从一个表情到另一个表情"的结果；演示里的钢琴界面不只读它，每一步都推进一次 Ziva（每步约 1.5–2.5 秒，[14](14-ziva-demo-walkthrough.md) 第 2 节 14:46；见 [02](02-requirements.md) 第 4 节、ADR-30） |
| **美术目标姿态** | 美术师给定的目标表情网格。论文用"到它的距离"衡量结果好不好（4.3），ADR-25 沿用 |
| **跟随比例（下唇跟随比例）** | 一组顶点的位移 ≈ 比例 ×"粘在下颌上会走的位移"，比例取最小二乘的系数：1 是完全跟着下颌，0 是不跟。物理段的指标，Ziva 和 FEBio 各报一个（ADR-25，07 第 4.2 节）；在实验室的 AA 目标上量过（下唇 0.09，嘴角 0.00，我们的物理是 1.00，13 E-09） |
