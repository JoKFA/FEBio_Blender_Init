## E-01 路线图从 T-03 开始怎么走？

*2026-11-04 提问。依据：[09](09-roadmap-and-tasks.md) 第 1 到 3 节。*

**简答**：T-03、T-04、T-05（以及 T-07、T-15）都不用等实验室，现在就能做。它们和 T-02 完成后，T-06 第一版就能用真实网格加临时参数，把物理段从头到尾跑通一次（里程碑 M2）。再往后的任务主要在等 Ziva 机器上的数据：D2 运动轨迹和 D3 参考结果。

```
现在就能开始（不等实验室）          第一版跑通                 换真实数据、比较、验收
─────────────────────────         ──────────              ─────────────────────
T-05 场景格式 ──┬─► T-02 资产导入 ─┐
               └─► T-08 运行外壳   │
T-03 粘连区域 ─────────────────────┼─► T-06 第一版 ──► T-12 换数据、调参 ──► T-14 验收
T-04 四面体化 ─────────────────────┘        ▲
T-07 粘连做法试验 ──────────────────────────┘（第二版用）
T-15 ruff（独立）
                                    D2 ─► T-10 轨迹 ─► T-09 landmark 层
                                    D3 ─► T-11 和 Ziva 并排比较
                                    T-13 面板：每个命令做完就补对应的小节
```

**现在能开始的三张卡**

| 卡 | 做什么 | 为什么必须做 | 难点 |
|---|---|---|---|
| T-05 场景格式 | 定下 `scene.json` 的格式（`asrp-scene/1`），提供 `asrp check` | 它是各模块之间的交接契约，T-02、T-06、T-08 都靠它 | 每个参数都带“来源”字段（实验室设置 / Ziva 默认值 / 我们定的）。T-06 第一版能放心用临时值，就靠这个字段把临时值标清楚 |
| T-03 粘连区域 | 从完整版 `.mb` 读粘连的逐顶点权重，算出嘴唇哪些区域挂到哪块骨头上（P-01 方案 A） | 非 Ziva 版场景把粘连删了 | `.mb` 格式没有公开文档，结果只算临时值。6 块肌肉网格被删了，要等 Ziva 机器导出的 `ziva_meshes/` 才有面 |
| T-04 四面体化 | 把嘴唇表面网格切成四面体，选定工具 | 见 [E-02](#e-02-为什么需要-t-04-四面体化) | 风险最高：网格可能自身穿插（A-10）；按 `tetSz` 切，厚度方向只有大约两层 |

**T-05 完成后能开始的**

- **T-02**：把 `data/lab_export/` 下的文件导入成 `scene.json`。OBJ 已经是场景坐标，不能再套一次 `world_matrix`。之后乘 0.962 换成毫米，再把坐标轴从 `(x, y, z)` 换成 `(x, -z, y)`。
- **T-08**：`asrp run` 的外壳（运行文件夹、溯源、进度、取消）。在 T-06 做好前，先拿一个现成的 `.feb` 文件代替生成器。

**T-06 第一版**用临时值补上缺的数据：
- 粘连先用硬绑定；
- 材料用常见的软组织参数；
- 单位按 0.962 mm；
- 没有轨迹时，用一条简单的下颌运动代替。

这一步的意义是尽早暴露真正的问题：四面体质量、尺寸、数值稳定性。

**再往后**：
- T-12 换真实数据、调参，要定时间上限；
- T-10 → T-09 等 D2；
- T-11 等 D3，只报告差别，不判合格（ADR-17）；
- T-13、T-14 等前面的命令都做完。

**建议的顺序**（建议，未定）：
1. T-05 最先做：工作量最小，做完能解锁最多的任务；
2. T-04 同时开：技术风险最大；
3. T-03 可以稍后：结果本来就是临时值，等 Ziva 机器的数据到了还要再核对；
4. 项目负责人最急的是 T-01：Ziva 许可到期后，D3 就再也拿不到了。

## E-02 为什么需要 T-04 四面体化？

*2026-11-04 提问。依据：[05](05-ziva-to-febio.md) 第 1 节，[04](04-architecture.md) 第 3 节和第 10 节，[11](11-risks-and-questions.md) A-10，ADR-01。*

**简答**：FEBio 是有限元求解器，只能在体积网格上计算，而我们手上只有嘴唇的**表面网格**。Ziva 是在内部自动把表面切成四面体的，切出来的四面体网格不在文件里，所以这一步得我们自己做。

| 环节 | Ziva 的做法 | 我们的做法 |
|---|---|---|
| 输入 | 嘴唇表面网格（10,240 个顶点，只是一层壳） | 同一个网格 `data/lab_export/mesh_middleres_OrbicularisOris.obj` |
| 把壳变成实心体 | Ziva 运行时自动切成四面体。zTet 节点只存“切多细”（`tetSz` 26.37）和逐顶点权重 | **自己做：T-04** |
| 计算 | 在四面体上算弹性变形 | FEBio 在四面体上算（tet4 单元，neo-Hookean 材料） |
| 显示 | zEmbedder 让精细的表面网格跟着粗的四面体网格动 | 用重心坐标插值，作用一样 |

**为什么绕不过去**

1. **软组织变形本质上是体积问题。** 嘴唇被拉、被压、受重力下垂，靠的是内部材料的弹性。有限元必须把物体切成小块才能算，Ziva 本身也是四面体有限元。所以换哪个求解器都要这一步。
2. **Ziva 的四面体网格拿不到。** 完整版 `.mb` 有 41 个 zTet 节点（[03](03-asset.md) 第 2 节）。资产盘点（`tools/mb_inventory.py` 生成的 `data/asset_inventory.json`）里，嘴唇的 zTet1 只存了这几样：`tetSz`（26.37）、10,240 个逐顶点权重、一个哈希值 `cHash`、一个**空的**网格槽 `iT`（0 个顶点）；另外就是输入输出的连线 `iGo`、`oGo`。没有四面体网格本身。
3. **其他做法都不合适。**
   - 壳单元：嘴唇有 45.8 的厚度，不是薄片。
   - 质点弹簧：不是有限元，ADR-01 放弃过自己写求解器。
   - 六面体网格：很难在这种不规则形状上自动生成。

**这一步是在什么计划下写出来的**

它是从选 FEBio 一路推出来的必经步骤，从第一版规格开始就有。

```
2026-10-27  ADR-01 选 FEBio（有限元）
              │
              ├─ spec-v0.1 的假设台账：A10"实验室资产能四面体化（静止态有组织互穿）"❓
              │    → 计划：拿到资产后做试验 S2，记录失败点（提交 65e8ab2）
              ▼
2026-10-28  设计文档成套（提交 54f23d2）
              ├─ 05 对应表：zTissue → 四面体 + 弹性材料；zTet → 我们自己做，用哪个工具见 T-04
              ├─ 04 流水线：资产导入 → 场景描述 → 四面体化（tetmesh.py） → 生成 FEBio 输入
              ├─ 11 风险表：四面体化失败，可能性中、影响高
              └─ 09 任务卡：T-04 = 试验 S2
```

当时定计划的方法是：把流水线拆成环节，每个环节依赖的假设记进假设台账，最没把握的先做试验，在真实环境里验证。

| 试验 | 验证什么 | 状态 |
|---|---|---|
| S1 | FEBio 本机能跑动力学、刚体铰链和重力 | ✅ 做了，还发现重力要反号（ADR-10） |
| S2 = T-04 | 真实的嘴唇网格能切成合格的四面体（A-10） | ⚠️ 前提已查：网格封闭、只有一块、是一个环；自身穿插还没查 |
| S3 = T-07 | 粘连用硬绑定还是弹簧 | 🟢 待做 |

T-04 风险最高的原因有三：
1. 网格如果自身穿插，有的工具会直接失败；
2. 按 `tetSz` 切，嘴唇厚度方向只有大约两层四面体，可能太粗；
3. 四面体数量决定计算速度（04 第 10 节估计，计算点会比 S1 多两到三个数量级）。

它一旦失败，T-06 就整条跑不起来，所以排在“现在就能开始”里。

**还没核实的想法**（建议，未定）：Ziva 能不能导出它自己的四面体网格？现在的 `tools/ziva_machine_export.py` 只导出 zGeo 的输入网格，没碰 zTet 的输出。如果能导出，有两个好处：
- 和 Ziva 用同一套计算网格，比较时少一个变量；
- T-04 多一个保底方案。

但 T-04 仍然要做：产品不能依赖 Ziva，以后换网格、换尺寸都要靠我们自己的工具。要采纳的话，先把它写进 [11](11-risks-and-questions.md) 和 [12](12-lab-export-checklist.md)。

## 怎么加新的一条

- **什么时候加**：有人问了“为什么”“从哪来”“这一步是干什么的”，而且答案要翻好几份文档才能拼出来，就加一条。只是查个数字的，不用加。
- **格式**：
  1. 编号 `E-xx`，标题就是问题本身；
  2. 第一行写提问日期和依据（链接到原文档）；
  3. 先写**简答**，再写细节；
  4. 每个数字、每个结论都指回原文档或者能复现的命令；
  5. 在上面的目录里加一行，在相关文档的对应位置加一个“为什么，见 13 E-xx”的链接。
- **设计变了**：对应的解释也要跟着改。已经过时的条目不删，在标题后注明“已过时，见 ADR-xx”。
