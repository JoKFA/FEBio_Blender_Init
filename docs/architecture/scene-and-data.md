## 1. 数据的六种形态与契约规则

数据从实验室导出到宿主和实验室代码读取，依次经过六种落盘形态。

**格式版本和内容版本是两件事**：
- **整数格式版本**回答“按哪套规则读这个文件”（例如 `asrp-scene/2` 里的 `2` 是格式版本，不能用来指定一次场景编辑）。
- **场景版本**是规范化清单的 SHA-256，回答“读到的是哪一份内容”。
- 各形态的格式版本互不捆绑升级：

| 产物 | 版本约定 |
|---|---|
| 场景清单、运动输入、静态导出包、公开结果清单 | 各有独立整数格式版本 |
| 建造配置、场景视图、独立查询包读取的静态数据 | 各有独立整数格式版本；配置名如 `legacy-v1` 另记，名字不参与格式分派 |
| 建造记录 | 有内部整数格式版本，另记生成器版本和实际内容摘要（同一生成器能产生许多不同建造） |
| 会话记录 | 有内部整数格式版本，覆盖会话清单、状态、尝试、缓存元数据和分支引用；内部文件首版不再各自编号，状态 ID 另记 |
| 台账、历史、解析样本、数组 | 台账随导入记录封装版本，历史随场景库内部格式，解析样本随状态记录；独立数组头按自身格式读取；每份内容可核摘要，PC2、NPY、FEBio 文件沿用各自格式 |

### 六种落盘形态总览

| 形态 | 落盘与稳定范围 | 定位 |
|---|---|---|
| **静态导出包** | 落盘、只读、独立整数版本 | 上机采集与本机导入之间的稳定约定 |
| **场景版本** | 落盘；对编辑、导入和迁移稳定（格式 `asrp-scene/2`） | 核心管理的可变物理与显示声明 |
| **导入台账与场景视图** | 落盘；**场景视图**是宿主运行前的稳定约定 | 追查来源/处理方式；供宿主查看和高亮 |
| **建造记录** | 落盘、不可变、带生成版本；内部格式可升级，旧实验保留原件 | 封存单次实验的静态模型与翻译产物 |
| **运动段与实际驱动** | 用户提交段与解析后实际驱动分别落盘；段输入语义稳定 | 封存每段实际送入 FEBio 的驱动与设置 |
| **已提交结果** | 落盘；**结果清单**是实验室与宿主读取的稳定约定 | 按身份与原序读回每段每帧结果数组 |

### 各形态最少必须保存的内容

- **静态导出包**：
  - 保存导出工具与厂商版本、对象和关系、原始属性、原单位、带原始顶点顺序的网格、权重图索引域、缺失原因和文件摘要。
  - 未知厂商属性在原包里保留原件，台账只记其原位置、可追查引用和“未解释”，不另存一套原始数组；以后可用新导入器重新解释同一导出包。
- **场景版本（`asrp-scene/2`）**：
  - 保存参考形状、参考表面、材料及本构、重力与物理尺度、对象、粘连声明、驱动通道和显示绑定声明；可附首选计算网格和来源。
  - 对象与表面 ID 由核心生成、改名后保持；文件引用带内容摘要；ID、摘要、长度等管理字段按格式定义。
  - 物理和显示声明的原值、来源、采用值和处理方式都可追查（每个值从哪来、程序怎么处理，记在导入台账的两列里）；研究员改参数产生新版本。
- **导入台账与场景视图**：
  - 台账分两列记录“值从哪来”和“程序怎么处理”（例如目标图是“未导出”，全目标表面找最近点是“本次近似”）。
  - “权重图画在哪一侧”和“未列元素默认多少”分别记证据，不合并成一个来源标记。
  - 18 个纤维首版**不列为 `asrp-scene/2` 的纤维对象**：原包和台账保留 18 项的身份、所属组织、已知激活、上游连接和缺失的方向。
    - 场景视图可从台账显示这些来源项并明确“未参与求解”。
    - 若对应实验全程出现非零激活，或同条件开关纤维出现可辨差异，该实验标“待纤维支持”。
  - 台账不因生成 XML 就将未验证的本构/阻尼/布料模型标成“已实现”。
  - 场景视图向宿主提供物体、角色、参考表面与显示面、参数与来源、粘连参与顶点和 landmark 组；编辑走核心入口。
- **建造记录**：
  - 保存实际计算网格与内容摘要、每张显示面的绑定、每条粘连边的逐点对应与后端实现记录、有效材料与刚度、物理尺度、预分配通道和后端编号表。
  - 建造封存静态模型、实际网格、绑定、对应、编号及翻译记录，**必须保存足以重放的数组**——只有哈希而没有被哈希的内容，清缓存后无法重放。
  - 本段实际送进 FEBio 的输入、样本和设置不在建造里，由各段封存。
- **运动段与实际驱动**：
  - 保存父状态 ID、时间轴、各通道及单位、缺省通道含义、物理曲线的实际取样值、显示输入（如四组 landmark）、本段有效求解设置，以及本段实际送进 FEBio 的输入。
  - 重放时求解器直接读取已保存的实际样本；尝试目录只保存执行副本与日志。
- **已提交结果**：
  - 保存场景版本、建造身份、状态、对象、参考表面 ID、结果层、生产者、绝对帧与秒、单位与坐标约定、顶点顺序身份、数组形状及内容摘要。
  - 每段数组继续用 float64 `.npy`，按对象、表面、层分别存。
  - 旧 `asrp-display/2` 表头照旧读，新段表头采用 `asrp-display/3`（允许首行对应任意已发布的绝对帧，并与结果清单互验）；PC2 是派生的回放文件。

### 四条数据契约规则

1. **未知字段严格拒收**（[T-45](../tasks/T-45.md)）：
   - 新版本可执行输入遇到未知字段必须拒绝并报告具体字段路径；未知厂商属性留在静态导出包并在台账中标明。原始值、采用值、实际生效值三者均须可查。
   - **校验分工**：结构用 JSON Schema，在可执行声明的每一层拒绝未知字段；跨对象引用、索引域、摘要、有限数、是否可执行由 `scene` 代码检查；重复键在 JSON 解析时拒绝。
   - `asrp-scene/1` 按旧读取规则走。
   - **可读但不能执行的取值不等于未知字段**：已识别的 `sliding`、`vertexID`、`maintainOffset=false` 和多层材料可进入场景版本，保留原值、来源和“不支持执行”的原因，场景视图里可点选。建造所选范围含相应的边或物体时，生成 FEBio 输入前按 ID 和字段拒绝；显式选择不涉及它们的切片可以建造。
2. **单位与坐标约定**：
   - 核心标准统一为几何毫米（mm）、Z 轴向上；FEBio 所需的物理长度缩放 `physics_length_scale`（`k`）只在后端进出时各转换一次。
   - 实验室训练查询继续沿用实验室一侧约定（绝对世界位置、场景单位、Y 轴向上）。
3. **静止参考面上的点序与身份核对**：
   - 给 Blender 的网格在导入时写入场景版本、表面 ID 和逐顶点原始行号。
   - 接缓存前核对原始行号、参考表面的有序静止坐标与连接关系（宿主浮点转换按导入时同一表示核对）。
   - 由于对应建在静止参考面上，逐帧合法重新三角化仍可回放；仅核对顶点数或面索引哈希查不出“交换两行坐标”的错误。
   - 实验室读数组同样核对对象、表面、层、帧和内容摘要。
4. **旧运行可读**：
   - 旧运行结果由旧版读取器直接回放，不为了看旧回放而重新求解。

## 2. 场景版本的落盘、引用与保留

场景的真身是场景版本库，不是 `.blend`（[ADR-46](../decisions/ADR-46.md)，[T-44](../tasks/T-44.md)）。磁盘与宿主引用按以下约定实现：

- **磁盘布局**：
  - 一个项目数据目录拥有持久的 `store_id`。
  - `scenes/<revision>/scene.json` 存该版小清单，`blobs/<sha256>` 按字节摘要共享有序网格、权重、绑定等大文件。
  - 清单引用大文件时写明用途、格式、摘要和长度，只靠清单即可找全全部内容。
- **版本定版规则**：
  - 场景版本以规范化清单的 SHA-256 标识。
  - 纳入摘要的内容：格式版本、稳定对象及表面 ID、物理与显示声明、采用的单位、数据来源引用和大文件摘要。
  - JSON 序列化固定 UTF-8、键序和有限数表示，保留有意义的数组顺序，拒绝重复键和非有限数，并用固定样本锁住规范化字节。
  - 时间、绝对路径、提交者、编辑说明及父版本记在版本外的历史记录里；不同编辑历史到达相同内容对应同一版本。
- **编辑历史**：
  - 场景库的 `history/` 下，**一次编辑事件一份 JSON**：父版本、结果版本、时间、提交者、说明及可用的路径信息。
  - 同内容经两条历史到达时保留两条事件；这些信息不参与内容摘要。
- **编辑与发布**：
  - 先写入并校验缺失的大文件，再在同卷暂存并发布清单，最后更新发起编辑方的引用。
  - 并发写入相同摘要时先核验已有内容再共用。
  - 任何一字节改坏必须报摘要错误，不把损坏解释成“找不到而换相似文件”。
- **`.blend` 引用与并发**：
  - `.blend` 保存 `store_id` + `revision`、相对 `.blend` 的仓库路径提示，以及会话 ID、状态 ID。
  - 普通“另存为”重算路径提示，继续引用同一不可变版本；从任一 `.blend` 编辑参数时生成新版本，只更新发起编辑的文件。
  - 搬家后允许重新定位，但必须核对 `store_id` 和版本身份。
  - 后台作业启动即绑定发起文件、场景版本和父状态；运行中切到另一 `.blend`，结果仍归发起者，回原文件可取回，外部文件缺失时指出具体缺项。
- **保留与删除**：
  - 求解器缓存可由会话命令清理；**已发布的场景版本首版不自动删除**（关闭 Blender、删分支、另存为均不触发回收），由项目负责人保留。
  - 暂存失败的临时文件可另行清理。
