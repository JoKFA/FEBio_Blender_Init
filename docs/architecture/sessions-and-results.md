## 1. 会话：磁盘结构与七条规矩

**状态是一次成功提交的历史终点**，包含到该时刻的完整物理历史和控制量。单凭某一帧的表面形状（如第 14 帧的嘴唇网格）不足以定义状态，因为相同位置可以有不同速度（[ADR-49](../decisions/ADR-49.md)，[T-47](../tasks/T-47.md)、[T-48](../tasks/T-48.md)）。

### 磁盘目录结构

以下为内部目录约定；调用方只通过会话命令和结果清单交互，不直接依赖内部文件名：

```text
session/
  session.json                 场景版本、建造、求解环境、根状态
  build/                       不可变建造清单：锁定的计算网格、对应、翻译记录和后端编号表
  states/<state-id>/           父状态 ID、本段输入、实际曲线样本、生效设置
                               已核验的结果清单、数组和重放参照
  cache/<state-id>/            可删除的 FEBio 存档（.dmp）、文件摘要和环境身份
  attempts/<attempt-id>/       本次运行专用的父档副本、输入、日志、临时输出
  refs/                        用户命名的分支和当前选中状态
```

**共享存储与导出约定**：
- 建造清单里的数组和网格，可按摘要放进同一项目库的 `blobs/` 共享（场景版本也用它，见 [场景版本落盘](scene-and-data.md)）；清单必须能找到并验证全部真实字节，会话清缓存不删这些字节。
- 搬走或导出会话时，要么连同所引用的内容一起打包，要么明确校验并定位同一个库；只复制一张摘要表不算可重放。

### 会话七条规矩

1. **新建**：
   - 根状态是参考姿态、零时刻和明确的初始控制量；锁住场景版本、不可变建造记录、FEBio 可执行文件身份、相关库与线程设置。
   - 加物体、换计算网格、换粘连算法，都必须新建建造和会话；改材料先发布新场景版本，再建造并新开会话。
2. **起步**：
   - 从根提交初始化段，可以只受重力（沉降），也可以在第 0–14 帧边走时间边摆到非中性姿态（“非中性起点”属于同一场景的起步运动，不是新场景）。
   - 只在确实满足静止检查时才标“已沉稳”；非中性起步不标“已沉稳”。后续追加的段不自动补沉降或末尾保持。
   - 回中性按实验室流程从中性根重走指定初始化；只有完整初始化输入、设置及后续同一动作核对相符，才复用已存起点。
3. **追加**：
   - 必须显式指定父状态。父末帧 `f` 归父，子段发布 `(f, f+n]`，驱动曲线输入包含 `f` 作为接头。
   - 省略已声明通道表示保持父末值，回零必须显式给出；接头值与父末不符则报错并指出通道，突变须写成有时间含义的动作；未知非零通道报错。
4. **插值**：
   - 新会话默认分段线性，旧整段平滑显式保留，样本一经提交即封存（详见本页第 5 节，[ADR-54](../decisions/ADR-54.md)）。
5. **运行与提交**：
   - 每次运行创建独立 `attempts/<attempt-id>/` 目录。根起步没有父档，写首份 `.feb`；从已提交父状态续算（写 `.rst`）时，先校验再复制父档，**严禁 FEBio 写入父档原路径**。
   - 本机实测表明，在原地被改写的存档上重试，12 次里有 11 次“正常结束”却走到第 70 帧而非预期的第 46 帧（[E-23](../archive/explanations/E-23.md)）。
   - 续算不加写档选项时父档不变，危险的是把新档写回父档同名路径；独立副本保护 `.dmp`，`-noappend` 涉及旧 `.xplt` 的重新打开，两者要分别在正式入口核验。
   - 每段封存本段实际送进 FEBio 的输入、样本和设置，尝试目录保存执行副本与日志。
   - 结果按预期绝对物理时间表匹配，经 `checks` 核对全部实际时间与硬门槛后才能提交，不能按步号认帧，也不能四舍五入帧号覆盖旧记录。
6. **失败、并发与恢复**：
   - 失败或取消只在尝试目录留诊断，绝不发布半个状态，父状态保持可用；同一父状态可分叉出多个成功子状态。
   - 提交采用整目录原子发布：先在同卷临时目录写齐结果、清单和摘要并关闭文件，再一次重命名发布整个子状态，最后带预期旧值更新 `refs/` 分支引用。
   - 两任务争同一分支时保留两个有效子状态，只移动一次引用并让后到者看到分支已移动。
   - 崩溃后未发布目录不算状态；已发布但分支未更新的子状态可按 ID 找回。相同父状态和相同有效输入重试时复用已校验提交。
7. **重放与清缓存**：
   - 状态身份覆盖父 ID、建造与环境身份、有效设置、物理实际样本和显示输入。字节摘要抓文件损坏，数值参照按容差抓重算漂移。
   - 缓存（`.dmp`）缺损或校验不符时从最近有效祖先重放；删光 `cache/` 和 `attempts/` 后，仍保留全部已提交输入和结果，仍能重放。
   - 更换 FEBio 构建或运行环境时，建立标明来源的新计算记录。

**与现行代码及旧试验脚本的差异**：
- 现行代码无会话状态树，每次 `asrp run` 从静止整段冷启动并平铺输出到 `runs/<运行编号>/`。
- 早先会话试验脚本在交给健康检查前曾先筛掉期望帧以外的记录（[E-23](../archive/explanations/E-23.md)），生产检查必须先检查全部实际时间，防止提前丢掉越界证据。

## 2. 检查与提交的分工

提交链路固定为四段责任（[ADR-50](../decisions/ADR-50.md)）：
**`backends/febio` 交出原始运行事实 → `results` 生成候选数组 → `checks` 给出有证据的判定 → `sessions` 按锁定的提交规则发布整个子状态**。

- `checks.evaluate(raw_run, candidate_results, rules)`返回含适用性、实测值、门槛和理由的判定；是否发布由 `sessions` 决定，独立对照继续用 `asrp compare`。

| 检查类别 | 核对内容 | 对提交的影响与负责模块 |
|---|---|---|
| **执行完整性** | 正常结束、实际时间、节点与行完整、有限值、父状态及建造身份 | 后端保留原始顺序和全部记录，`checks` 核对；硬门槛失败或必做检查缺失，子状态不发布 |
| **物理合理性** | 将现行 `plausibility.py` 及 `simulate.py` 中 `_physics_checks` 的计算迁入 `checks` | 按对象、段用途和已有门限声明适用性；倒置四面体等执行门槛失败即拒提交 |
| **显示面质量** | 逐层报告末帧和最差帧的翻面、边长异常 | 保留现行 `_surface_health` 的**只报告**语义；升格为门槛须写入版本化验收规则 |
| **Ziva 对照** | 复用 `compare.py` 指标和 `ziva_compare.py` 对齐逻辑；保留独立 `asrp compare` | 无同条件参考时，工程健康段仍可提交，对照保持“未核实”单独签收 |

**执行顺序与适用性细则**：
- 执行完整性核对必须在取整、去重和挑选预期帧**之前**抓出重复时间、越界帧或截断行。
- 非中性起步无纯重力沉降窗口时，物理合理性记录“不适用”和原因，不签“已沉稳”。

## 3. 结果层与读回契约

结果数组统一按**（状态、对象、表面 ID、结果层、绝对帧）**读取，内容是该表面按原始顶点顺序排列的世界坐标（核心标准为几何 mm、Z 轴向上）。
- **粗壳与细显示面用不同的稳定表面 ID 区分，处理阶段用结果层名区分**；公开结果层名固定只有 `physics` 和 `final`（[ADR-52](../decisions/ADR-52.md)）。

| 层或产物 | 谁生产 | 覆盖范围 |
|---|---|---|
| **`physics`** | 后端出计算节点运动，`results` 用建造封存绑定还原原序表面；给定运动刚体由实际变换产生 | 所有声明输出面的组织、皮肤和刚体（含下颌、手） |
| **`final`** | `results` 在指定表面执行场景声明且已验证的显示处理 | 嘴唇、两眼、额肌等带 landmark 绑定对象（各组验证通过后）；皮肤最终面（取得并验证包裹曲线链后） |
| **按压脚本改过的皮肤、牙舌额外显示修正、控制器或训练程序自身产物** | **实验室所有，核心不发布** | 实验室可读核心层、自行修改并另存；改动不回写核心物理状态树 |

**分层边界与公开结果清单细则**：
- **皮肤多面**：皮肤可在原序布料面和绑定的细显示面分别发布 `physics`；若粗壳只是建造内部网格，其节点数组属诊断而非公开表面；若实验室读的布料网格本身就是该壳，则按其稳定表面 ID 发布。
- **无后处理与缺数据时**：没有显示后处理的对象（如骨头）直接读 `physics`（下颌训练查询用本家族原序参考验，会话中下颌由实际变换生成其表面 `physics` 顶点；补到下颌参考不会凭空产生 `final`）。
  - 皮肤需取得并验证“最终嘴唇 → 包裹曲线 → 皮肤蒙皮”数据后才发布 `final`；缺少所需数据时清单注明原因，读取 `final` 明确失败，**禁止用 `physics` 假充 `final`**。
- **公开结果清单**（格式 `asrp-results/1`，文件 `results.json`，均待实现）：必须写明生产者、场景版本、建造身份、状态、对象、表面 ID、结果层、顶点顺序身份、单位、坐标系、绝对帧与时间及内容摘要；每条数组引用对应一个状态、对象、表面、层、绝对帧与秒。
- **与现行代码的差异**：现行结果仅覆盖单块嘴唇的 `physics/display.*` 与 `final/display.*`，缺少多对象与多表面身份字段；插件回放（`blender_addon/asrp_blender/asset.py` 第 791 行）仅核对顶点个数。

## 4. 训练查询（`asrp_query`）

实验室训练循环不推进物理时间、没有段和状态，在已载入的静态模型上给定位姿即可返回网格顶点。地基阶段将其拆成**可独立安装、由 Python 3.9 进程内调用的包 `asrp_query`**（[ADR-53](../decisions/ADR-53.md)，[T-52](../tasks/T-52.md)）。

- **已知与未知**：已知实验室 Maya 自带 Python 3.9；实验室实际训练调用进程和 NumPy 构建尚未知，待上机确认（[11](../11-risks-and-questions.md) 的 `D22`）。因此 3.9 兼容是对交付的要求，开发机先证明干净的 3.9 环境能独立安装。
- **分工**：
  - Python 3.13 核心从场景版本生成查询静态数据（`asrp-query-data/1`，入口文件 `query.json`，引用带摘要的数值 `.npy`；均待实现）；`query.json` 记录场景版本、表面及原序身份、坐标单位、绑定和枢轴。
  - `asrp_query` 一次载入静态数据后在内存里反复查询，不需要状态、帧或结果清单；`results`（3.13）复用同一份几何运算。
  - 场景迁移、会话、FEBio、Blender、Ziva 对比和沉降运行读取器留在核心。
- **Python 3.9 兼容线**：
  - 必须守住范围：公开入口 `asrp_query/__init__.py`、静态数据读取与身份校验、坐标转换、蒙皮运算、刚体枢轴变换，以及它们的**全部传递依赖和包安装元数据**。
  - 首版限制（我们选的，不是实验室的要求）：只依赖标准库及实测兼容的 NumPy；**严禁导入 `asrp_core`**（须用干净 3.9 解释器隔离测试守住）。
- **契约与范围**：
  - 入口 `asrp_query.open_query(static_path)`返回一次载入、可反复按姿态查询的模型。
  - 保留现有 `rest_model(scene_json_path)` 和 `final_shape(model, jaw_rotation, landmark_positions, …)` 的调用路径和嘴唇返回形状；五张表面的新查询用独立方法，不能把旧函数的单个数组改成五项。
  - 默认基底保持静止形状（不是沉降形状）；输入输出继续采用实验室一侧约定（绝对世界位置、场景单位、Y 轴向上）。
  - 输出范围从嘴唇一组扩展到四组 landmark 网格（嘴唇、左眼、右眼、额肌）加下颌网格。
- **已有实测边界**：本机 Python 3.13 下真实嘴唇（10,240 顶点）载入耗时 219–272 ms、内存查询 3.1–3.6 ms，而起一次 CLI 子进程约 275 ms（[E-23](../archive/explanations/E-23.md)）。这只覆盖嘴唇及本机 3.13 环境；实验室实际调用进程、NumPy 构建及四组加下颌的耗时与参考裁判待上机确认。
- **与现行代码的差异**：现行 `asrp_core/final_shape.py` 顶层直接导入整个 `scene` 模块，无法在 Python 3.9 中脱离核心独立安装，且仅输出嘴唇网格。

## 5. 段界插值与样本封存

新会话默认使用**分段线性插值**，旧整段的单调三次 Hermite 平滑作为显式选项保留（[ADR-54](../decisions/ADR-54.md)）：

- **样本封存**：无论线性还是平滑，实际交给求解器的驱动样本一经提交便封存在段记录中，后续追加绝不改写历史样本。
- **平滑新段规则**：明确要求平滑的新段，只使用该段已知关键帧与父末值生成，端点采用单侧规则，不承诺接头处控制速度连续。首版段格式不要求研究员输入接头速度。
- **等价边界**：同一串关键帧都按相同分段线性规则取样时，切段本身不制造差别；同一起点、同一组实际样本、相同求解设置与步序下，整算与续算须在登记容差内一致。换切点重新拟合整段平滑属于另一条输入。

以下说明直接面向研究员，明确分段线性与整段平滑的差别：

> 每按一次键，会从上次结束的姿态和运动状态继续。新段默认在相邻关键点之间匀速改变控制量，接头处的控制速度可能改变。把同一批关键点放在一起重新做整段平滑，接头附近可能得到不同的驱动，软组织的运动也可能不同。要复现一次实验，请使用保存的各段和实际驱动样本。
